<TlDr>`RETURNING` возвращает значения строк, которые изменил оператор. Отдельный `SELECT` после `INSERT`, `UPDATE` или `DELETE` не нужен.</TlDr>

## Что есть в данных

В `book` одиннадцать книг. У «Тихого Дона» цена 890.00. В `review` десять отзывов, у двух рейтинг ниже четырёх.

## INSERT: номер новой строки

```sql run expect=rows:1
insert into author (name, country, born_year) values ('Лев Толстой', 'Россия', 1828) returning author_id;
```

`RETURNING author_id` возвращает номер, который выдала последовательность. На доске строка влетает в `author`, а в панели результата появляется колонка `author_id` со значением 7. Тот же номер можно было бы получить отдельным `SELECT`, но это лишний запрос и лишний шанс ошибиться.

## UPDATE: старое и новое значение

```sql run expect=rows:1
update book set price = price * 0.9 where book_id = 1 returning old.price, new.price;
```

PostgreSQL 18 умеет возвращать и старое, и новое значение строки. `old.price` показывает 890.00, `new.price` показывает 801.00. На доске строка сначала стоит со старой ценой, потом ячейка переворачивается на новую.

Если нужны только новые значения, пиши `returning price`: это обычное имя колонки после изменения.

## DELETE: что именно удалили

```sql run expect=rows:2
delete from review where rating < 4 returning *;
```

`RETURNING *` возвращает все колонки удалённых строк. В результате две строки: отзывы с рейтингом 3 и 2. На доске они перечёркиваются и уходят. Без `RETURNING` осталось бы только `DELETE: 2`, и ты не увидел бы, какие именно строки попали под условие.

## Зачем это нужно

`RETURNING` делает изменение и чтение одной атомарной операцией. Никто не успеет изменить или удалить твою строку между записью и чтением. Это важно, когда номер или значение нужно сразу передать дальше: создать заказ, записать аудит, вернуть клиенту созданную запись.

## Чего нет в выдаче и почему

- ❌ В `RETURNING` нет строк, которые не изменились: `UPDATE` возвращает только совпавшие с `WHERE`.
- ❌ Нет старых значений в `RETURNING` без `old`: обычное имя колонки после `UPDATE` даёт новое значение.
- ❌ После превью новых строк и изменений нет в таблицах: всё откатилось.

## Ловушки

<Callout kind="trap">
`RETURNING` не спасает от забытого `WHERE`. Если не указать условие, `UPDATE` или `DELETE` затронет все строки, а `RETURNING` честно вернёт их все. Сначала проверь условие в `SELECT`, потом меняй:

```sql noexec
select book_id, price from book where book_id = 1;
```
</Callout>

<Callout kind="tip">
Порядок строк в `RETURNING` не гарантирован. Если он важен для ответа, сортируй результат снаружи или не полагайся на порядок. Для массовых изменений добавляй `RETURNING` только с нужными колонками: `*` на широкой таблице гонит лишние данные.
</Callout>

## Проверь себя

1. Что вернёт `UPDATE` с `RETURNING old.price, new.price`?
2. Сколько строк вернёт `DELETE` с `RETURNING *` для рейтинга ниже 4?
3. Почему `RETURNING` надёжнее отдельного `SELECT` после вставки?

<Cheatsheet>
- `RETURNING` работает в `INSERT`, `UPDATE`, `DELETE` и `MERGE`.
- `returning *` возвращает все колонки изменённых строк.
- `returning old.price, new.price` показывает значение до и после.
- Возвращаются только строки, которые затронул оператор.
- Порядок строк в `RETURNING` не гарантирован.
</Cheatsheet>
