<TlDr>`MERGE` сравнивает цель с источником по ключу и для каждой строки выбирает ветку: обновить, вставить или удалить.</TlDr>

## Что есть в данных

В `book` одиннадцать книг с номерами от 1 до 11. Книга 1 «Тихий Дон» стоит 890.00. В `review` десять отзывов, у книги 2 их два, у книги 11 ни одного.

## Синхронизация одной командой

```sql run expect=rows:2
merge into book b
using (values (1, 700.00), (12, 100.00)) as s(id, price)
on b.book_id = s.id
when matched then update set price = s.price
when not matched then insert (title, price) values ('Новая книга', s.price);
```

Источник здесь это две строки: книга 1 с новой ценой 700 и строка с ключом 12, которой в цели нет. Для строки 1 срабатывает `WHEN MATCHED`: цена меняется на 700. Для строки 12 совпадения нет, срабатывает `WHEN NOT MATCHED`: появляется «Новая книга» с очередным номером.

На доске изменённая строка помечена `MATCHED UPDATE`, новая `NOT MATCHED INSERT`. Каждая ветка красит строку по-своему. `MERGE` вернул 2: одну строку обновил, одну вставил.

## Ветка DELETE

```sql run expect=rows:2
merge into review r
using (values (2), (11)) as s(book_id)
on r.book_id = s.book_id
when matched then delete
returning r.review_id, r.book_id;
```

Ветка `WHEN MATCHED THEN DELETE` удаляет строки цели, для которых нашлась пара в источнике. Здесь у книги 2 два отзыва, у книги 11 ни одного, поэтому удаляются два отзыва. На доске они перечёркиваются, как в обычном `DELETE`.

## MERGE и ON CONFLICT

`ON CONFLICT` реагирует на одну вставляемую строку и один уникальный ключ. `MERGE` берёт целый набор строк и для каждой решает, что делать. Поэтому `MERGE` удобен для синхронизации: загрузили пачку изменений и одной командой привели таблицу к нужному виду.

У `MERGE` есть ветка `WHEN NOT MATCHED BY SOURCE`: она удаляет строки цели, которых нет в источнике. В этом уроке такая ветка не анимируется, запрос показывается целиком в режиме `final-only`.

## Чего нет в выдаче и почему

- ❌ Старой цены 890 у книги 1 нет: ветка `MATCHED UPDATE` записала 700.
- ❌ «Новой книги» не было до запроса: её создала ветка `NOT MATCHED INSERT`.
- ❌ Двух отзывов на книгу 2 нет после второй команды: сработала ветка `MATCHED DELETE`.
- ❌ Изменений нет в базе после превью: `MERGE` откатился.

## Ловушки

<Callout kind="trap">
Если в источнике две строки с одинаковым ключом, `MERGE` попытается изменить одну строку цели дважды и упадёт с ошибкой. Убедись, что ключ источника уникален:

```sql noexec
using (values (1, 700.00), (1, 800.00)) as s(id, price)
```
</Callout>

<Callout kind="tip">
`MERGE` не заменяет `ON CONFLICT` везде. Для одной вставляемой строки upsert короче и понятнее. Для синхронизации пачки, где нужны вставки, обновления и удаления, `MERGE` выражает правило целиком одним запросом.
</Callout>

<Cheatsheet>
- `merge into цель using источник on ключ`
- `when matched then update set ...`
- `when matched then delete`
- `when not matched then insert ...`
- Ветка выбирается для каждой строки цели по ключу соединения.
- `WHEN NOT MATCHED BY SOURCE` удаляет строки, которых нет в источнике.
- `MERGE` возвращает число затронутых строк.
</Cheatsheet>
