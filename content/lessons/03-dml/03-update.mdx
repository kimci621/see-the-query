<TlDr>`UPDATE` меняет строки, которые прошли `WHERE`. Строки вне условия остаются прежними. `UPDATE ... FROM` берёт новые значения из другой таблицы.</TlDr>

## Что есть в данных

В `book` одиннадцать книг. Четыре стоят дороже 800: «Тихий Дон», «Python. К вершинам мастерства», «Простой Python» и «Изучаем Python». У Лусиану Рамальо из Бразилии одна книга.

## WHERE выбирает строки

```sql run expect=rows:4
update book set price = price * 0.9 where price > 800 returning book_id, title, price;
```

На доске проходит `WHERE`: четыре строки остаются, семь приглушаются. Потом у четырёх строк переворачивается ячейка `price`. `RETURNING` показывает новые цены. Остальные строки не изменились, хотя `SET` написан для всей таблицы.

Порядок важен: сначала Postgres находит строки по `WHERE`, потом применяет `SET` к каждой найденной. Поэтому условие можно писать по старым значениям, как здесь: `price > 800` проверяется до умножения.

## Без WHERE

<Callout kind="trap">
Если забыть `WHERE`, `UPDATE` затронет все строки. На настоящей базе это авария, а не упражнение. В превью можно посмотреть, как это выглядит:

```sql run expect=rows:11
update book set price = price * 0.9;
```

Изменились все одиннадцать книг. Перед массовым `UPDATE` проверь то же условие через `SELECT` и выполни изменение в транзакции.
</Callout>

## UPDATE ... FROM

Новое значение не обязано быть константой или арифметикой над той же строкой. Его можно взять из другой таблицы:

```sql run expect=rows:1
update book set price = price * 0.5
from author a
where book.author_id = a.author_id and a.country = 'Бразилия'
returning book_id, title, price;
```

На доске сначала читаются `book` и `author`, потом соединение и `WHERE` оставляют одну книгу, и только она меняется. Без `FROM` пришлось бы сначала узнать номер автора отдельным запросом.

## Новая версия строки

`UPDATE` не стирает старую строку на месте. Postgres записывает новую версию, а старая остаётся видимой другим транзакциям до `COMMIT` и ещё некоторое время после. Это называется MVCC. Подробно разберём в главе про транзакции; пока достаточно знать, что массовый `UPDATE` создаёт много новых версий и занимает место.

## Чего нет в выдаче и почему

- ❌ Семи книг дешевле 800 нет в результате первого `UPDATE`: `WHERE` их не выбрал, и они не изменились.
- ❌ Книги Лусиану Рамальо нет в результате `UPDATE ... FROM`: страна автора не Бразилия.
- ❌ Изменений нет в базе после превью: все примеры откатились.

## Ловушки

<Callout kind="trap">
`UPDATE` без `WHERE` и `UPDATE` с опечаткой в условии выглядят одинаково: обе команды успешно завершаются. Сравни число изменённых строк с ожидаемым. Если `UPDATE` вернул 11 вместо 4, условие не сработало так, как ты думал.
</Callout>

<Callout kind="tip">
На большой таблице обновляй порциями: `where book_id between 1 and 1000`, потом следующая порция. Так блокировка короче, а ошибку видно на маленькой пачке. Для массовых миграций заранее проверь план запроса и место на диске.
</Callout>

## Проверь себя

1. Сколько строк изменит `UPDATE book SET price = price * 0.9 WHERE price > 800`?
2. Что произойдёт, если убрать `WHERE`?
3. Почему `UPDATE ... FROM` меняет только одну книгу?

<Cheatsheet>
- `update t set колонка = значение where условие;`
- `WHERE` выбирает строки до применения `SET`.
- Без `WHERE` меняются все строки таблицы.
- `UPDATE ... FROM` берёт значения из другой таблицы по условию соединения.
- `RETURNING` показывает изменённые строки.
- `UPDATE` создаёт новые версии строк, старые убирает vacuum.
</Cheatsheet>
