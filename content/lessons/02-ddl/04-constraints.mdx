<TlDr>Ограничения проверяют данные при записи. `DEFAULT` подставляет значение, если его не указали.</TlDr>

## Что есть в данных

В `author` шесть авторов: имя обязательно. В `customer` шесть покупателей; email каждого обязателен и уникален. У Анны адрес `anna@example.com` и 120 бонусов. Колонка `bonus` не допускает отрицательных чисел, а при пропуске получает ноль.

Все примеры запускаются в превью и откатываются. Сохранённые данные не изменятся, пока не нажмёшь «Применить» в редакторе.

## Обязательное значение

**Ограничение** задаёт правило для данных. `NOT NULL` не позволяет записать отсутствие значения. Попробуем добавить автора без имени:

```sql run expectError=23502
insert into author (country) values ('Россия');
```

На доске показана попытка вставки, а Postgres возвращает `23502`: колонка `name` требует значение. Чтобы добавить автора, укажи имя.

## Уникальное значение

`UNIQUE` запрещает повторять значение или сочетание значений в разных строках. Попробуем занять адрес Анны:

```sql run expectError=23505
insert into customer (name, email, created_at)
values ('Ирина', 'anna@example.com', now());
```

Ошибка `23505` сообщает о повторе. На доске видны попытка и существующая строка Анны. Адрес нужно изменить; саму Анну запрос не меняет.

<Callout kind="analogy">
Уникальный email похож на номер занятого шкафчика: второй человек не может получить тот же номер, пока он занят. Пустое значение `NULL` ведёт себя иначе: по умолчанию `UNIQUE` допускает несколько таких значений, если колонка не запрещает `NULL`.
</Callout>

## Проверка условия

`CHECK` задаёт условие для строки. В `customer` бонусы должны быть не меньше нуля:

```sql run expectError=23514
insert into customer (name, email, bonus, created_at)
values ('Ирина', 'ira@example.com', -1, now());
```

Postgres возвращает `23514`: значение `-1` нарушает условие. Попытка не добавляется к шести покупателям.

## Значение по умолчанию

`DEFAULT` задаёт значение, которое Postgres подставляет, когда колонку пропустили или для неё явно указали `DEFAULT`:

```sql run expect=rows:1
insert into customer (name, email, created_at)
values ('Ирина', 'ira@example.com', now());
```

На сцене у новой строки `bonus` равен 0. Это превью: после него в базе по-прежнему шесть покупателей.

## Чего нет в выдаче и почему

- ❌ Нового автора без имени нет в таблице: вставку остановил `NOT NULL`.
- ❌ Ирины с повторным email или отрицательным бонусом нет в таблице: эти вставки нарушают ограничения.
- ❌ Ирина с нулевым бонусом тоже не сохранилась: успешное превью откатилось.

## Ловушки

<Callout kind="trap">
`CHECK (bonus >= 0)` сам по себе не запрещает `NULL`: условие с `NULL` даёт неизвестный результат, а такой результат проходит проверку. В нашей таблице отсутствие бонуса отдельно запрещает `NOT NULL`.

```sql run expectError=23502
insert into customer (name, email, bonus, created_at)
values ('Ирина', 'ira@example.com', null, now());
```

Явный `NULL` не заменяется на `DEFAULT`. Чтобы получить ноль, пропусти `bonus` или укажи `DEFAULT`.
</Callout>

## Проверь себя

1. Какую ошибку вернёт вставка автора без имени? Запусти первый пример.
2. Что произойдёт, если заменить email Анны на свободный адрес в примере `UNIQUE`?
3. Какой бонус появится, если не указывать колонку `bonus`? Проверь на доске.

<Cheatsheet>
- `NOT NULL` запрещает отсутствие значения.
- `UNIQUE` запрещает повтор значения; поведение `NULL` настраивается отдельно.
- `CHECK` проверяет условие строки, но сам по себе не заменяет `NOT NULL`.
- `DEFAULT` подставляет значение при пропуске колонки или явном указании `DEFAULT`.
</Cheatsheet>
