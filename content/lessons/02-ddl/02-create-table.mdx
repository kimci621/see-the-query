<TlDr>`CREATE TABLE` задаёт колонки и их типы. Временная таблица принадлежит текущей сессии, а превью в песочнице откатывает её создание.</TlDr>

## Что есть в данных

В начале урока пользовательских таблиц нет. Мы создадим `author` и `book`, добавим в них по строке и проверим, как работают типы.

Выполняй примеры по порядку: кнопка «Применить» сохраняет изменения для следующих запросов. Если хочешь начать заново, нажми «Сброс» в редакторе и подтверди сброс урока.

## Создадим таблицу авторов

У каждой колонки есть имя и **тип данных**. Тип задаёт, какие значения Postgres хранит в колонке и какие операции к ним применимы.

```sql run apply expect=rows:0
create table author (
  author_id bigint primary key,
  name text not null
);
```

`author_id` хранит целый номер большого диапазона, а `name` хранит текст. `PRIMARY KEY` отличает строки друг от друга; `NOT NULL` требует указать имя. Ограничения подробно разберём в следующих уроках.

Если хочешь увидеть черновик, скопируй запрос в редактор и дождись превью: на доске появится таблица с двумя колонками. Превью не сохраняет изменения. Нажми «Применить» под примером, и пустая таблица останется на доске.

Добавим автора с номером 1:

```sql apply expect=rows:1
insert into author (author_id, name) values (1, 'Михаил Шолохов');
```

После применения в `author` одна строка. Мы указали номер сами: автоматическую выдачу номеров будем изучать отдельно.

## Таблица книг и её колонки

Теперь создадим таблицу для книги. `author_id` будет ссылаться на существующего автора:

```sql run apply expect=rows:0
create table book (
  book_id bigint primary key,
  title text not null,
  author_id bigint references author (author_id),
  pages integer,
  price numeric(10, 2),
  published_on date
);
```

После применения на доске две таблицы. У `book` 6 колонок, а линия связи ведёт к `author`. Некоторые колонки могут быть свёрнуты: кнопка «+N колонки» раскрывает их на доске. У новой таблицы пока нет строк.

Типы здесь решают разные задачи:

- `integer` и `bigint` хранят целые числа. У `bigint` диапазон шире; `int` это сокращение `integer`.
- `numeric(10, 2)` подходит для цены: всего до 10 цифр, из них 2 после запятой. При записи дробь округляется до указанного масштаба.
- `text` хранит текст, `date` дату, а `timestamptz` момент времени с учётом часового пояса при вводе и выводе.
- `boolean` хранит `true` или `false`; если колонка допускает `NULL`, значение может отсутствовать.
- `text[]` хранит массив текстовых значений, а `jsonb` данные в формате JSON, например объект с полями.

<Callout kind="analogy">
Тип похож на формат поля в анкете: дату и номер просят заполнить по разным правилам. Postgres проверяет и преобразует введённое значение по правилам типа; одно и то же текстовое представление при разных типах может вести себя по-разному.
</Callout>

Добавим одну книгу и укажем дату:

```sql apply expect=rows:1
insert into book (book_id, title, author_id, pages, price, published_on)
values (1, 'Тихий Дон', 1, 1504, 890.00, '1940-01-01');
```

После применения в `book` одна строка.

```sql run expect=rows:1
select title, pages, price from book;
```

На доске остаются три выбранные колонки. В результате «Тихий Дон», 1504 страницы и цена 890.00. Остальные колонки остаются в таблице, но в этой выдаче их нет.

## Цена и вычисления

Выражение можно проверить и без таблицы. Оператор `::` приводит значение к указанному типу:

```sql run expect=rows:1
select 890.00::numeric(10, 2) as price;
```

Получаем одну строку с ценой 890.00. Для денег `numeric` позволяет хранить десятичные значения точно в пределах заданной точности; `float8` хранит приближение.

## Другие типы на примерах

Создавать отдельную таблицу для проверки значений не обязательно:

```sql run expect=rows:1
select true as available, array['роман', 'классика']::text[] as tags,
       '{"id":1}'::jsonb as details;
```

Получилась одна строка: логическое значение, массив из двух меток и JSON-объект. Их тоже можно хранить в колонках подходящих типов.

А так можно указать момент времени со смещением `+03`:

```sql run expect=rows:1
select '2024-01-15 12:00:00+03'::timestamptz as added_at;
```

В результате один момент времени. Доска показывает его в UTC: `09:00:00Z`. PostgreSQL учитывает часовой пояс подключения при текстовом выводе, но сам момент не меняется.

## Временная таблица

`CREATE TEMP TABLE` создаёт временную таблицу, доступную текущей сессии. Обычно она удаляется при завершении сессии; поведение при завершении транзакции можно настроить отдельно.

```sql run expect=rows:0
create temp table session_tmp (x integer);
```

Нажми «На доску»: в превью виден черновик `session_tmp` с одной колонкой. После превью таблица не сохраняется, потому что песочница откатывает запрос. Если же отдельно применить такую команду, таблица будет доступна в текущей сессии до её удаления или завершения сессии.

## Чего нет в выдаче и почему

- В выборке из `book` нет имени автора: запрос выбрал только `title`, `pages` и `price`. Имя находится в `author`.
- В той же выдаче нет даты `published_on`: мы её не перечислили в `SELECT`.
- Созданного только в превью `session_tmp` нет в базе после отката. Это свойство превью, а не признак любой временной таблицы.

## Ловушки

<Callout kind="trap">
Приближённый `float8` и десятичный `numeric` могут дать разный результат:

```sql run expect=rows:1
select 0.1::float8 + 0.2::float8 as float_sum,
       0.1::numeric + 0.2::numeric as numeric_sum;
```

В одной строке сравни `float_sum` и `numeric_sum`. Для `float8` может появиться `0.30000000000000004`, для `numeric` результат равен `0.3`. Полное число видно в панели «Результат»: на доске оно может не поместиться в ячейку. Для суммы денег обычно выбирают `numeric` и заранее задают точность и масштаб.

Теперь проверим, сохранилась ли временная таблица после превью:

```sql run expectError=42P01
select * from session_tmp;
```

Postgres возвращает ошибку `42P01`: таблица не найдена. Для примера её создание не применялось. Если применить `CREATE TEMP TABLE`, такой запрос сможет найти таблицу в той же сессии.
</Callout>

## Проверь себя

1. Сколько колонок в созданной `book`? Раскрой свёрнутые колонки на доске и посчитай.
2. Что вернёт `select title, price from book;`? Измени последний запрос к `book` и проверь.
3. Почему `session_tmp` не нашлась после кнопки «На доску»? Найди в уроке разницу между превью и применением.

<Cheatsheet>
- `CREATE TABLE` задаёт таблицу и тип каждой колонки.
- `integer` и `bigint` хранят целые числа; `numeric(10, 2)` хранит десятичное число с заданными точностью и масштабом.
- `text`, `date`, `timestamptz`, `boolean`, `text[]` и `jsonb` подходят для разных данных.
- `CREATE TEMP TABLE` создаёт таблицу текущей сессии. Превью в песочнице откатывается; «Применить» сохраняет изменение.
- `float8` приближённый тип. Для денежных сумм подходит `numeric`.
</Cheatsheet>
