<TlDr>Первичный ключ отличает строки, внешний ключ связывает таблицы. `ON DELETE` задаёт, что делать со ссылками при удалении.</TlDr>

## Что есть в данных

В `orders` восемь заказов. У заказа 1 две позиции в `order_item`: внешний ключ связывает их с заказом и настроен на `ON DELETE CASCADE`. В `author` есть автор с номером 1, на которого ссылаются книги.

Первичные и внешние ключи уже встречались в уроке 1.3. Здесь посмотрим, как ссылки влияют на удаление. Превью откатывается; для собственного примера ниже нужно применять указанные команды по порядку.

## Ключи и ссылки

**Первичный ключ** (`PRIMARY KEY`) выбирает уникальный непустой идентификатор строки. **Внешний ключ** (`FOREIGN KEY`) проверяет, что указанное значение ссылается на существующий ключ другой таблицы. Если внешний ключ допускает `NULL`, отсутствие ссылки тоже разрешено.

<Callout kind="analogy">
Заказ похож на папку с позициями внутри. Если удалить папку вместе с содержимым, позиции исчезнут. Но связь можно настроить иначе: оставить записи и убрать ссылку на удалённый объект.
</Callout>

## Удаление с CASCADE

```sql run expect=rows:1
delete from orders where order_id = 1;
```

На доске удаляется один заказ и вслед за ним две его позиции. Это делает `ON DELETE CASCADE` у внешнего ключа `order_item`. Превью ничего не сохраняет: после него заказ и позиции остаются в базе.

## Когда ссылка мешает удалению

```sql run expectError=23503
delete from author where author_id = 1;
```

Postgres возвращает `23503`: на автора ссылаются книги. Действие по умолчанию `NO ACTION` проверяет, что после операции не осталось нарушенных ссылок. Если ограничение отложено, проверка может быть отложена до конца транзакции. `RESTRICT` не позволяет откладывать эту проверку.

## Сохранить строки и убрать ссылку

Создадим две таблицы для собственного примера. Нажми «Применить» под каждой командой:

```sql run apply expect=rows:0
create table lesson_parent (id integer primary key);
```

После применения на доске появится пустая таблица `lesson_parent`.

```sql run apply expect=rows:0
create table lesson_child (id integer primary key, parent_id integer references lesson_parent (id) on delete set null);
```

После применения видна связь `lesson_child.parent_id` с родительской таблицей.

```sql apply expect=rows:1
insert into lesson_parent values (1);
```

```sql apply expect=rows:1
insert into lesson_child values (1, 1);
```

Примени обе вставки. Теперь одна дочерняя строка ссылается на родителя 1.

```sql run expect=rows:1
delete from lesson_parent where id = 1;
```

В превью родитель исчезает, а дочерняя строка остаётся: `parent_id` становится `NULL`. После отката превью связь снова на месте.

## Чего нет в выдаче и почему

- ❌ Заказа 1 и двух его позиций нет в сцене после удаления: позиции удаляет `CASCADE`.
- ❌ Родителя 1 нет в последней сцене: запрос его удаляет. Дочерняя строка остаётся без ссылки благодаря `SET NULL`.

## Ловушки

<Callout kind="trap">
`CASCADE` может удалить больше строк, чем перечислено в `WHERE`. Проверь связанные таблицы и их действия `ON DELETE` перед применением:

```sql run expect=rows:1
delete from orders where order_id = 1;
```

Одна удалённая строка заказа влечёт удаление двух позиций. Превью их не сохраняет.
</Callout>

<Cheatsheet>
- `PRIMARY KEY` задаёт уникальный непустой ключ строки.
- `FOREIGN KEY` проверяет ссылку на другую таблицу.
- `ON DELETE CASCADE` удаляет зависимые строки, `SET NULL` убирает ссылку.
- `NO ACTION` проверяет целостность ссылок; `RESTRICT` не допускает отложенной проверки.
</Cheatsheet>
