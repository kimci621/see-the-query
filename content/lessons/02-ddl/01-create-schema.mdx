<TlDr>Схема группирует объекты базы. Если имя таблицы написано без схемы, PostgreSQL ищет её по порядку из `search_path`.</TlDr>

## Что есть в данных

Песочница начинается без пользовательских таблиц: доска пуста. Схема `public` уже есть. Мы создадим схему `library` и по одной таблице `book` в каждой схеме, чтобы сравнить результаты запросов.

Выполняй примеры по порядку. Кнопка «Применить» сохраняет изменение в песочнице; следующие запросы зависят от предыдущих. Чтобы начать заново, нажми «Сброс» в редакторе и подтверди сброс урока.

## Создадим схему

`CREATE SCHEMA` добавляет схему в текущую базу. Назовём её `library`:

```sql run apply expect=rows:0
create schema library;
```

Нажми «Применить» под примером. Пустая схема создана, но на базовой доске рамка пока не появится: доска показывает схему вместе с её таблицами.

Если хочешь увидеть создание до применения, сначала скопируй запрос в редактор и дождись превью. На сцене появится рамка `library`; само превью изменение не сохраняет. Затем нажми «Применить» под примером.

Теперь создадим таблицу внутри `library`. Имя перед точкой обозначает схему, после точки стоит имя таблицы:

```sql run apply expect=rows:0
create table library.book (
  book_id integer primary key,
  title text not null
);
```

После применения на доске появится таблица `book` внутри рамки `library`. В ней две колонки и пока нет строк. Заполним одну:

```sql apply expect=rows:1
insert into library.book values (1, 'Тихий Дон');
```

После применения в таблице одна книга. Указав `library.book`, мы обратились к конкретной таблице независимо от пути поиска.

## Обратимся по полному имени

```sql run expect=rows:1
select * from library.book;
```

На доске показана одна строка: номер 1 и «Тихий Дон». В этом запросе схема названа явно. PostgreSQL не нужно выбирать между одноимёнными таблицами в разных схемах.

<Callout kind="analogy">
Схемы похожи на отделы библиотеки, в каждом может лежать свой каталог `book`. Запись `library.book` указывает и отдел, и каталог. В отличие от папок на компьютере, схемы PostgreSQL не вкладываются друг в друга.
</Callout>

## Куда смотрит search_path

**Путь поиска** (`search_path`) задаёт порядок схем для имён без префикса. Посмотрим настройку нашей песочницы:

{/* final-only: SHOW возвращает настройку, но пошаговая трасса для него пока не поддерживается */}
```sql run expect=rows:1 trace=final-only
show search_path;
```

В результате одна строка со значением `public`. Это настройка песочницы. В другой базе путь может отличаться; схемы, которых нет или к которым нет доступа, пропускаются. Системная схема `pg_catalog` тоже участвует в поиске, даже когда её нет в показанном списке.

Создадим другую таблицу с тем же именем, но в `public`:

```sql run apply expect=rows:0
create table public.book (
  book_id integer primary key,
  title text not null
);
```

И добавим в неё другую книгу:

```sql apply expect=rows:1
insert into public.book values (2, 'Капитанская дочка');
```

Теперь в базе две разные таблицы `book`, по одной строке в каждой. Одинаковые короткие имена допустимы, потому что схемы разные.

```sql run expect=rows:1
select * from public.book;
```

Здесь вернулась «Капитанская дочка». На доске ищи таблицу `book` в рамке `public`. По полному имени `library.book` мы получали «Тихий Дон».

## Чего нет в выдаче и почему

- «Тихого Дона» нет в запросе к `public.book`: он лежит в другой таблице, `library.book`.
- «Капитанской дочки» нет в запросе к `library.book`: она записана в `public.book`.
- Поиск `book` без схемы не объединяет обе таблицы: выбирается первая подходящая.

## Ловушки

<Callout kind="trap">
Если схему не указать, PostgreSQL берёт первую подходящую таблицу в пути поиска. Сейчас в пути указана `public`:

```sql run expect=rows:1
select * from book;
```

Получилась «Капитанская дочка» из `public.book`. Таблица `library.book` существует, но в показанную настройку пути схема `library` пока не входит.

Изменим порядок схем для текущего подключения:

```sql apply expect=rows:0
set search_path = library, public;
```

Выполни тот же запрос ещё раз:

```sql run expect=rows:1
select * from book;
```

Теперь вернётся «Тихий Дон»: `library` стоит раньше `public`. Если нужна конкретная таблица независимо от настройки, укажи её полное имя, например `public.book`.
</Callout>

## Проверь себя

1. Сколько строк в каждой таблице после всех вставок? Запусти запросы с полными именами и сравни.
2. Какую книгу вернёт `select * from book` после изменения пути? Проверь на доске.
3. Что вернёт `select * from public.book`, если `library` стоит первой в пути? Измени запрос в редакторе и проверь.

<Cheatsheet>
- `CREATE SCHEMA library` создаёт схему в текущей базе.
- `library.book` указывает схему и таблицу явно.
- `SHOW search_path` показывает настройку поиска для текущего подключения.
- `SET search_path = library, public` ставит `library` перед `public`.
- При одинаковых именах без указания схемы находится первая подходящая таблица в пути.
</Cheatsheet>
