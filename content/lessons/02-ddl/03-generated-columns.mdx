<TlDr>Генерируемая колонка вычисляется из других колонок строки. Postgres сам обновляет её значение, а напрямую записать значение нельзя.</TlDr>

## Что есть в данных

В начале урока таблиц нет. Создадим таблицу и добавим строку. Выполняй примеры по порядку: нажимай «Применить» там, где это указано. «Сброс» вернёт урок в начало.

## Сумма из цены и количества

Пусть сумма покупки равна цене, умноженной на количество. Вместо того чтобы передавать её отдельно, зададим формулу в определении таблицы:

<Callout kind="analogy">
Генерируемая колонка похожа на сумму в чеке: меняешь количество товара, и сумма следует за ним. Формулу хранит база, поэтому повторно передавать сумму не нужно.
</Callout>

```sql run apply expect=rows:0
create table t (
  price numeric,
  qty integer,
  total numeric generated always as (price * qty) stored
);
```

Нажми «Применить», чтобы сохранить таблицу. `STORED` означает, что Postgres вычисляет `total` при записи строки и хранит результат.

Добавим покупку: две книги по 890.

```sql run apply expect=rows:1
insert into t (price, qty) values (890, 2);
```

Примени вставку. На доске в колонке `total` появится 1780, хотя мы не указали её в `INSERT`.

```sql run expect=rows:1
select price, qty, total from t;
```

Теперь изменим количество в превью:

```sql run expect=rows:1
update t set qty = 3;
```

В сцене сумма меняется с 1780 на 2670. Превью откатывается, поэтому сохранённое количество остаётся равным двум. Чтобы сохранить изменение, нажми «Применить».

## STORED и VIRTUAL

В PostgreSQL 18 есть два вида генерируемых колонок. `STORED` вычисляется при вставке или изменении строки и хранится в таблице. `VIRTUAL` вычисляется при чтении и не занимает места для хранения значения. Если вид не указан, в PostgreSQL 18 выбирается `VIRTUAL`. В более ранних версиях правила могут отличаться.

Выражение может обращаться к колонкам текущей строки, но не к другим генерируемым колонкам. Подзапросы и изменчивые функции, например `random()`, в нём не разрешены.

## Чего нет в выдаче и почему

- ❌ Строки с количеством 3 нет в сохранённой таблице, если ты только посмотрел превью: `UPDATE` откатился.

## Ловушки

<Callout kind="trap">
Нельзя подменить результат формулы своим числом:

```sql run expectError=428C9
insert into t (price, qty, total) values (1, 1, 5);
```

Postgres вернёт ошибку `428C9`. Укажи только исходные колонки или передай для генерируемой колонки ключевое слово `DEFAULT`: значение всё равно вычислит база.
</Callout>

Обычный `DEFAULT` работает иначе: он задаёт значение при вставке, когда его не передали. Генерируемая колонка связана с формулой и пересчитывается при изменении исходных данных.

## Проверь себя

1. Чему равен `total` для цены 890 и количества 2? Найди значение на доске.
2. Что произойдёт с суммой, если изменить количество на 3? Проверь запросом `UPDATE` в превью.
3. Почему нельзя вставить в `total` число 5 напрямую?

<Cheatsheet>
- `GENERATED ALWAYS AS (выражение)` задаёт формулу для колонки.
- `STORED` хранит результат, `VIRTUAL` вычисляет его при чтении.
- В PostgreSQL 18 без указания вида выбирается `VIRTUAL`.
- Напрямую задать значение нельзя; `DEFAULT` в `INSERT` или `UPDATE` разрешён.
</Cheatsheet>
