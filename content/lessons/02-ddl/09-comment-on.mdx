<TlDr>`COMMENT ON` добавляет описание к таблице, колонке или другому объекту. Комментарий хранится в каталоге и виден всем, кто читает схему.</TlDr>

## Что есть в данных

В `book` одиннадцать книг. У таблицы пока нет комментария: в каталоге на месте описания `NULL`.

## Добавить комментарий

```sql run expect=rows:0
comment on table book is 'Каталог книг магазина';
```

На доске рядом с `book` появляется подпись. Превью откатится, и комментарий исчезнет вместе с ним. Это не данные и не ограничение: описание лежит в системном каталоге и не влияет на запросы.

Чтобы комментарий остался в базе, примени ту же команду:

```sql run apply expect=rows:0
comment on table book is 'Каталог книг магазина';
```

Применение записывает изменение без сцены. Дальше его увидят все запросы к каталогу.

## Прочитать комментарий

```sql run expect=rows:1
select obj_description('book'::regclass) as comment;
```

`obj_description` принимает объект каталога и возвращает его описание. Для колонки есть отдельная функция `col_description`. Комментарии также показывает `\d+ book` в psql.

## Убрать комментарий

```sql run expect=rows:0
comment on table book is null;
```

На доске подпись исчезает: `NULL` стирает описание. Сама таблица и данные остаются на месте. Превью вернёт комментарий обратно.

## Зачем это нужно

Комментарий переживает смену разработчика и виден из базы, а не из вики, которая устарела. Хорошее описание отвечает на вопрос «что здесь лежит и почему», а не пересказывает имя колонки. Например, у `price` полезно указать валюту, а у `status` перечислить допустимые значения.

## Чего нет в выдаче и почему

- ❌ Комментария нет в строках `book`: он хранится в каталоге, а не в таблице.
- ❌ После превью с `is null` подписи на доске нет: описание стёрлось и вернулось с откатом.

## Ловушки

<Callout kind="trap">
Комментарий не проверяется базой. Опечатка или устаревшее описание останутся как есть, пока кто-то не поправит их вручную. Не пиши в комментарии правила, которые уже выражены ограничениями: они проверяются автоматически.
</Callout>

<Callout kind="tip">
Комментарии удобно ставить на таблицы и колонки, смысл которых не очевиден из имени: единицы измерения, формат, источник данных. Для больших схем это дешёвая документация рядом с данными.
</Callout>

## Проверь себя

1. Где хранится комментарий к таблице?
2. Что вернёт `obj_description`, если комментарий не задан?
3. Чем `comment on table` отличается от `alter table ... add constraint`?

<Cheatsheet>
- `comment on table book is '...'` добавляет описание таблицы.
- `comment on column book.price is '...'` добавляет описание колонки.
- `is null` удаляет комментарий.
- `obj_description('book'::regclass)` читает комментарий таблицы.
- `col_description('book'::regclass, 1)` читает комментарий колонки по номеру.
</Cheatsheet>
