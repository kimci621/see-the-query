<TlDr>Скалярный подзапрос возвращает ровно одно значение. Оно подставляется в каждую строку внешнего запроса, как обычное число.</TlDr>

## Что есть в данных

В <T id="public.book">book</T> 11 книг. Самая дорогая стоит 3200.00, это «Изучаем Python». У «Острова погибших кораблей» в <C id="public.book.price">price</C> стоит NULL. Оба числа пригодятся дальше.

## Одно число на всю таблицу

Начнём с обычного агрегата:

```sql run expect=rows:1
select max(price) from book;
```

Одна строка, 3200.00. Теперь поставим тот же запрос внутрь скобок:

```sql run expect=rows:11
select title, (select max(price) from book) as max_price from book order by book_id;
```

11 строк, и в каждой колонке `max_price` одно и то же число 3200.00. Подзапрос вернул одно значение, и оно подставилось в каждую строку.

На доске мини-сцена подзапроса сжимается в карточку со значением 3200.00. Дальше это значение улетает в ячейку каждой из 11 строк. Подпись шага: «Подзапрос: одно значение 3200.00».

<Callout kind="analogy">
Справочник на стене. Ты заполняешь 11 бланков и в графу «максимальная цена» каждый раз вписываешь одно и то же число из справочника. Справочник не меняется от бланка к бланку.
</Callout>

Пройди главное одной сценой:

<Scene>

```sql run expect=rows:1
select max(price) from book;
```

</Step>
<Step caption="Снаружи: 11 строк, в каждой 3200.00">

## Значение можно считать

Скалярный подзапрос это выражение. С ним работают как с числом: складывают, вычитают, сравнивают.

```sql run expect=rows:11
select title, price, round(price - (select avg(price) from book), 2) as diff
from book order by book_id;
```

Средняя цена 1138.00: 11380 делим на 10 книг с ценой. Снова 11 строк, потому что подзапрос не добавляет и не убирает строки. У «Тихого Дона» разница -248.00, у «Изучаем Python» 2062.00. У «Острова погибших кораблей» цена NULL, и разность тоже NULL.

## Подзапрос в WHERE

Тот же приём работает в условии:

```sql run expect=rows:3
select title, price from book where price > (select avg(price) from book) order by book_id;
```

3 строки: «Python. К вершинам мастерства», «Простой Python» и «Изучаем Python». Порог один для всех, 1138.00. Подзапрос не знает, какую строку проверяет `WHERE`, поэтому считает одно и то же число. На доске он выполняется отдельной мини-сценой один раз, потом сканер идёт по 11 строкам.

## Ноль строк это не ошибка

```sql run expect=rows:11
select title, (select price from book where book_id = 99) as missing_price
from book order by book_id;
```

11 строк, во всех `missing_price` равен NULL. Подзапрос не нашёл ни одной строки, и скалярный контекст превратил пустоту в NULL. Ошибка начинается только когда строк две или больше.

## Чего нет в выдаче и почему

- ❌ 11 разных значений `max_price`: подзапрос не зависит от строки, число одно на весь запрос.
- ❌ Строка «Остров погибших кораблей» в запросе с `diff`: цена NULL, разность NULL.
- ❌ 8 книг в запросе с `WHERE`: порог 1138.00 прошли только 3.
- ❌ Пустая колонка в запросе с `book_id = 99`: подзапрос пуст, снаружи 11 строк с NULL.
- ❌ Хоть одна строка в запросе с ошибкой: Postgres отказался его выполнять.

## Ловушки

<Callout kind="trap">
Скалярный подзапрос обязан вернуть не больше одной строки. Здесь внутренний запрос отдаёт все 11 цен:

```sql run expectError=21000
select title, (select price from book) as p from book;
```

Код `21000`, текст `more than one row returned by a subquery used as an expression`. Postgres не берёт первую строку и не усредняет сам. Он отказывается угадывать. Если нужно много значений, это уже `IN`, `EXISTS` или `JOIN`, а не скалярный подзапрос.
</Callout>

<Callout kind="tip">
Скалярный подзапрос удобен для одного числа: максимума, средней, количества. Если внутри появился `GROUP BY`, проверь, что на выходе правда одна строка. Иначе получишь `21000`.
</Callout>

## Проверь себя

1. Сколько строк вернёт `select title from book where price > 500`? Сначала ответь, потом проверь на доске.
2. Что покажет `select title, (select price from book where category_id = 3) as p from book`? Посчитай строки внутри подзапроса.
3. Поменяй `max` на `min` в первом запросе. Какое число окажется в каждой строке?

<Cheatsheet>
- `(select ...)` в выражении: одна колонка и не больше одной строки.
- Одна строка даёт значение. Ноль строк дают NULL. Две строки и больше дают ошибку `21000`.
- Некоррелированный подзапрос не зависит от строки, значение одинаковое для всех.
- В `WHERE` скалярный подзапрос работает как постоянный порог.
- Нужен набор значений: бери `IN`, `EXISTS` или `JOIN`.
</Cheatsheet>
