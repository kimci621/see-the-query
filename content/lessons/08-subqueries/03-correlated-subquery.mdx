<TlDr>Коррелированный подзапрос ссылается на строку внешнего запроса. Поэтому для каждой строки он считается заново со своими значениями.</TlDr>

## Что есть в данных

В <T id="public.book">book</T> 11 книг и 5 авторов. У Шолохова две книги: 890.00 и 350.00, средняя 620.00. У Рамальо одна книга за 2400.00. У Пушкина 420.00 и 350.00, средняя 385.00. У Беляева 560.00 и NULL, средняя 560.00. У Верна две книги по 610.00, средняя 610.00. Ещё две книги остались без автора: «Простой Python» и «Изучаем Python».

## Средняя по автору

```sql run expect=rows:6
select author_id, round(avg(price), 2) as avg_price
from book
group by author_id
order by author_id nulls last;
```

6 строк: пять авторов и одна строка `NULL`. У строки `NULL` средняя 2595.00, но это средняя по двум книгам без автора, а не по несуществующему автору.

## Сравниваем с порогом своей группы

```sql run expect=rows:2
select title from book b
where price > (select avg(price) from book where author_id = b.author_id)
order by book_id;
```

2 строки: «Тихий Дон» и «Капитанская дочка». Внутри скобок стоит `b.author_id`, ссылка на текущую строку внешнего запроса.

Для «Тихого Дона» подзапрос считает среднюю по Шолохову, 620.00, и сравнивает 890.00 с 620.00. Для «Капитанской дочки» считает по Пушкину, 385.00, и сравнивает 420.00 с 385.00. Остальные книги порог не прошли.

На доске для первых трёх строк внешнего запроса запускается своя мини-сцена: «Тихий Дон» со средней 620.00, «Python. К вершинам мастерства» со средней 2400.00, «Судьба человека» с той же 620.00. Дальше плеер не повторяет сцену для каждой строки: остальные вердикты он берёт из итога. Подпись шага: «Коррелированный подзапрос: 3 строки».

<Callout kind="analogy">
Учитель проверяет диктанты. Общий порог для всего класса это некоррелированный подзапрос. А коррелированный это «сравни с прошлой оценкой этого же ученика»: для каждой тетради учитель открывает личное дело именно этого ученика.
</Callout>

## Против общего среднего

Похожий запрос без ссылки на внешнюю строку даёт другой ответ:

```sql run expect=rows:3
select title, price from book where price > (select avg(price) from book) order by book_id;
```

3 строки, а не 2. Здесь порог общий, 1138.00, а не средняя по автору. Коррелированный запрос отвечает «дороже своих», этот отвечает «дороже всех». Сравни числа: 2 против 3.

Пройди главное одной сценой:

</Step>

```sql run expect=rows:2
select title from book b
where price > (select avg(price) from book where author_id = b.author_id)
order by book_id;
```

</Step>

## Чего нет в выдаче и почему

- ❌ «Python. К вершинам мастерства»: 2400.00 равно средней Рамальо, а нужно строго больше.
- ❌ «Голова профессора Доуэля»: 560.00 равно средней Беляева.
- ❌ «Путешествие к центру Земли» и «Дети капитана Гранта»: 610.00 равно средней Верна.
- ❌ «Остров погибших кораблей»: цена NULL, сравнение дало UNKNOWN.
- ❌ «Простой Python» и «Изучаем Python»: `author_id` равен NULL, подзапрос не находит строк, средняя NULL.
- ❌ 3 строки из запроса с общим средним: там другой порог, 1138.00 вместо средней по автору.

## Ловушки

<Callout kind="trap">
Одинаковое имя внутри и снаружи прячет корреляцию:

```sql run expect=rows:3
select title from book b
where price > (select avg(price) from book b)
order by book_id;
```

3 строки, ошибки нет. Внутренняя таблица тоже названа `b`, и `avg(price)` считается по всем книгам. Внешняя строка больше не участвует: запрос стал некоррелированным и отвечает на другой вопрос. Дай внутренней таблице другое имя, например `b2`, и условие снова начнёт ссылаться на внешнюю строку.
</Callout>

<Callout kind="tip">
Коррелированный подзапрос удобен для правила «дороже своих». На большой таблице он может быть дорогим: вложенный запрос считается для каждой внешней строки. Если тот же ответ даёт `JOIN` с готовыми средними, сравни план выполнения и время.
</Callout>

## Проверь себя

1. Поменяй `>` на `>=` в главном запросе. Сколько строк останется? Сначала ответь, потом проверь.
2. Поменяй `>` на `<`. Сколько строк вернётся?
3. Почему книги без автора не проходят сравнение даже с очень большим порогом?

<Cheatsheet>
- Коррелированный подзапрос ссылается на внешнюю строку, например `b.author_id`.
- Он считается для каждой внешней строки, поэтому порог у каждой строки свой.
- Без ссылки на внешнюю строку подзапрос становится некоррелированным и отвечает на другой вопрос.
- Внешнее значение NULL не находит пары: `NULL = NULL` не истина, средняя получается NULL.
- Одинаковый алиас внутри и снаружи молча прячет корреляцию. Бери разные имена.
</Cheatsheet>
