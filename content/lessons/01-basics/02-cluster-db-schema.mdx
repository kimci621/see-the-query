<TlDr>В кластере находятся базы, внутри базы схемы, а внутри схемы таблицы. Имя схемы помогает найти нужную таблицу.</TlDr>

## Что есть в данных

В этой песочнице открыта база `postgres`. В схеме `public` лежат 8 таблиц книжного магазина. На доске показаны две: <T id="public.book">book</T> с 11 книгами и <T id="public.author">author</T> с 6 авторами. Остальные тоже есть в базе.

Рамка вокруг таблиц на доске подписана `public`. Это имя схемы, а не отдельная таблица.

## От кластера до таблицы

**Кластер PostgreSQL** объединяет базы данных, которыми управляет один экземпляр сервера. В одном кластере может быть несколько баз. Подключение работает с одной выбранной базой; чтобы обратиться к другой, обычно открывают отдельное подключение.

Внутри базы находятся **схемы**. Схема объединяет объекты по именам: в ней могут лежать таблицы, функции и другие объекты. Схема не вкладывается в другую схему.

Посмотри на положение <T id="public.book">book</T> в нашей песочнице:

<Nesting path="postgres/public/book" />

На доске видна только нижняя часть этой картинки: рамка `public` и таблицы в ней. Кластер и базу доска не рисует как таблицы.

Проверим имя базы, к которой подключена песочница:

```sql run expect=rows:1
select current_database();
```

Одна строка, значение `postgres`. На сцене появляется результат из одной ячейки: функция берёт имя текущей базы, а не читает строки <T id="public.book">book</T>.

## Что лежит в public

Полное имя таблицы внутри базы состоит из схемы и имени таблицы. Точка разделяет их: `public.book`.

```sql run expect=rows:1
select title from public.book where book_id = 1;
```

На доске сканер проходит <T id="public.book">book</T>, а `WHERE` оставляет одну строку. В результате «Тихий Дон». Мы указали схему явно и обратились к таблице внутри неё.

Имена таблиц текущей схемы можно запросить у самой базы. Для этого есть представление `information_schema.tables`:

{/* final-only: information_schema.tables это представление, пошаговая трасса для него пока не поддерживается */}
```sql run expect=rows:8 trace=final-only
select table_name
from information_schema.tables
where table_schema = 'public'
order by 1;
```

В результате 8 имён, среди них `author`, `book` и `review`. Они отсортированы по имени. Здесь смотри на панель результата: содержимое системного представления доска по шагам пока не показывает.

## Как Postgres находит таблицу без схемы

В запросах предыдущего урока мы писали `book` без имени схемы. Postgres нашёл таблицу по **`search_path`**: это список схем для поиска. Он просматривает их по порядку и берёт первое подходящее имя.

Посмотрим настройку песочницы:

{/* final-only: SHOW возвращает настройку, но пошаговая трасса для него пока не поддерживается */}
```sql run expect=rows:1 trace=final-only
show search_path;
```

В одной строке увидишь `public`. Поэтому в этой песочнице запрос без имени схемы находит `public.book`:

```sql run expect=rows:1
select title from book where book_id = 1;
```

Снова «Тихий Дон». На доске фокусируется та же таблица, что и в запросе с `public.book`.

<Callout kind="analogy">
Представь стойку выдачи с несколькими секциями. В каждой может лежать папка с названием `book`. Если назвать секцию вместе с папкой, нужную найдут сразу. Если назвать только папку, придётся проверять секции в установленном порядке. `search_path` задаёт этот порядок для схем.
</Callout>

В другой установке путь может быть другим. Например, стандартная настройка PostgreSQL часто выглядит как `"$user", public`: сначала ищется схема с именем текущего пользователя, если она существует и доступна, затем `public`. Системная схема `pg_catalog` тоже участвует в поиске, даже когда её нет в показанном списке.

## Какие ещё схемы есть

Запросим имена схем, доступных текущему пользователю:

{/* final-only: information_schema.schemata это представление, пошаговая трасса для него пока не поддерживается */}
```sql run expect=rows:4 trace=final-only
select schema_name from information_schema.schemata order by 1;
```

Здесь 4 строки: `information_schema`, `pg_catalog`, `pg_toast` и `public`. Точный список зависит от базы и прав пользователя. В служебных схемах Postgres хранит сведения, нужные для работы; таблицы книжного магазина находятся в `public`.

## Чего нет в выдаче и почему

- Таблицы из других схем не попали в список таблиц магазина: запрос оставил только `table_schema = 'public'`.
- `postgres` не попал в список схем: это имя базы, уровень выше.
- Книги и авторы не появились в списке схем: `book` и `author` это таблицы внутри `public`.

## Ловушки

<Callout kind="trap">
Две схемы одной базы могут содержать таблицы с одинаковым именем. Представь, что есть `shop.book` и `archive.book`, а путь поиска начинается с `shop`, затем идёт `archive`. Тогда этот запрос обратится к `shop.book`:

```sql noexec
select * from book;
```

Это мысленный пример: схем `shop` и `archive` в песочнице пока нет. Если поменять их местами в пути, тот же запрос найдёт `archive.book`. Когда важна конкретная таблица, укажи схему: например, `public.book`. Создавать свои схемы и менять путь будем в уроке 2.1.
</Callout>

<Cheatsheet>
- Кластер содержит базы, база содержит схемы, схема содержит таблицы и другие объекты.
- `current_database()` показывает имя базы текущего подключения. В песочнице это `postgres`.
- `public.book`: схема `public`, таблица `book`.
- `search_path` задаёт порядок поиска имени без схемы. `show search_path` показывает настройку текущей сессии.
- `information_schema` даёт сведения об объектах, доступных текущему пользователю.
</Cheatsheet>
