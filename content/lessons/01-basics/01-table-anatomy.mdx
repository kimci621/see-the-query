<TlDr>Таблица это сетка: строка один объект, колонка одно свойство, ячейка значение со своим типом.</TlDr>

## Что есть в данных

На доске две таблицы: <T id="public.book">book</T> с 11 книгами и <T id="public.author">author</T> с 6 авторами. В уроке понадобятся две книги. У «Острова погибших кораблей» нет цены, у «Простого Python» нет автора.

## Таблица это сетка

Данные в PostgreSQL лежат в **таблицах**. Таблица выглядит так же, как на доске: шапка с именем, ряд колонок, под ним строки.

```sql run expect=rows:11
select * from book;
```

11 строк. Над <T id="public.book">book</T> поднимается призрак со всеми 9 колонками, а в шапке таблицы на доске стоит то же число 11.

<Callout kind="analogy">
Представь журнал записи в поликлинике. Одна строка журнала это один визит. Графы журнала это фамилия, кабинет, время. Ячейка это то, что вписано в графу у конкретного визита. Фамилию в графу «время» никто не пишет: у каждой графы своё назначение.
</Callout>

## Строка

**Строка** это один объект: одна книга, один автор. Набор колонок у таблицы задан заранее, а строк сколько угодно: добавили книгу, стало 12.

У строки нет имени и нет номера. Postgres не обещает, в каком порядке отдаст строки, если порядок не попросили. Поэтому на строку указывают через значение колонки, которое у всех строк разное. В <T id="public.book">book</T> это <C id="public.book.book_id">book_id</C>, подробно про ключи в уроке 1.3.

Возьмём книгу с `book_id = 7`:

```sql run expect=rows:1
select * from book where book_id = 7;
```

Одна строка: «Остров погибших кораблей». На шаге `WHERE` сканер проходит все 11 строк призрака, 10 краснеют и уходят, одна остаётся.

## Колонка

**Колонка** это одно свойство, общее для всех строк таблицы. У <T id="public.book">book</T> есть <C id="public.book.title">title</C>, <C id="public.book.price">price</C>, <C id="public.book.pages">pages</C> и ещё шесть колонок.

Выберем три:

```sql run expect=rows:11
select title, price, pages from book;
```

Строк снова 11, колонок 3. Строки не пропали, у каждой осталась только запрошенная часть. На шаге `SELECT` лишние колонки уходят из призрака.

## Ячейка

**Ячейка** это значение на пересечении строки и колонки. Одна строка и одна колонка дают одну ячейку:

```sql run expect=rows:1
select title from book where book_id = 7;
```

В ответе одна ячейка: «Остров погибших кораблей». Меньше куска данных в таблице не бывает.

## У каждой колонки свой тип

**Тип** говорит, какие значения могут лежать в колонке и что с ними можно делать. Тип подписан на доске под именем каждой колонки.

```sql run expect=rows:1
select title, price, pages, published_at, tags from book where book_id = 1;
```

Это «Тихий Дон». <C id="public.book.price">price</C> имеет тип `numeric(10,2)`: число с двумя знаками после запятой, отсюда 890.00. <C id="public.book.pages">pages</C> это `integer`, целое 1504. <C id="public.book.published_at">published_at</C> это `date`, дата без времени: 1940-01-01. <C id="public.book.tags">tags</C> это `text[]`, массив строк `{классика,роман}`.

Цену можно сравнить с числом, а название нельзя:

```sql run expectError=42883
select title from book where title = 5;
```

Под редактором карточка ошибки «Нет такой функции или оператора» с кодом `42883`. Разверни «Текст Postgres», там оригинал: `operator does not exist: text = integer`. Оператора «равно» для текста и целого числа нет, и запрос падает целиком. Как явно переводить значение в другой тип, разберём в главе 5.

## Пустая ячейка это NULL

Если значения нет, в ячейке лежит **NULL**. Это не ноль и не пустая строка, а отметка «значение неизвестно».

```sql run expect=rows:1
select title, price from book where price is null;
```

Одна строка: «Остров погибших кораблей». NULL на доске рисуется серой плашкой с пунктиром, его не спутать с числом. Сравнивают с NULL особым способом, через `IS NULL`. Почему так, разберём в уроке 4.5.

Пройди всё по шагам. Первый шаг отправь «На доску», дальше листай «Дальше»:

## Чего нет в выдаче и почему

- ❌ 10 книг в запросе с `book_id = 7`: у них другой `book_id`.
- ❌ Остальные колонки в запросе одной ячейки: попросили только `title`.
- ❌ «Остров погибших кораблей» в ловушке ниже с `price = 0`: цены у него нет, а NULL не ноль.

## Ловушки

<Callout kind="trap">
NULL это не ноль. Новичок ищет книги без цены через `price = 0`:

```sql run expect=rows:0
select title from book where price = 0;
```

Пусто. Нажми на чип `WHERE`: «осталось 0 из 11 строк, UNKNOWN у 1». Этот UNKNOWN и есть «Остров»: цена у него не 0, её нет, и Postgres не может сказать, равна она нулю или нет.

Пустой строке NULL тоже не равен. Пустая строка это известное значение, текст из нуля символов. На доске она выглядит как `''`, а NULL как серая плашка. Книги без цены ищут через `price is null`.
</Callout>

<Callout kind="tip">
В консоли psql типы колонок показывает команда `\d book`. Здесь они подписаны прямо на доске. Перед запросом глянь на типы: так меньше ошибок с несовпадением типов.
</Callout>

## Проверь себя

1. Сколько строк и колонок вернёт `select name, country from author;`? Сначала ответь, потом запусти.
2. Какой `book_id` у «Простого Python»? Достань его ячейку <C id="public.book.author_id">author_id</C> и посмотри, что в ней.
3. Какой тип у года рождения автора? Найди колонку <C id="public.author.born_year">born_year</C> на доске.

<Cheatsheet>
- Таблица: шапка, колонки, строки. Строка: один объект. Колонка: одно свойство. Ячейка: одно значение.
- Число колонок фиксировано, число строк меняется. Порядок строк не гарантирован.
- У каждой колонки тип. Текст с числом не сравнить: ошибка `42883`.
- Нет значения: NULL. Это не ноль и не `''`. Ищут через `is null`.
- `select колонки from таблица where условие`: условие выбирает строки, список после `select` выбирает колонки.
</Cheatsheet>
