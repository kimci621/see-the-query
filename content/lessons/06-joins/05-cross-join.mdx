<TlDr>`CROSS JOIN` соединяет каждую строку одной таблицы с каждой строкой другой. Условия `ON` нет, поэтому строк в результате ровно `N × M`.</TlDr>

## Что есть в данных

В <T id="public.author">author</T> 6 авторов, в <T id="public.book">book</T> 11 книг. Все книги разные: есть дорогие, есть без цены, есть без автора. Для `CROSS JOIN` это не важно: он не сравнивает значения, а берёт все сочетания строк.

Два числа урока: 6 × 11 = 66 и 6 × 2 = 12. Первое получится, если взять все книги, второе если ограничить вторую сторону двумя.

## Все пары

Соединим всех авторов со всеми книгами:

```sql run expect=rows:66
select a.name, b.title
from author a
cross join book b
order by a.name, b.title;
```

66 строк. Каждый автор встречается 11 раз, каждая книга 6 раз. Это и есть **декартово произведение**: все пары, без исключений.

На доске шаг `CROSS JOIN` рисует веер линий от каждой строки author к каждой строке book. Подпись: «CROSS JOIN: 6 × 11 = 66 строк». Красных строк с крестиком нет: в `CROSS JOIN` не бывает строк без пары, потому что условия, которое могло бы не выполниться, тоже нет.

`CROSS JOIN` не смотрит на `NULL`. Книга без автора всё равно соединится с каждым автором, потому что сравнения не происходит.

Тот же результат даёт запятая в `FROM`:

```sql run expect=rows:66
select a.name, b.title
from author a, book b
order by a.name, b.title;
```

Это старый синтаксис. Запятая между таблицами означает `CROSS JOIN`, а условие соединения тогда пишут в `WHERE`.

## Ограничить вторую сторону

Второй стороной не обязана быть целая таблица. Возьмём две самые дорогие книги:

```sql run expect=rows:12
select a.name, b.title
from author a
cross join (
  select title
  from book
  order by price desc nulls last, book_id
  limit 2
) b
order by a.name, b.title;
```

12 строк. Подзапрос выбрал «Изучаем Python» за 3200 и «Python. К вершинам мастерства» за 2400. Каждый из 6 авторов встретился с каждой из 2 книг.

Подзапрос во `FROM` в этом уроке показывается только итогом: пошаговая анимация для него появится в уроке 8.2. Число строк и результат при этом настоящие.

## CROSS JOIN и WHERE

Тот же результат можно получить фильтром после полного произведения:

```sql run expect=rows:12
select a.name, b.title
from author a
cross join book b
where b.book_id in (2, 11)
order by a.name, b.title;
```

12 строк, те же две книги. Разница в том, что здесь сначала образуются все 66 пар, а `WHERE` оставляет 12. На доске это видно: шаг `CROSS JOIN` даёт 66 строк, шаг `WHERE` оставляет 12 из 66.

Для двух книг разница незаметна. Для больших таблиц она решает: произведение растёт быстро.

## Чего нет в выдаче и почему

- ❌ Девять книг в запросе с подзапросом: подзапрос оставил только две самые дорогие.
- ❌ 54 пары в запросе с `where b.book_id in (2, 11)`: фильтр оставил 2 книги из 11, то есть 6 × 2 = 12 строк.
- ❌ Строки без пары: в `CROSS JOIN` их не бывает, он не проверяет условия.
- ❌ 66 строк в запросе с `count(*)`: агрегат свернул все пары в одну строку с числом 66.

## Ловушки

<Callout kind="trap">
Забытое условие в старом синтаксисе даёт произведение вместо соединения:

```sql run expect=rows:1
select count(*) as pairs
from author a, book b;
```

1 строка, в ней 66. Если это был отчёт «авторы и их книги», он покажет каждому автору все книги магазина. На маленьком датасете это выглядит странно, на больших таблицах превращается в миллионы строк. Запятая в `FROM` всегда `CROSS JOIN`, даже если ты этого не хотел.
</Callout>

<Callout kind="tip">
`CROSS JOIN` нужен для комбинаций: все сотрудники на все дни смены, все авторы на все категории для матрицы. Держи вторую сторону маленькой, например через подзапрос с `LIMIT` или через список значений. Если нужна не вся сетка, а пары по условию, это обычный `JOIN` с `ON`.
</Callout>

## Проверь себя

1. Сколько строк даст `author cross join book_category`? Категорий 6, авторов 6.
2. Сколько строк даст `book cross join book`? Книг 11.
3. Сколько строк останется, если в запросе на 66 строк добавить `where a.country = 'Россия'`? Российских авторов 4.

<Cheatsheet>
- `a cross join b`: каждая строка `a` с каждой строкой `b`, всего `N × M`.
- `from a, b` это тот же `CROSS JOIN`, старый синтаксис.
- Условия `ON` нет. `WHERE` применяется после произведения.
- В `CROSS JOIN` не бывает строк без пары, `NULL` не мешает.
- Для комбинаций, матриц и календарей. Следи за размером второй стороны.
- Забытое условие в запятом `FROM` размножает строки.
</Cheatsheet>
