<TlDr>`JOIN` повторяет строку левой таблицы столько раз, сколько пар нашлось справа. Один заказ с тремя позициями даёт три строки, и `count(*)` считает уже их, а не заказы.</TlDr>

## Что есть в данных

В <T id="public.orders">orders</T> 8 заказов. В <T id="public.order_item">order_item</T> 15 позиций: у заказа 3 их три, у заказов 1, 5, 6, 7 и 8 по две, у заказов 2 и 4 по одной.

Все 8 заказов имеют хотя бы одну позицию. «Остров погибших кораблей» не заказывали ни разу, позиции для этой книги нет.

## Считаем заказы

```sql run expect=rows:1
select count(*) from orders;
```

Одна строка, в ней 8. Запомни это число. Столько заказов в таблице.

## Соединяем с позициями

```sql run expect=rows:15
select o.order_id, i.book_id
from orders o
join order_item i using (order_id)
order by o.order_id, i.book_id;
```

15 строк. Было 8 заказов, стало 15 строк. Запомни и это число.

Связь здесь **один ко многим**: у одного заказа много позиций. Соединение не склеивает позиции в одну строку, оно ставит каждую рядом с заказом. Заказ 3 появился три раза, заказ 2 один раз.

На доске строка заказа 3 расходится на три: книга 6, книга 8 и книга 9. Счётчик итога: 15 строк. Заказы без позиций потерялись бы, потому что `JOIN` внутренний, но таких в датасете нет.

## Один заказ крупным планом

```sql run expect=rows:3
select o.order_id, i.book_id, i.qty
from orders o
join order_item i using (order_id)
where o.order_id = 3
order by i.book_id;
```

3 строки: книги 6, 8 и 9, по одной штуке. Одна строка `orders` превратилась в три строки результата.

Это и есть размножение. Чем больше позиций у заказа, тем больше строк он даст в соединении.

## Сколько позиций в каждом заказе

```sql run expect=rows:8
select o.order_id, count(*) as items
from orders o
join order_item i using (order_id)
group by o.order_id
order by o.order_id;
```

8 строк, по одной на заказ. `GROUP BY` собрал размноженные строки обратно в стопки. Счётчики: у заказа 3 три позиции, у заказов 1, 5, 6, 7 и 8 по две, у 2 и 4 по одной. В сумме снова 15.

## count(*) и count(distinct)

```sql run expect=rows:1
select count(*) as joined_rows,
       count(distinct o.order_id) as orders
from orders o
join order_item i using (order_id);
```

Одна строка: `joined_rows` 15, `orders` 8.

`count(*)` считает строки после соединения. `count(distinct o.order_id)` считает уникальные заказы. Если в отчёте нужно число заказов, подходит второе. Если число позиций, первое.

## Чего нет в выдаче и почему

- ❌ «Остров погибших кораблей»: книгу не заказывали, в `order_item` для неё нет строки.
- ❌ 8 строк в соединении: уникальных заказов 8, но строк 15, потому что заказы повторяются.
- ❌ Заказы без позиций: их нет в датасете. Появился бы такой заказ, `JOIN` выбросил бы его из выдачи.
- ❌ 15 в `count(distinct o.order_id)`: эта функция считает заказы, а не строки.

## Ловушки

<Callout kind="trap">
Отчёт «сколько оплаченных заказов» через соединение считает позиции:

```sql run expect=rows:1
select count(*) from orders o
join order_item i using (order_id)
where o.status = 'paid';
```

Одна строка, в ней 9. Но оплаченных заказов 4: заказы 1, 3, 6 и 7. В них 2, 3, 2 и 2 позиции, всего 9.

`count(*)` посчитал строки после размножения. Отчёт завышен больше чем в два раза, а запрос выглядит безобидно.

Считай заказы до соединения или бери `count(distinct o.order_id)`. Если нужны и сумма по позициям, и число заказов, посчитай их отдельными запросами и не смешивай в одном `count`.
</Callout>

<Callout kind="tip">
Когда нужна сумма по позициям, работай с `order_item` напрямую: `sum(qty)`, `sum(qty * price)`. Соединение с `orders` не изменит сумму, если каждый заказ соединяется со своими позициями ровно один раз.

Опаснее соединять две таблицы, где обе стороны «многие»: строки перемножатся дважды. Тогда сначала агрегируй каждую сторону в подзапросе, потом соединяй результаты.
</Callout>

## Проверь себя

1. Сколько строк вернёт соединение для заказа 5? Посчитай позиции в датасете, потом проверь.
2. Сколько уникальных книг было заказано? Напиши `count(distinct i.book_id)` по соединению.
3. Замени `join` на `left join`. Сколько строк получится и почему столько же?

<Cheatsheet>
- Один ко многим: строка левой таблицы повторяется для каждой пары справа.
- `count(*)` после соединения считает пары, а не заказы.
- `count(distinct pk)` считает уникальные строки левой таблицы.
- `GROUP BY` по ключу левой таблицы собирает размноженные строки обратно.
- `INNER JOIN` выбрасывает левые строки без пар, `LEFT JOIN` сохраняет.
- Суммы по позициям считай на `order_item`, без лишнего соединения.
- Две связи «многие» в одном запросе перемножают строки дважды.
</Cheatsheet>
