<TlDr>GROUP BY раскладывает строки по стопкам с одинаковым значением ключа, и каждая стопка сворачивается в одну строку с агрегатом.</TlDr>

## Что есть в данных

На доске три таблицы. В <T id="public.author">author</T> 6 авторов: 4 из России, 1 из Бразилии, 1 из Франции. У Бориса Пастернака нет ни одной книги.

В <T id="public.book">book</T> 11 книг. Номер категории лежит в <C id="public.book.category_id">category_id</C>: 3 это «Фантастика», 4 «Классика», 6 «Python». У «Простого Python» категории нет, там NULL. У «Острова погибших кораблей» нет цены.

В <T id="public.orders">orders</T> 8 заказов, у каждого один из четырёх статусов в <C id="public.orders.status">status</C>.

## Агрегат по частям

В уроке 7.1 агрегат сворачивал всю таблицу в одну строку. Чтобы посчитать авторов отдельно по каждой стране, нужен **GROUP BY**:

```sql run expect=rows:3
select country, count(*) from author group by country;
```

3 строки: Россия 4, Бразилия 1, Франция 1. Каждая страна дала одну строку, а `count(*)` посчитан внутри неё.

На доске строки author сначала окрашиваются: у каждой страны свой цвет. Потом строки одного цвета съезжаются в стопку, сбоку у стопки скобка. Колонка `country` подсвечена как ключ, остальные зачёркнуты: в выдачу они не попадут. Потом каждая стопка сворачивается в одну строку, а подпись шага: «GROUP BY country: 6 строк → 3 группы». Вот и вся механика: **группа** это стопка строк с одинаковым ключом.

<Callout kind="analogy">
Сортировка писем на почте. Письма раскладывают по ячейкам, на каждой ячейке название страны. Потом про каждую ячейку пишут одну строчку в отчёт: «Россия, 4 письма». Сами письма в отчёт не попадают, только итог по ячейке.
</Callout>

## Что можно написать в SELECT

После группировки от стопки остаётся одна строка. Поэтому в `SELECT` можно ставить колонки из `GROUP BY` и агрегаты, а любую другую колонку нельзя. Проверим:

```sql run expectError=42803
select country, name from author group by country;
```

Карточка «Колонка вне GROUP BY», код `42803`. В стопке «Россия» четыре разных имени, а строка на выходе одна. Какое имя в неё поставить, Postgres не знает и выбирать наугад не будет. На доске строки снова съезжаются в стопки, `country` подсвечена, а колонка `name` краснеет.

Выхода два. Можно добавить `name` в `GROUP BY`, но тогда у каждого автора будет своя стопка из одной строки. Или свернуть имена агрегатом. Агрегат `string_agg` склеивает значения стопки в одну строку:

```sql run expect=rows:3
select country, string_agg(name, ', ') as names
from author
group by country;
```

У России в `names` четыре имени через запятую, у Бразилии и Франции по одному. На доске `name` в стопках уже не красная, а подсвечена: теперь она внутри агрегата. Подробно `string_agg` разберём в уроке 7.4.

## NULL тоже группа

Сгруппируем книги по категориям:

```sql run expect=rows:4
select category_id, count(*) from book group by category_id;
```

4 строки. У «Классики» (4) и «Фантастики» (3) по 4 книги, у «Python» (6) две. Четвёртая строка: `category_id` NULL и одна книга, «Простой Python».

В уроке 4.5 сравнение `NULL = NULL` давало UNKNOWN. В `GROUP BY` правило другое: все NULL в ключе считаются одинаковыми и падают в одну стопку. Будь в базе ещё три книги без категории, в строке NULL было бы 4.

В справочнике категорий шесть, а в выдаче три плюс NULL. Остальных трёх нет, например «Литературы по фотографии»: ни у одной книги нет такого `category_id`. Нет строк, нет и стопки. Нулей GROUP BY не показывает. Как получить строку с нулём, увидишь ниже, на авторах.

## Любой агрегат по стопкам

Внутри стопки работает любая агрегатная функция из урока 7.1. Средняя цена по категориям:

```sql run expect=rows:4
select category_id, round(avg(price), 2) as avg_price
from book
group by category_id;
```

Классика 502.50, Фантастика 593.33, Python 2800.00, книга без категории 1990.00. Python-книги дороже классики больше чем в пять раз.

В «Фантастике» 4 книги, а среднее 593.33 это 1780 / 3. «Остров погибших кораблей» лежит в той же стопке, но цены у него нет, и `avg` пропустил NULL так же, как в уроке 7.1. На доске у его строки в стопке плашка «NULL не считается».

## Каждая строка ровно в одной стопке

Заказы по статусам:

```sql run expect=rows:4
select status, count(*) from orders group by status;
```

4 строки: paid 4, new 2, shipped 1, cancelled 1. Сложи: 4 + 2 + 1 + 1 = 8, ровно столько заказов в таблице. Каждая строка попадает ровно в одну стопку. GROUP BY ничего не теряет и не удваивает.

## Книги каждого автора, включая ноль

Теперь соединим урок 6.3 с этим. Нужны все авторы и число книг у каждого, Пастернак тоже:

```sql run expect=rows:6
select a.name,
       count(*) as all_rows,
       count(b.book_id) as books
from author a
left join book b on b.author_id = a.author_id
group by a.author_id, a.name
order by books desc, a.name;
```

6 строк, у Пастернака `books` 0. Сначала LEFT JOIN дал 10 строк, из них одна у Пастернака, с NULL во всех колонках книги. Потом GROUP BY разложил эти 10 строк на 6 стопок, по одной на автора. На доске стопка Пастернака последняя и самая короткая: одна строка, в `book_id` NULL, справа плашка «NULL не считается».

Сравни две колонки. В стопке Пастернака одна строка, и `count(*)` её посчитал: `all_rows` 1. А `count(b.book_id)` пропускает NULL и даёт 0. Это ловушка из урока 6.3, только теперь в каждой стопке отдельно. Для «сколько книг у автора» бери `count` от колонки правой таблицы.

В `GROUP BY` здесь две колонки. Ключ стопки это пара значений: строки попадают в одну стопку, только если совпали обе. `author_id` отличает двух авторов с одинаковым именем, а `name` нужно, чтобы показать имя в выдаче.

Пройди главное одной сценой. Первый шаг отправь «На доску», дальше листай «Дальше»:

## Чего нет в выдаче и почему

- ❌ Имена авторов в запросе `select country, name`: `name` нет в `GROUP BY` и нет в агрегате, ошибка `42803`.
- ❌ «Литература по фотографии» и ещё две категории в книгах по категориям: ни одной книги с таким `category_id`, стопки нет.
- ❌ Цена «Острова погибших кораблей» в средней цене «Фантастики»: агрегаты пропускают NULL.
- ❌ Сами строки таблиц: каждая стопка свернулась в одну строку.

## Ловушки

<Callout kind="trap">
NULL в ключе собирает в одну стопку строки, у которых на самом деле может не быть ничего общего. Сгруппируем книги по автору:

```sql run expect=rows:6
select author_id, count(*) from book group by author_id;
```

6 строк, и в строке NULL число 2. Это «Простой Python» и «Изучаем Python», у которых автор не указан. Postgres сложил их в одну стопку, хотя у книг могут быть разные авторы, которых никто не записал. Видишь в отчёте группу NULL, подумай, что она значит на самом деле.
</Callout>

<Callout kind="tip">
Порядок групп в выдаче не обещан, как и порядок строк без `ORDER BY`. В запросе по странам Россия может оказаться и первой, и последней. Для отчёта добавляй `order by` по агрегату или по ключу, а при равных значениях второй ключ, как `order by books desc, a.name` выше.
</Callout>

## Проверь себя

1. Допиши к запросу по статусам `where customer_id = 1`. Сколько групп останется? Куда делись `new` и `cancelled`?
2. Сколько книг написали авторы каждой страны? Соедини `author` и `book` и сгруппируй по `a.country`. Сначала посчитай в уме, потом проверь.
3. Сгруппируй книги по двум колонкам: `group by author_id, category_id`. Групп станет 7, а не 6. Какая стопка из ловушки распалась на две?

<Cheatsheet>
- `group by ключ`: строки с одинаковым ключом в одну стопку, от стопки одна строка.
- В `SELECT` после `GROUP BY`: колонки из `GROUP BY` и агрегаты. Другая колонка: ошибка `42803`.
- `group by a, b`: стопка на каждую пару значений.
- NULL в ключе: все NULL в одной стопке.
- Нет строк, нет стопки. Нужен ноль: `left join` и `count(колонка правой таблицы)`.
- Порядок групп не обещан, добавляй `order by`.
</Cheatsheet>
