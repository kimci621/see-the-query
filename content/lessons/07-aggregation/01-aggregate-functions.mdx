<TlDr>Агрегатная функция берёт значения со всех строк и сворачивает их в одно: сколько, сумма, среднее, минимум, максимум. NULL она пропускает, кроме `count(*)`.</TlDr>

## Что есть в данных

На доске три таблицы. В <T id="public.book">book</T> 11 книг, цена есть у 10: у «Острова погибших кораблей» в <C id="public.book.price">price</C> NULL. В <T id="public.customer">customer</T> 6 покупателей, у Марии Ивановой нет города. В <T id="public.order_item">order_item</T> 15 позиций заказов, в <C id="public.order_item.qty">qty</C> число экземпляров: обычно 1, но иногда 2 или 3.

## Много строк, одно число

Обычная функция работает со значением одной строки: `price * 0.9` считается для каждой книги отдельно. **Агрегатная функция** собирает значения со всех строк и выдаёт одно:

```sql run expect=rows:1
select count(*) from book;
```

Одна строка, в ней 11. На доске строки book собираются в одну стопку, сканер идёт по ней сверху вниз, а счётчик рядом растёт: 1, 2, 3 и так до 11. Потом стопка схлопывается в одну строку. Чип этого шага в плеере называется по функции: `COUNT`.

Агрегат без `GROUP BY` всегда возвращает ровно одну строку, сколько бы строк ни было на входе. Даже если их ноль: об этом ниже.

<Callout kind="analogy">
Кассир закрывает смену и разбирает ящик с чеками. Сколько чеков в ящике, общая выручка, средний чек, самый маленький и самый большой. Каждый вопрос про весь ящик сразу, а ответ на него один. Если на чеке стёрлась сумма, кассир не впишет её в выручку, но среди бумажек в ящике этот чек посчитает.
</Callout>

## count(*) и count(колонка)

В уроке 4.5 ты уже видел, что `count(*)` и `count(price)` по книгам дают 11 и 10. Откуда разница, видно на покупателях:

```sql run expect=rows:1
select count(*) as all_rows,
       count(city) as with_city
from customer;
```

6 и 5. **`count(*)`** считает строки, ему всё равно, что в ячейках. **`count(колонка)`** считает строки, где в этой колонке есть значение. У Марии города нет, и `count(city)` её пропустил.

На доске у строки Марии плашка «NULL не считается», и сканер проходит её серой, счётчик `count(city)` на ней не растёт. Чип шага теперь `COUNT +1`: первая функция запроса и ещё одна.

Отсюда правило, которое пригодилось в ловушке урока 6.3: строка с NULL это всё равно строка. Нужно число строк, бери `count(*)`. Нужно число заполненных значений, бери `count(колонка)`.

## sum, avg, min, max

Сложим экземпляры во всех позициях заказов и сравним с числом позиций:

```sql run expect=rows:1
select sum(qty) as copies, count(*) as items
from order_item;
```

19 экземпляров в 15 позициях. **`sum`** складывает значения, а `count` их считает. Разница в 4 экземпляра пришла из трёх позиций, где `qty` 2 или 3.

Самая дешёвая и самая дорогая книга:

```sql run expect=rows:1
select min(price), max(price) from book;
```

350.00 и 3200.00. **`min`** и **`max`** тоже пропускают NULL: «Остров» без цены не может оказаться ни самым дешёвым, ни самым дорогим. Они работают не только с числами: `min(title)` вернёт название, которое при сортировке встанет первым, а `max(published_at)` самую свежую дату.

Теперь среднее, и рядом то, из чего оно получается:

```sql run expect=rows:1
select sum(price), count(price), avg(price)
from book;
```

11380.00, 10 и 1138.0000000000000000. **`avg`** делит сумму на число непустых цен: 11380 на 10, а не на 11. Если бы книга без цены считалась за ноль, вышло бы 1034.55. Но в среднее она не входит вовсе.

Хвост из нулей не ошибка. Для `numeric` функция `avg` возвращает `numeric` с большой точностью. Для отчёта его округляют:

```sql run expect=rows:1
select round(avg(price), 2) as avg_price
from book;
```

1138.00. `round` здесь обычная функция: она получает уже готовое среднее и округляет одно число.

## Пустое множество: NULL или ноль

Что вернут агрегаты, если на вход не пришло ни одной строки? Возьмём условие, под которое не подходит ни одна книга:

```sql run expect=rows:1
select sum(price), count(price)
from book
where price > 5000;
```

Одна строка, а не ноль строк. В `sum` NULL, в `count` 0. На доске после `WHERE` не остаётся ни одной книги, а шаг агрегата всё равно выдаёт одну строку: серая плашка NULL и 0. Документация говорит прямо: кроме `count`, агрегаты на пустом входе возвращают NULL. `avg`, `min` и `max` тоже. Ноль у `sum` означал бы «сложили и получили ноль», а складывать было нечего.

Если в отчёте нужен ноль, подставь его через COALESCE из урока 4.5:

```sql run expect=rows:1
select coalesce(sum(price), 0) as total
from book
where price > 5000;
```

0 вместо NULL.

## Агрегат и обычная колонка

Хочется увидеть самую дорогую цену и рядом название книги:

```sql run expectError=42803
select title, max(price) from book;
```

Карточка «Колонка вне GROUP BY», код `42803`. Агрегат свернул 11 строк в одну, а названий 11. Какое из них поставить рядом с максимумом, Postgres не знает и угадывать не станет. На доске колонка `title` красная.

Без `GROUP BY` в `SELECT` могут стоять только агрегаты и константы. Сам `GROUP BY` разберём в уроке 7.2: он сворачивает строки не в одну, а в одну на группу.

Пройди основные числа урока одной сценой. Первый шаг отправь «На доску», дальше листай «Дальше»:

<Scene>
<Step caption="Считаем все книги: 11">

```sql run expect=rows:1
select count(*) from book;
```

</Step>
<Step caption="Считаем книги с ценой: 10, NULL не посчитан">

```sql run expect=rows:1
select count(price) from book;
```

</Step>
<Step caption="Минимум и максимум цены: 350 и 3200">

```sql run expect=rows:1
select min(price), max(price) from book;
```

</Step>

## Чего нет в выдаче и почему

- ❌ Сами строки таблиц: агрегат свернул их в одну итоговую строку.
- ❌ «Остров погибших кораблей» в `count(price)`, `sum(price)`, `avg(price)`, `min(price)`: цены нет, а NULL агрегаты пропускают.
- ❌ Мария Иванова в `count(city)`: города нет.
- ❌ Ноль в `sum(price)` при `price > 5000`: на пустом входе `sum` возвращает NULL.

## Ловушки

<Callout kind="trap">
Агрегат нельзя писать в `WHERE`. Найдём книгу с самой высокой ценой:

```sql run expectError=42803
select title, price
from book
where price = max(price);
```

Карточка «Агрегат в WHERE», тот же код `42803`. Вспомни логический порядок из урока 4.2: `WHERE` решает, какие строки попадут в агрегат, поэтому выполняется раньше него. На шаге `WHERE` максимума ещё нет.

Самую дорогую книгу найдёт сортировка из урока 4.6. Не забудь `nulls last`, иначе первым встанет «Остров» без цены:

```sql run expect=rows:1
select title, price
from book
order by price desc nulls last
limit 1;
```

«Изучаем Python» за 3200.00.
</Callout>

<Callout kind="tip">
Сколько в колонке пустых значений, считают так: `count(*) - count(колонка)`. Это быстрая проверка данных перед отчётом. Число большое: значит, `avg` по этой колонке посчитан по малой части строк.
</Callout>

## Проверь себя

1. Сколько книг без цены покажет `select count(*) - count(price) from book`? Сначала ответь, потом проверь.
2. Что вернёт `select max(pages), min(pages) from book where price is null`? Почему два числа совпали?
3. Сколько экземпляров в заказе 1? Допиши `where order_id = 1` к запросу с `sum(qty)`.

<Cheatsheet>
- Агрегат без GROUP BY сворачивает все строки в одну.
- `count(*)`: строки. `count(колонка)`: строки, где значение не NULL.
- `sum`, `avg`, `min`, `max` пропускают NULL. `avg` делит на число непустых значений.
- `min` и `max` работают с числами, текстом и датами.
- Пустой вход: `count` даёт 0, остальные NULL. Нужен ноль: `coalesce(sum(x), 0)`.
- Округлить среднее: `round(avg(x), 2)`.
- Обычная колонка рядом с агрегатом без GROUP BY: ошибка `42803`.
- Агрегат в WHERE нельзя: WHERE выполняется раньше.
</Cheatsheet>
