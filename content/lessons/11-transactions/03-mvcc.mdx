<TlDr>MVCC хранит версии строк и показывает запросу подходящий снимок данных. Старые версии убирает VACUUM, когда они больше не нужны.</TlDr>

## Что есть в данных

В <T id="public.book">book</T> книга 1 «Тихий Дон» стоит 890,00. Изменим её цену и рассмотрим служебные сведения о версии строки. Примеры выполняй по порядку: кнопка «Применить» меняет учебную базу до сброса.

```sql run expect=rows:1
select book_id, title, price from book where book_id = 1;
```

На доске остаётся одна книга с ценой 890,00. В обычной выдаче видна подходящая запросу версия строки, а не все её старые состояния.

## Снимок и версии

**MVCC** означает управление конкурентным доступом с помощью нескольких версий данных. Каждый оператор видит снимок, определённый правилами его транзакции. Обычное чтение не ждёт изменения строки другой транзакцией и не показывает её незавершённую запись. Явные блокировки работают по отдельным правилам.

При `UPDATE` PostgreSQL создаёт новую версию изменённой строки. Старая может ещё понадобиться другому снимку, поэтому не обязана исчезнуть сразу. В следующем уроке сравним, когда разные уровни изоляции получают снимок.

<Callout kind="analogy">
В библиотечном каталоге готовят новую редакцию карточки книги. Пока она не опубликована, посетитель читает прежнюю. Старую карточку не выбрасывают, пока она нужна тем, кто уже начал с ней работать.
</Callout>

## Системные колонки

В таблице есть служебные колонки, даже если `SELECT *` их не показывает. `ctid` указывает физическое положение версии в таблице, `xmin` - транзакцию, создавшую её, а `xmax` может содержать сведения об удалении, замене или блокировке версии. Точные номера транзакций зависят от запуска.

```sql run expect=rows:1
select book_id, ctid, xmin, xmax from book where book_id = 1;
```

В результате одна строка. Запомни `ctid` и `xmin`, затем измени цену:

```sql apply expect=rows:1
update book set price = price + 10 where book_id = 1 returning title, price;
```

Кнопка «Применить» фиксирует изменение. Цена стала 900,00. Снова прочитай служебные колонки:

```sql run expect=rows:1
select book_id, ctid, xmin, xmax from book where book_id = 1;
```

Запрос возвращает видимую новую версию. Сравни её `ctid` и `xmin` с записанными раньше: при обновлении создана новая версия, поэтому её положение и транзакция создания изменились. `ctid` не годится как постоянный идентификатор книги: используй первичный ключ.

Старая версия не обязательно видна обычному запросу, даже если её место на странице ещё занято. Значение `xmax` нельзя читать как простую метку «строка удалена»: оно может относиться к незавершённой или отменённой операции либо к блокировке. ## Когда нужно освобождать место

Когда старая версия больше не нужна ни одному снимку, `VACUUM` может освободить её место для повторного использования. Обычный `VACUUM` не обещает уменьшить файл таблицы на диске. На сервере PostgreSQL эту работу обычно выполняет autovacuum; в сцене мы запускаем очистку явно.

```sql apply expect=rows:0
vacuum book;
```

Это отдельная команда: `VACUUM` нельзя запускать внутри блока транзакции. После очистки книга не исчезла:

```sql run expect=rows:1
select book_id, title, price from book where book_id = 1;
```

Видим одну строку с ценой 900,00. Очистка убирает ненужные версии, а не текущую запись книги.

## Чего нет в выдаче и почему

- ❌ Старой цены 890,00 в чтении после `UPDATE`: текущему запросу видна новая версия.
- ❌ Всей истории версий в обычном `SELECT`: он возвращает только версии, видимые его снимку.
- ❌ Постоянного номера строки в `ctid`: положение версии может измениться.

## Ловушки

<Callout kind="trap">
Ненулевой `xmax` сам по себе не доказывает, что строка удалена. Учитывай состояние транзакции и признаки блокировки. Для идентификации книги используй `book_id`, а не `ctid` или номер транзакции.
</Callout>

<Callout kind="tip">
Не держи транзакции открытыми без необходимости: старые снимки могут задерживать очистку версий. Настройки autovacuum и долгие транзакции проверяют на работающем сервере, а не по одному числу `xmax`.
</Callout>

<Cheatsheet>
- MVCC позволяет запросам читать подходящие версии строк из снимка.
- `xmin` связан с созданием версии; `xmax` нужно читать вместе с состоянием транзакции и признаками версии.
- `ctid` указывает положение версии, но не заменяет первичный ключ.
- `VACUUM` освобождает место ненужных версий для повторного использования.
</Cheatsheet>
