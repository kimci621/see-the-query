<TlDr>SAVEPOINT создаёт точку внутри транзакции. ROLLBACK TO отменяет изменения после неё и позволяет продолжить работу.</TlDr>

## Что есть в данных

В <T id="public.book">book</T> книга 3 «Судьба человека» стоит 350,00. На ней разберём частичный откат. В <T id="public.customer">customer</T> у покупателя 2 бонус равен нулю: отрицательное значение запрещено ограничением.

```sql run expect=rows:1
select title, price from book where book_id = 3;
```

На доске остаётся одна книга с ценой 350,00. Примеры ниже выполняются по порядку. Кнопка «Применить» запускает весь блок и сохраняет зафиксированные изменения в учебной базе.

## Вернуться к точке

**Точка сохранения** отмечает состояние внутри открытой транзакции. Команда `ROLLBACK TO SAVEPOINT` отменяет изменения после этой точки, но не завершает транзакцию. После отката можно выполнить новые команды и затем сделать `COMMIT`.

```sql apply expect=rows:1
begin;
savepoint s1;
update book set price = 1 where book_id = 3;
rollback to savepoint s1;
update book set price = 999 where book_id = 3;
commit;
select title, price from book where book_id = 3;
```

Последний запрос вернул цену 999,00. Цена 1 отменена откатом к `s1`; следующее изменение сделано после отката и зафиксировано. Проверь это отдельным чтением:

```sql run expect=rows:1
select title, price from book where book_id = 3;
```

На доске одна строка с ценой 999,00. Если нажать «Сброс», база вернётся к исходной цене 350,00.

<Callout kind="analogy">
Черновик договора можно сохранить перед сложной правкой. Если правка не подошла, вернись к сохранённому варианту и продолжай редактирование. Окончательно отправишь договор только после проверки всех изменений.
</Callout>

## Ошибка внутри транзакции

При пакетной загрузке одна запись может нарушить ограничение. Если до неё создана точка сохранения, приложение может обработать ошибку, откатиться к точке и продолжить с оставшимися данными. Откат убирает все изменения после точки, включая успешные, а не только неудачную команду.

В этой сцене сессия A получает ошибку ограничения, откатывается к `s1` и затем читает шесть покупателей. Сцена подготовлена заранее и не меняет учебную базу:

<TwoSessions id="savepoint" />

Теперь попробуй ошибку в песочнице:

```sql apply expectError=23514
begin;
savepoint s1;
update customer set bonus = bonus - 500 where customer_id = 2;
rollback to savepoint s1;
commit;
```

Появится ошибка `23514`: бонус не может быть отрицательным. Песочница останавливает блок на первой ошибке и откатывает открытую транзакцию; команды после ошибки в этом блоке не выполняются. Продолжение после `ROLLBACK TO` показано в сцене выше.

```sql run expect=rows:1
select customer_id, bonus from customer where customer_id = 2;
```

Вернулась одна строка с бонусом 0. Неудачное изменение не сохранилось.

## Освободить точку

`RELEASE SAVEPOINT` удаляет точку сохранения, но не фиксирует транзакцию. Изменения после точки остаются частью общей транзакции и могут быть отменены полным `ROLLBACK`:

```sql apply expect=rows:1
begin;
savepoint s1;
update book set price = 901 where book_id = 1;
release savepoint s1;
rollback;
select title, price from book where book_id = 1;
```

Цена книги 1 снова равна 890,00. `RELEASE` освободил точку, а последующий полный откат отменил изменение цены.

В транзакции может быть несколько точек. Откат к ранней точке удаляет точки, созданные позже. Сама точка отката остаётся доступной для повторного использования. Если создать несколько точек с одинаковым именем, PostgreSQL сначала обращается к самой новой; для ясности удобнее давать им разные имена.

```sql apply expectError=3B001
begin;
savepoint s1;
savepoint s2;
rollback to savepoint s1;
rollback to savepoint s2;
```

Последняя команда вызывает ошибку `3B001`: после отката к `s1` точка `s2` уже не существует. Песочница откатывает оставшуюся открытую транзакцию.

## Чего нет в выдаче и почему

- ❌ Цены 1 у книги 3: её отменил откат к `s1`.
- ❌ Отрицательного бонуса: ограничение отклонило изменение.
- ❌ Цены 901 у книги 1: `RELEASE` не заменяет `COMMIT`, а полный `ROLLBACK` отменил изменение.

## Ловушки

<Callout kind="trap">
`ROLLBACK TO` откатывает всё, что сделано после точки, даже успешные команды. Если перед ошибочной записью нужно сохранить предыдущие изменения, создай точку непосредственно перед этой записью.
</Callout>

<Callout kind="tip">
После ошибки приложение должно явно выполнить `ROLLBACK TO SAVEPOINT`, прежде чем продолжать команды в той же транзакции. Ставь точку только там, где действительно планируешь обработать ошибку и продолжить работу.
</Callout>

## Проверь себя

1. Какая цена книги 3 сохранилась после отката к `s1` и последующего `COMMIT`?
2. Что происходит с успешными изменениями, сделанными после точки сохранения, при `ROLLBACK TO`?
3. Почему после `RELEASE SAVEPOINT` полный `ROLLBACK` всё ещё отменил цену 901?

<Cheatsheet>
- `SAVEPOINT имя` создаёт точку в открытой транзакции.
- `ROLLBACK TO SAVEPOINT имя` отменяет изменения после точки, оставляя транзакцию открытой.
- `RELEASE SAVEPOINT имя` освобождает точку без фиксации транзакции.
- `COMMIT` фиксирует оставшиеся изменения; полный `ROLLBACK` отменяет транзакцию целиком.
</Cheatsheet>
