<TlDr>Top-N в группе делается в два шага: внутри группы пронумеровать строки через `row_number`, затем во внешнем запросе оставить нужные номера.</TlDr>

## Что есть в данных

В <T id="public.book">book</T> 11 книг. Категория в <C id="public.book.category_id">category_id</C> заполнена не у всех: у «Простого Python» её нет.

Книги лежат в четырёх группах: «Фантастика» (3), «Классика» (4), «Python» (6) и `NULL`. В <T id="public.book_category">book_category</T> шесть категорий, но «Литература по фотографии» (5) пустая, а у «Художественной литературы» (1) и «Литературы по программированию» (2) книги только в подкатегориях.

В «Фантастике» четыре книги. У «Острова погибших кораблей» нет цены в <C id="public.book.price">price</C>, а «Путешествие к центру Земли» и «Дети капитана Гранта» стоят по 610.00. Это ничья и NULL, на них держится весь урок.

## Нумеруем внутри категории

Сначала пронумеруем книги в каждой категории от дорогой к дешёвой:

```sql run expect=rows:11
select title, category_id, price,
  row_number() over (partition by category_id order by price desc nulls last) as rn
from book
order by category_id nulls last, price desc nulls last;
```

Вернулось 11 строк, по одной на книгу. Внутри каждой категории номера начинаются с 1.

- «Фантастика»: в этом прогоне «Дети капитана Гранта» 610 получает 1, «Путешествие к центру Земли» 610 получает 2, «Голова профессора Доуэля» 560 получает 3, «Остров погибших кораблей» без цены получает 4.
- «Классика»: «Тихий Дон» 890 получает 1, дальше 420, 350 и 350.
- «Python»: «Изучаем Python» 3200 получает 1, «Python. К вершинам мастерства» 2400 получает 2.
- `NULL`: «Простой Python» 1990 получает 1, потому что категория `NULL` это отдельная партиция.

`NULLS LAST` в окне отправил книгу без цены в конец своей партиции. Без него при сортировке по убыванию NULL оказался бы первым.

На доске book окрашивается по `category_id`, и в каждой группе идёт своя нумерация. Строки не схлопываются: все 11 книг остаются.

## Оставляем по одной на категорию

Теперь обернём запрос в подзапрос и отфильтруем:

```sql run expect=rows:4
select * from (
  select title, category_id,
    row_number() over (partition by category_id order by price desc nulls last) as rn
  from book
) t
where rn = 1
order by category_id nulls last;
```

Вернулось 4 строки:

- «Дети капитана Гранта», категория 3, 610.00;
- «Тихий Дон», категория 4, 890.00;
- «Изучаем Python», категория 6, 3200.00;
- «Простой Python», категория `NULL`, 1990.00.

Внутри подзапроса было 11 строк с номерами. Снаружи `where rn = 1` оставил по одной строке на партицию. На доске появляется временная таблица с 11 строками, затем красным гаснут все, у кого номер больше 1, и остаются четыре победителя.

`order by category_id nulls last` в самом конце сортирует строки по номеру категории, а `NULL` ставит последним. Для `ASC` NULL и так идут последними, но явное правило читается лучше и не зависит от направления сортировки.

## Почему нельзя отфильтровать сразу

Номер строки считается оконной функцией, а оконные функции выполняются после `WHERE`. Если написать `where rn = 1` в том же запросе, где объявлен `rn`, Postgres скажет, что такой колонки нет. Поэтому нужен подзапрос или CTE: внутренний запрос считает номера, внешний фильтрует.

Это тот же барьер, что в уроке 9.2, только теперь он стоит на пути к готовому паттерну Top-N.

## Книга без цены

Проверим, что делает `NULLS LAST`. Уберём его из окна:

```sql run expect=rows:4
select * from (
  select title, category_id,
    row_number() over (partition by category_id order by price desc) as rn
  from book
) t
where rn = 1
order by category_id nulls last;
```

В «Фантастике» победил «Остров погибших кораблей» без цены. По умолчанию `DESC` ставит NULL первыми, поэтому книга без цены получила номер 1 и стала «самой дорогой» в категории.

Остальные три строки не изменились. На доске у «Острова» появляется номер 1, а у книг по 610.00 номера 2 и 3.

## Чего нет в выдаче и почему

- ❌ «Литература по фотографии»: в категории 5 нет ни одной книги, партиции для неё нет.
- ❌ «Художественная литература» и «Литература по программированию»: у них нет своих книг, только подкатегории 3, 4 и 6.
- ❌ «Путешествие к центру Земли»: у него та же цена 610.00, что у «Детей капитана Гранта», а `row_number` выдал номер 1 только одной из двух книг. Выбор не гарантирован.
- ❌ «Остров погибших кораблей» в основном запросе: цены нет, `NULLS LAST` отправил его на номер 4.
- ❌ Пять строк в основном запросе: `row_number` даёт по одному первому месту на партицию. С `rank` первое место делили бы две книги.

## Ловушки

<Callout kind="trap">
`rank` вместо `row_number` ломает «по одной строке на группу»:

```sql run expect=rows:5
select * from (
  select title, category_id,
    rank() over (partition by category_id order by price desc nulls last) as rn
  from book
) t
where rn = 1
order by category_id nulls last;
```

Вернулось 5 строк: в «Фантастике» обе книги по 610.00 получили `rank = 1`. Для Top-N нужен именно `row_number`, если требуется ровно N строк. `rank` подходит, когда нужны все, кто делит место.
</Callout>

<Callout kind="trap">
Псевдоним окна не виден в `WHERE` того же запроса:

```sql run expectError=42703
select title,
  row_number() over (partition by category_id order by price desc nulls last) as rn
from book
where rn = 1;
```

Код `42703`: оконная функция ещё не посчитана на шаге `WHERE`. Оберни запрос в подзапрос, как в основном примере.
</Callout>

<Callout kind="tip">
Если ничья не должна решаться случайно, добавь в `order by` окна уникальный ключ: `order by price desc nulls last, book_id`. Тогда победитель будет одним и тем же при каждом запуске. Для «второй и следующий» меняй фильтр на `rn <= 2`.
</Callout>

## Проверь себя

1. Замени `where rn = 1` на `where rn <= 2`. Сколько строк вернётся? Посчитай по категориям, потом проверь.
2. Добавь `book_id` в конец `order by` внутри окна. Какая книга победит в «Фантастике» при цене 610.00?
3. Убери `desc` из `order by` внутри окна, оставив `nulls last`. Какая книга победит в «Фантастике»?

<Cheatsheet>
- Top-N: `row_number() over (partition by category_id order by price desc nulls last)` внутри подзапроса.
- Снаружи: `where rn = 1` для одного победителя, `where rn <= N` для нескольких.
- `row_number` даёт уникальные номера, `rank` делит место при ничьей.
- `NULLS LAST` в `order by ... desc` не даёт книге без цены стать первой.
- Псевдоним окна не виден в `WHERE`: нужен подзапрос или CTE.
- Уникальный ключ в `order by` окна делает выбор при ничьей устойчивым.
</Cheatsheet>
