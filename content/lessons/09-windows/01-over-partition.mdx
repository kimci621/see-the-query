<TlDr>`OVER()` считает агрегат для каждой строки и не убирает её из выдачи. `PARTITION BY` делит строки на группы, и окно считается внутри своей группы.</TlDr>

## Что есть в данных

В <T id="public.employee">employee</T> 8 сотрудников. В <C id="public.employee.position">position</C> шесть разных значений: директор, руководитель продаж, руководитель склада, менеджер, кладовщик и стажёр.

Зарплаты в <C id="public.employee.salary">salary</C> разные, от 40000 до 300000. У Натальи Лебедевой и Игоря Новикова по 70000: это ничья, она ещё пригодится в уроке 9.2.

## GROUP BY оставляет по одной строке на группу

Сначала посчитаем среднюю зарплату по должностям привычным способом:

```sql run expect=rows:6
select position, avg(salary) as avg_pos
from employee
group by position;
```

Вернулось 6 строк, хотя сотрудников 8. `GROUP BY` собрал строки в стопки по должности и свернул каждую стопку в одну строку. Вторая строка менеджера и вторая строка кладовщика исчезли: от них осталось только число в агрегате.

На доске строки employee съезжаются в шесть стопок, и от каждой остаётся по одной строке. Запомни число 6. Дальше оно пригодится для сравнения.

## OVER() считает, но строки не трогает

Теперь тот же средний показатель, но рядом с каждым сотрудником:

```sql run expect=rows:8
select name, salary,
  avg(salary) over () as avg_all,
  avg(salary) over (partition by position) as avg_pos
from employee
order by employee_id;
```

Вернулось 8 строк, столько же, сколько в таблице. Ни одна строка не исчезла.

`avg(salary) over ()` считает среднюю по всей таблице. У всех восьми строк в `avg_all` стоит 137500: это 1 100 000, сумма всех зарплат, делённая на 8.

`avg(salary) over (partition by position)` считает среднюю внутри должности. Значения по должностям:

- директор: 300000;
- руководитель продаж: 180000;
- руководитель склада: 160000;
- менеджер: 140000;
- кладовщик: 70000;
- стажёр: 40000.

У Алексея Морозова и Дмитрия Соколова должность одна, поэтому у обоих `avg_pos` равна 140000. При этом зарплаты у них разные, 190000 и 90000. Окно посчитало среднее по партиции и положило его в каждую строку партиции.

На доске сотрудники окрашиваются в шесть цветов по должностям. Строки остаются на месте, а справа появляются две вычисленные колонки. Подпись стадии: «ОКНО avg, avg: 8 строк, строки не схлопываются».

<Callout kind="analogy">
Представь ведомость с зарплатами. `GROUP BY` это итоговая строка внизу отдела: остаётся одно число на отдел, фамилии пропадают. `OVER (PARTITION BY position)` это пометка на полях напротив каждой фамилии: «средняя по твоему отделу такая-то». Фамилии никуда не делись, пометка повторяется у всех коллег.
</Callout>

## OVER() без PARTITION BY

Если `PARTITION BY` не указать, вся таблица становится одной партицией. Проверим на сумме:

```sql run expect=rows:8
select name, salary, sum(salary) over () as total
from employee
order by employee_id;
```

У всех восьми строк `total` равно 1100000. Это не накопление, а сумма сразу по всей таблице: `ORDER BY` внутри окна нет, значит рамка не движется по строкам.

На доске все строки получают один цвет: партиция одна.

## Как читать OVER

Выражение `over (...)` говорит Postgres две вещи:

1. Где границы окна: `partition by position` делит строки на группы по должности, без `partition by` группа одна.
2. В каком порядке считать: `order by` внутри окна включает накопление. Об этом подробно в уроке 9.4.

Оконная функция считается после `WHERE`, `GROUP BY` и `HAVING`, но до `ORDER BY` и `LIMIT`. Поэтому она видит уже отфильтрованные строки, а её результат можно сортировать обычным `ORDER BY` в конце запроса.

## Чего нет в выдаче и почему

- ❌ В `group by position` нет второй строки менеджера и второй строки кладовщика: стопки свернулись, от каждой осталась одна строка.
- ❌ В оконном запросе нет 6 строк: вернулись все 8, окно не сворачивает партицию.
- ❌ В `sum(salary) over ()` нет накопления по строкам: без `order by` окно сразу берёт всю таблицу, у всех 1100000.
- ❌ В `avg_all` нет разных значений: средняя по всей таблице одна, поэтому 137500 повторяется восемь раз.

## Ловушки

<Callout kind="trap">
`ORDER BY` внутри `OVER` меняет смысл агрегата. Без него средняя считается по всей партиции, с ним Postgres считает накопительную среднюю:

```sql run expect=rows:2
select name, position, salary,
  avg(salary) over (partition by position) as avg_pos,
  avg(salary) over (partition by position order by salary) as running_avg
from employee
where position = 'Менеджер'
order by salary;
```

У Дмитрия `avg_pos` равна 140000, а `running_avg` равна 90000: окно с `order by` на первой строке увидело только его зарплату. У Алексея обе колонки показывают 140000, потому что после второй строки в рамке обе зарплаты.

Если нужен средний по всей партиции, убери `order by` из окна. Если порядок нужен для другой функции, задай рамку явно, но об этом в уроке 9.4.
</Callout>

<Callout kind="tip">
Окно удобно, когда нужны и детали, и итог в одной строке: доля сотрудника в фонде отдела, отклонение зарплаты от средней, сравнение строки с итогом. Для одного итога на группу хватает `GROUP BY`.
</Callout>

2. Убери `partition by position` из `avg_pos`. Какое значение появится у всех восьми строк?

<Cheatsheet>
- `over ()`: вся таблица как одно окно, строки остаются.
- `over (partition by position)`: отдельное окно на каждую должность.
- `PARTITION BY` не сворачивает строки, `GROUP BY` сворачивает.
- Без `ORDER BY` внутри окна агрегат считается по всей партиции.
- `ORDER BY` внутри окна включает накопление, подробно в уроке 9.4.
- Окно считается после `WHERE` и `GROUP BY`, поэтому видит уже отфильтрованные строки.
</Cheatsheet>
