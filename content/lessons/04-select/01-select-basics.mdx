<TlDr>SELECT решает, какие колонки попадут в выдачу: готовые, вычисленные и переименованные через алиас.</TlDr>

## Что есть в данных

В <T id="public.author">author</T> 6 авторов: у каждого номер, имя, страна и год рождения. В <T id="public.book">book</T> 11 книг. В конце урока пригодятся особые строки: у «Острова погибших кораблей» нет цены, а дороже 2000 стоят только две книги.

## Звёздочка: все колонки

Начнём с самого частого запроса:

```sql run expect=rows:6
select * from author;
```

Звёздочка значит «все колонки таблицы». 6 строк, 4 колонки. На доске от <T id="public.author">author</T> отделяется призрак со всеми колонками. На шаге `SELECT` из него ничего не уходит, подпись так и скажет: 4 колонки из 4.

`SELECT *` удобен, чтобы быстро глянуть на таблицу. В коде приложения колонки лучше перечислять явно. Почему, скажу ниже.

## Список колонок

Перечислим нужные колонки через запятую:

```sql run expect=rows:6
select name, country from author;
```

Строк столько же, 6, а колонок 2. На шаге `SELECT` лишние колонки призрака зачёркиваются и бледнеют, потом уходят. Выдача стала уже. Такой отбор колонок называют **проекцией**.

Колонки в выдаче идут в том порядке, в каком ты их перечислил, а не как в таблице:

```sql run expect=rows:6
select born_year, name from author;
```

Год рождения теперь первый. Переставь колонки местами и запусти ещё раз.

## Выражения: новая колонка из старых

Вместо готовой колонки можно написать выражение. Удвоим число страниц у первых трёх книг:

```sql run expect=rows:3
select title, pages * 2 from book where book_id <= 3;
```

Строк 3. Колонка `pages` на шаге `SELECT` зачёркивается и уходит, а справа появляется новая, подсвеченная: 3008, 1796, 128. Postgres посчитал выражение для каждой строки.

Посмотри на имя новой колонки: `?column?`. У выражения нет своего имени, и Postgres подставил заглушку. Работать с такой колонкой неудобно, хочется дать ей имя.

## Алиасы

**Алиас** это имя, которое ты даёшь колонке в выдаче. Пишется после `AS`:

```sql run expect=rows:3
select title, pages * 2 as double_pages from book where book_id <= 3;
```

Те же 3008, 1796 и 128, но колонка теперь называется `double_pages`.

Выражения бывают любые: арифметика, функции, склейка строк. Посчитаем скидку 10 процентов:

```sql run expect=rows:1
select title, price, price * 0.9 as sale from book where book_id = 2;
```

Одна строка: цена 2400.00, в колонке `sale` 2160.000. Знаков после точки стало три: у цены их два, у 0.9 один, и numeric при умножении ничего не округлил.

Алиас можно дать и обычной колонке:

```sql run expect=rows:2
select title as book_title, price as price_rub from book where price > 2000;
```

Две строки, две книги дороже 2000. На шаге `SELECT` колонки `title` и `price` подсвечиваются, подпись говорит «переименовываем title → book_title, price → price_rub», и в шапке призрака появляются новые имена.

Алиас не меняет ни данные, ни таблицу. В <T id="public.book">book</T> колонка по-прежнему называется <C id="public.book.title">title</C>. Новое имя живёт только в выдаче этого запроса.

<Callout kind="analogy">
SELECT похож на кухню ресторана. Со склада приезжает целый ящик продуктов, это строка. Повар берёт из него то, что нужно для блюда (колонки), что-то режет и жарит (выражения) и подписывает тарелку названием из меню (алиас). В зал уходит тарелка, а не ящик.
</Callout>

Соберём приёмы урока в одну сцену. Первый шаг отправь «На доску», дальше листай «Дальше»:

## Чего нет в выдаче и почему

В примере с `price > 2000`:

- ❌ «Простой Python» за 1990 и ещё 7 книг: цена не больше 2000.
- ❌ «Остров погибших кораблей»: цены нет, сравнение с 2000 дало «не знаю». Почему «не знаю» не проходит фильтр, разберём в уроке 4.5.
- ❌ Колонки <C id="public.book.author_id">author_id</C>, <C id="public.book.pages">pages</C> и остальные: их нет в списке после `SELECT`.

## Ловушки

<Callout kind="trap">
Опечатка в имени колонки ломает весь запрос, а не одну строку:

```sql run expectError=42703
select titel from book;
```

Postgres отвечает `column "titel" does not exist`, код `42703`. Колонки `titel` в таблице нет, и угадывать он не станет. Карточка ошибки подскажет похожее имя, а написание всегда можно сверить с доской.
</Callout>

<Callout kind="trap">
Текст пишут в одинарных кавычках, а в двойных имена колонок. Перепутаешь, и Postgres пойдёт искать колонку:

```sql run expectError=42703
select "Тихий Дон" from book;
```

`column "Тихий Дон" does not exist`: Postgres искал колонку с таким именем. Нужен был текст `'Тихий Дон'` в одинарных кавычках.
</Callout>

<Callout kind="tip">
В коде приложения не пиши `SELECT *`. Добавят в таблицу колонку, и запрос молча начнёт возвращать больше. Список колонок фиксирует, что именно отдаёт запрос. Звёздочку оставь, чтобы быстро посмотреть на таблицу.
</Callout>

<Callout kind="tip">
Слово `AS` можно пропустить: `select title book_title from book` тоже сработает. Но с некоторыми ключевыми словами в роли алиаса, например `from` или `order`, запрос без `AS` упадёт. С `AS` подойдёт любое имя, поэтому пиши его всегда.
</Callout>

## Проверь себя

1. `select name, born_year from author` вернёт 6 строк. А сколько колонок?
2. Напиши запрос: название книги и цена со скидкой 25 процентов, алиас `sale`. Сколько строк вернётся для книг дороже 1000?
3. Что вернёт `select price as title from book where book_id = 1`? Почему колонка называется `title`?

<Cheatsheet>
- `select *`: все колонки. `select a, b`: только перечисленные, в этом порядке.
- Выражение в списке: `pages * 2`, `price * 0.9`. Новая колонка появляется справа.
- Без алиаса выражение называется `?column?`.
- Алиас: `выражение as имя`. Имя действует только в выдаче, таблица не меняется.
- Опечатка в колонке: `42703`. Текст в одинарных кавычках, в двойных имена.
</Cheatsheet>
