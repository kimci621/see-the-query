<TlDr>ORDER BY расставляет строки по ключу: ASC по возрастанию, DESC по убыванию. NULL считается больше любого значения: при ASC он внизу, при DESC наверху. Строки с равным ключом разводит второй ключ.</TlDr>

## Что есть в данных

В <T id="public.book">book</T> 11 книг, у «Острова погибших кораблей» нет цены. Две пары стоят одинаково: по 610 «Путешествие к центру Земли» (320 страниц) и «Дети капитана Гранта» (704), по 350 «Судьба человека» (64) и «Сказка о рыбаке и рыбке» (32). В <T id="public.employee">employee</T> 8 сотрудников, у кладовщиков Натальи Лебедевой и Игоря Новикова одинаковая зарплата, 70000.

## Без ORDER BY порядок не обещан

Без `ORDER BY` Postgres отдаёт строки в том порядке, в каком ему удобно. Порядок зависит от плана запроса и от того, как строки лежат на диске. Сегодня он один, после пары обновлений таблицы другой, и это не баг. Нужен порядок: попроси его явно.

## Сортировка по одной колонке

```sql run expect=rows:11
select title, price from book order by price;
```

11 строк, от дешёвых к дорогим. Направление не указано, значит, `ASC`: по возрастанию. На шаге `ORDER BY` в плеере колонка `price` сначала подсвечивается как ключ сортировки, потом строки переезжают на новые места.

Посмотри в самый низ: там «Остров погибших кораблей» с серой плашкой вместо цены. Postgres сортирует NULL так, будто он больше любой цены. Поэтому при сортировке по возрастанию книга без цены оказывается последней.

## DESC: NULL переезжает наверх

```sql run expect=rows:11
select title, price from book order by price desc;
```

`DESC` переворачивает порядок: дорогие сверху. И «Остров» теперь первый. NULL по-прежнему «больше всех», а самое большое при убывании стоит в начале. Хотел три самые дорогие книги, а первой получил книгу без цены: частый сюрприз.

## NULLS FIRST и NULLS LAST

Место NULL можно задать явно. `NULLS LAST` отправляет строки без значения в конец:

```sql run expect=rows:11
select title, price from book order by price desc nulls last;
```

Первым идёт «Изучаем Python» за 3200, «Остров» уехал вниз. Обратная команда, `NULLS FIRST`, поднимает NULL наверх и при возрастании:

```sql run expect=rows:11
select title, price from book order by price nulls first;
```

«Остров» первый, дальше книги по 350.

## Ничьи: строки с равным ключом

У «Путешествия к центру Земли» и «Детей капитана Гранта» цена одна, 610. Кто из них выше при `order by price`, Postgres не обещает. Для него эти строки равны, и он ставит их как получится. Запусти тот же запрос через месяц, и пара может поменяться местами.

Чтобы порядок стал определённым, добавь второй ключ через запятую. Пусть это будут страницы:

```sql run expect=rows:11
select title, price, pages from book order by price desc, pages;
```

Среди книг по 610 первым стоит «Путешествие к центру Земли» (320 страниц), за ним «Дети капитана Гранта» (704). Пара по 350 тоже разошлась: «Сказка о рыбаке и рыбке» (32) выше «Судьбы человека» (64). Остальные строки остались на тех же местах, что и при одном ключе. Второй ключ смотрят только там, где по первому ничья.

<Callout kind="analogy">
Школьный журнал. Ученики идут по фамилии, но в классе два Иванова. Тогда учитель смотрит на имя: Иванов Антон выше Иванова Бориса. Имя решает только спор Ивановых, Петровых и Сидоровых оно не двигает. Если бы в журнале было записано только «Иванов», кого писать первым, решал бы случай.
</Callout>

## У каждого ключа своё направление

Сотрудники по должности, а внутри должности от большой зарплаты к меньшей:

```sql run expect=rows:8
select name, position, salary from employee order by position, salary desc;
```

8 строк. Должности идут по алфавиту: «Директор», «Кладовщик», «Менеджер» и дальше. У менеджеров Алексей Морозов (190000) выше Дмитрия Соколова (90000). Кладовщики Лебедева и Новиков стоят рядом, но кто из них выше, снова не обещано: зарплата у них одинаковая, а третьего ключа нет.

`DESC` здесь относится только к `salary`. Должности отсортированы по возрастанию, потому что у `position` направление не указано. Запись `order by position, salary desc` значит `order by position asc, salary desc`, а вовсе не «всё по убыванию».

Повтори, куда уезжает NULL, одной сценой. Первый шаг отправь «На доску», дальше листай «Дальше»:

## Чего нет в выдаче и почему

Строки здесь не пропадают. В списке другое: то, чего Postgres не обещает.

- ❌ Порядок строк без `ORDER BY`: Postgres его не обещает.
- ❌ Порядок внутри ничьей при одном ключе: «Путешествие» и «Дети» по 610 могут встать в любом порядке. Задай второй ключ.
- ❌ «Остров» внизу при `DESC`: NULL больше любой цены, поэтому при убывании он наверху. Убрать его вниз можно через `NULLS LAST`.

## Ловушки

<Callout kind="trap">
Ничья на границе `LIMIT`. Пять самых дешёвых книг:

```sql run expect=rows:5
select title, price from book order by price limit 5;
```

Пятое место делят «Путешествие» и «Дети», обе по 610. В выдачу попадёт одна из них, и какая именно, не обещано. Если следующую страницу взять через `offset 5`, одна книга может показаться дважды, а другая не показаться ни разу. Страницы подробно разберём в уроке 4.7.
</Callout>

<Callout kind="tip">
Если порядок важен, последним ключом ставь то, что не повторяется, обычно первичный ключ: `order by price, pages, book_id`. Страницы тоже могут совпасть, а `book_id` у каждой книги свой. Тогда ничьих не остаётся, и одна и та же страница возвращает одни и те же строки.
</Callout>

## Проверь себя

2. Что изменится, если в примере с сотрудниками написать `order by position desc, salary`? Сначала скажи, кто будет первым, потом запусти.
3. Кого из сотрудников наняли раньше всех? Отсортируй <T id="public.employee">employee</T> по `hired_at`.

<Cheatsheet>
- `order by колонка [asc | desc]`, по умолчанию `asc`.
- NULL сортируется как самое большое значение: при `asc` он в конце, при `desc` в начале.
- `nulls first` и `nulls last` ставят NULL туда, куда скажешь.
- Несколько ключей через запятую: следующий смотрят только при ничьей по предыдущим.
- Направление у каждого ключа своё: `order by a, b desc` значит `a asc, b desc`.
- Без `order by` порядок строк не обещан. Ничья при последнем ключе тоже.
</Cheatsheet>
