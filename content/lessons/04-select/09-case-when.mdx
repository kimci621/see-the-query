<TlDr>`CASE WHEN` это `if` внутри SQL: возвращает значение по первому условию, которое оказалось TRUE, и не смотрит на остальные ветки.</TlDr>

## Что есть в данных

В <T id="public.book">book</T> 11 книг с ценами от 350 до 3200. У «Острова погибших кораблей» цены нет: NULL. В <T id="public.review">review</T> 10 отзывов с оценками от 1 до 5.

`CASE` не создаёт новых строк. Он добавляет колонку, в которой у каждой строки своё значение.

## Первая форма: ветки по условию

Разложим книги по цене на три корзины:

```sql run expect=rows:11
select title, price,
       case when price < 500 then 'дёшево'
            when price < 1000 then 'средне'
            else 'дорого' end as bucket
from book
order by bucket, title;
```

11 строк. В «дёшево» три книги по 350 и 420, в «средне» четыре книги от 560 до 890, в «дорого» четыре: 1990, 2400, 3200 и «Остров погибших кораблей» с NULL.

NULL не прошёл ни одно условие, поэтому сработал `ELSE`. Это важная деталь: `NULL < 500` даёт NULL, а не TRUE.

На доске у каждой строки на секунду вспыхивает та ветка, которая сработала, а потом появляется колонка `bucket`.

## Условия проверяются по порядку

Порядок веток решает результат. Если первое условие слишком широкое, до второго дело не дойдёт:

```sql run expect=rows:2
select case when price > 300 then 'дорого'
            when price > 1000 then 'очень дорого' end as bucket,
       count(*)
from book
group by bucket
order by bucket;
```

2 строки: `дорого` у 10 книг и NULL у «Острова»: цена NULL не прошла ни первое, ни второе условие. Ветка «очень дорого» не сработала ни разу, хотя книги дороже 1000 есть. Условие `> 300` перехватило их первым.

Поменяй ветки местами, и появятся обе категории.

<Callout kind="trap">
`CASE` не продолжает проверку после первого TRUE. Если нужны взаимоисключающие категории, ставь более узкие условия раньше, а широкие позже.
</Callout>

## CASE без ELSE

`ELSE` необязателен. Без него невыполненное условие даёт NULL:

```sql run expect=rows:2
select title,
       case when price > 1000 then 'дорого' end as bucket
from book
where book_id in (1, 2)
order by book_id;
```

2 строки. У «Тихого Дона» цена 890, условие ложное, поэтому `bucket` равен NULL. У «Python. К вершинам мастерства» 2400, и там строка `дорого`.

Если NULL в результате не нужен, добавь `ELSE`.

## CASE в ORDER BY

`CASE` можно ставить не только в `SELECT`, но и в `ORDER BY`. Например, сначала книги с ценой, потом без цены:

```sql run expect=rows:11
select title, price from book
order by case when price is null then 1 else 0 end,
         price desc nulls last;
```

11 строк. Первыми идут 10 книг с ценой по убыванию, последним «Остров погибших кораблей». На доске строки переставляются: ключ сортировки посчитан выражением, а не колонкой.

## CASE и агрегаты

`CASE` часто прячется внутри `SUM` и `COUNT`. Посчитаем книги дороже 1000:

```sql run expect=rows:1
select sum(case when price >= 1000 then 1 else 0 end) as expensive
from book;
```

Одна строка: 3. `CASE` превращает каждую подходящую книгу в 1, остальные в 0, а `SUM` складывает единицы. Это старый способ считать по условию; `FILTER` из урока 7.4 читается лучше.

Другой пример, сумма чеков по категориям:

```sql run expect=rows:4
select case when price is null then 'нет цены'
            when price < 500 then 'до 500'
            when price < 1000 then '500-999'
            else '1000+' end as bucket,
       count(*) as books
from book
group by bucket
order by bucket;
```

4 строки: «1000+» три книги, «500-999» четыре, «до 500» три, «нет цены» одна. `GROUP BY` группирует по выражению `CASE`, а не по исходной колонке.

## Типы веток должны совпадать

Все ветки `CASE` обязаны приводиться к одному типу. Строка и число несовместимы:

```sql run expectError=42804
select case when price < 500 then 'дёшево'::text else price end
from book;
```

Код `42804`: `CASE types numeric and text cannot be matched`. Если нужна строка, приведи число к тексту явно или выбери другой тип результата.

<Callout kind="tip">
Если условий больше двух и они проверяют один и тот же признак, подумай о таблице-справочнике с диапазонами. `CASE` на десять веток трудно читать и легко сломать порядком.
</Callout>

## Чего нет в выдаче и почему

- ❌ «Остров погибших кораблей» в корзине «дёшево» или «средне»: цена NULL, оба сравнения дали NULL.
- ❌ Категория «очень дорого» в примере с широким первым условием: ветка `> 300` сработала раньше.
- ❌ Непустой `bucket` у «Тихого Дона» в примере без `ELSE`: условие `price > 1000` ложное, вернулся NULL.

## Ловушки

<Callout kind="trap">
`CASE` не заменяет `WHERE`. Если нужны только дорогие книги, фильтруй строки до `SELECT`:

```sql run expect=rows:3
select title, price from book where price >= 1000 order by price;
```

3 строки: 1990, 2400 и 3200. NULL не попал. `CASE` оставил бы все 11 строк, просто у дешёвых было бы другое значение колонки.
</Callout>

<Callout kind="trap">
Порядок веток важнее кажется на первый взгляд. Проверь запрос с порогами `1000` и `500`, переставь ветки, и сравни число строк в группах. Это лучший способ увидеть, как работает первое сработавшее условие.
</Callout>

## Проверь себя

1. Сколько книг попадёт в корзину «дорого», если поменять порог `1000` на `2000`?
2. Что вернёт `case when price is null then 'нет' end` для книги 1? Проверь на доске.
3. Переставь ветки `> 300` и `> 1000` местами. Появится ли категория «очень дорого» и сколько строк в ней будет?

<Cheatsheet>
- `CASE WHEN условие THEN значение ... ELSE значение END`.
- Срабатывает первая ветка с TRUE, остальные не проверяются.
- NULL в условии не TRUE, поэтому идёт `ELSE` или NULL без `ELSE`.
- `CASE` работает в `SELECT`, `ORDER BY`, `GROUP BY` и внутри агрегатов.
- Типы всех веток должны совпадать.
- Для фильтра строк всё ещё нужен `WHERE`, а не `CASE`.
</Cheatsheet>
