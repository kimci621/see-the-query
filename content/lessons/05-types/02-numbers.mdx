<TlDr>Целое деление отбрасывает дробную часть. Для денежных сумм подходит numeric, а float хранит многие дроби приближённо.</TlDr>

## Что есть в данных

В <T id="public.book">book</T> две числовые колонки: <C id="public.book.price">price</C> numeric(10,2) и <C id="public.book.pages">pages</C> int. Цен нет у одной книги («Остров погибших кораблей»), в агрегатах она выпадает.

## Целое деление

Два целых делятся нацело. Дробная часть выбрасывается, без округления:

```sql run expect=rows:1
select 7 / 2 as int_div, 7::numeric / 2 as exact_div;
```

Один и тот же запрос, два ответа: `3` и `3.5000000000000000`. Когда один операнд имеет тип numeric, дробная часть сохраняется. Для дробей вроде одной трети результат всё равно придётся округлить. Это ловушка номер один: `pages / 100` для «средней толщины» даст 0 для тонких книг:

```sql run expect=rows:1
select pages, pages::numeric / 100 as hundreds from book where book_id = 3;
```

«Судьба человека»: 64 страницы и `0.64` сотни. Без `::numeric` было бы `0`.

## numeric: точные деньги

Тип numeric точно хранит десятичные значения в пределах заданной точности. Например, цена `890.00` не получает двоичной погрешности при хранении. Для операций с бесконечной дробной частью и для колонки с заданным масштабом может понадобиться округление.

```sql run expect=rows:1
select sum(price) as total, avg(price) as middle from book;
```

Сумма известных цен: `11380.00`, средняя `1138.0000000000000000`. Обрати внимание: `avg` считает по 10 книгам, книга без цены не участвует. `count(*)` сказал бы 11.

## Округление

Для numeric при округлении половина уходит от нуля:

```sql run expect=rows:1
select round(2.5) as r25, round(3.5) as r35;
```

Получились 3 и 4. Для отрицательного числа половина тоже уходит от нуля: `round(-2.5)` даёт -3. Для float правило зависит от платформы, часто половина округляется к чётному. Округление до двух знаков для numeric записывают как `round(x, 2)`.

## float: приблизительное хранение

Дробные с плавающей точкой хранятся как двоичная дробь. Некоторые десятичные дроби в двоичной системе бесконечны, и получается вот это:

```sql run expect=rows:1
select (0.1::float8 + 0.2::float8) as float_sum, (0.1::float8 + 0.2::float8)::numeric as cast_sum;
```

`float_sum` показывает `0.30000000000000004`: не все десятичные дроби точно представимы в двоичном формате. Приведённый `cast_sum` показывает `0.3`, но приведение уже вычисленного результата не возвращает потерянную точность. Для денежной суммы исходные значения лучше сразу хранить и считать как numeric.

```sql run expect=rows:1
select price::float8 as approx_price from book where book_id = 1;
```

На экране `890`: тип float не сохраняет количество десятичных знаков исходной записи. Само целое число 890 представимо точно, но не каждая десятичная дробь представима так же.

## Переполнение

int это 32 бита: максимум 2147483647. Сумма страниц маленькой таблицы не переполнится, а вот счётчик событий в нагруженной системе может:

```sql run expectError=22003
select 2147483647 + 1;
```

`22003 numeric_value_out_of_range`. Для больших счётчиков есть bigint (8 байт), для identifier в больших таблицах его и берут.

## Деньги считаются в numeric

Посчитаем выручку заказа 1: количество умножить на цену, всё в numeric:

```sql run expect=rows:1
select sum(qty * price) as revenue from order_item where order_id = 1;
```

`1730.00`: один «Тихий Дон» за 890 и две «Капитанские дочки» по 420. На доске `SUM` собирает обе строки заказа в одну сумму.

## Чего нет в выдаче и почему

- ❌ Книга без цены в `sum` и `avg`: NULL выпадает из агрегатов (кроме `count(*)`).
- ❌ «0.64 сотни страниц» без `::numeric`: целое деление съело дробную часть.
- ❌ `0.1 + 0.2 = 0.3` во float: равенство ложное, сравнивай с допуском или в numeric.

## Ловушки

<Callout kind="trap">
Деление в середине выражения может потерять дробную часть раньше, чем выполнится умножение:

```sql run expect=rows:1
select 13 / 10 * 10 as int_result, 13::numeric / 10 * 10 as numeric_result;
```

Первый результат `10`, второй `13.0000000000000000`. Если дробная часть нужна дальше, приведи операнд до деления.
</Callout>

<Callout kind="tip">
Для денег используй numeric с подходящей точностью и масштабом или целое число минимальных денежных единиц. Для float выбирай допустимую погрешность исходя из задачи. Диапазон счётчика проверяй до выбора int или bigint.
</Callout>

## Проверь себя

1. Сколько вернёт `select 5 / 2 * 2`? А `select 5::numeric / 2 * 2`?
2. Почему `avg(price)` по 11 книгам посчитан по 10?
3. Какой тип выбрать для поля «скидка в процентах с двумя знаками»?

<Cheatsheet>
- int / int → целое (дробная часть отбрасывается к нулю). numeric сохраняет дробную часть с доступной точностью.
- numeric: деньги и всё, что должно сойтись до копейки.
- float4/float8: приблизительное хранение, `0.1 + 0.2 != 0.3`.
- Переполнение int: `22003`. Большие счётчики: bigint.
- NULL выпадает из sum/avg.
</Cheatsheet>
