<TlDr>Полнотекстовый поиск сравнивает нормализованные лексемы текста и запроса. Конфигурация определяет разбор слов, а GIN может ускорить поиск.</TlDr>

## Что есть в данных

В <T id="public.review">review</T> десять отзывов о книгах. Посмотрим, как PostgreSQL разбирает текст первого отзыва:

```sql run expect=rows:1
select to_tsvector('russian', 'Великий роман о донском казачестве. Читается на одном дыхании.') as vector;
```

В результате одна строка типа `tsvector`. Нажми на подчёркнутую ячейку, чтобы увидеть значение целиком. Вектор содержит семь лексем и их позиции; например, `велик` соответствует слову «Великий», а предлог «о» отсутствует как стоп-слово.

Сцена использует тот же PostgreSQL: переключи шаги от исходного текста до вектора. Парсер может выделять перекрывающиеся токены, а словарь решает, какие лексемы оставить.

## Запрос по лексемам

`plainto_tsquery` преобразует обычный текст запроса в поисковые лексемы. Оператор `@@` проверяет соответствие вектору. Найдём отзывы со словом «фантастика»:

```sql run expect=rows:2
select book_id, rating from review
where to_tsvector('russian', body) @@ plainto_tsquery('russian', 'фантастика')
order by book_id;
```

Получились два отзыва: о книгах 6 и 8. Поиск сравнивает лексемы по правилам выбранной конфигурации. Это не понимание смысла текста и не универсальный поиск синонимов или опечаток.

<Callout kind="analogy">
В предметном указателе разные формы слова могут вести к одной записи. Вектор похож на такой указатель с позициями в документе, а поисковый запрос ищет подходящие записи указателя.
</Callout>

## Храним вектор и добавляем индекс

Создадим вычисляемую колонку для текста отзыва:

```sql apply expect=rows:0
alter table review add column body_tsv tsvector
  generated always as (to_tsvector('russian', body)) stored;
```

Нажми «Применить». PostgreSQL вычисляет сохранённый вектор при записи строки. Добавим GIN-индекс:

```sql apply expect=rows:0
create index review_body_tsv_idx on review using gin (body_tsv);
```

Теперь найдём отзывы, в которых поисковому запросу соответствуют обе лексемы:

```sql run expect=rows:1
select book_id, rating from review
where body_tsv @@ plainto_tsquery('russian', 'книга python')
order by book_id;
```

Один отзыв о книге 2 с оценкой 5. `plainto_tsquery` соединяет распознанные слова условием «и»; порядок слов в таком запросе не обязан совпадать с порядком в тексте. Индекс может помочь на больших данных, но на десяти строках планировщик вправе выбрать последовательное чтение.

## Ранжирование

`ts_rank` вычисляет оценку соответствия вектора запросу. Посмотрим три отзыва с наибольшей оценкой:

```sql run expect=rows:3
select book_id, round(ts_rank(body_tsv, plainto_tsquery('russian', 'книга python'))::numeric, 4) as rank
from review order by rank desc, book_id, review_id limit 3;
```

Первая строка относится к книге 2 и имеет оценку 0,0985 в этом примере; следующие строки с нулём включены потому, что запрос не отфильтровал несовпадения через `@@`. Оценка нужна для сравнения результатов выбранной формулы, а не для измерения «процента смысла».

## Вектор обновляется при изменении текста

Заменим текст отзыва 2:

```sql apply expect=rows:1
update review set body = 'Учимся писать запросы.' where review_id = 2;
```

После применения сохранённый вектор этой строки пересчитан. Повторим поиск:

```sql run expect=rows:0
select book_id, rating from review
where body_tsv @@ plainto_tsquery('russian', 'книга python')
order by book_id;
```

Совпадений больше нет. «Сброс» восстановит исходные отзывы и удалит учебную колонку с индексом.

## Слова и подстроки

`LIKE` и `ILIKE` ищут по шаблону символов; полнотекстовый поиск работает с лексемами и учитывает настройки словаря. Для поиска части слова или сходных строк может подойти `pg_trgm`, который мы использовали в уроке типов индексов. Выбор зависит от того, что именно должен находить пользователь.

## Чего нет в выдаче и почему

- ❌ Предлога «о» в векторе: словарь распознал его как стоп-слово.
- ❌ Отзыва после замены его текста: новый вектор больше не соответствует двум поисковым лексемам.
- ❌ Гарантии использования GIN на маленькой таблице: планировщик выбирает способ чтения по оценкам.

## Ловушки

<Callout kind="trap">
Разные конфигурации могут давать разные лексемы. Согласуй конфигурацию документа, запроса и индекса; не считай стемминг поиском синонимов или исправлением опечаток.
</Callout>

<Callout kind="tip">
Проверяй поиск на реальных текстах и ожидаемых запросах. Индекс требует места и работы при записи, поэтому сравни планы и измерения на подходящем объёме данных.
</Callout>

<Cheatsheet>
- `to_tsvector` создаёт вектор лексем и позиций по выбранной конфигурации.
- `plainto_tsquery` разбирает обычный текст запроса; `@@` проверяет совпадение.
- Сохранённая генерируемая колонка обновляется при записи строки; GIN может ускорить поиск.
- `ts_rank` даёт оценку для сортировки, а не гарантию смыслового сходства.
</Cheatsheet>
