# Итоги спайков Ф0

Дата: 2026-10-08. Машина: MacBook (Apple Silicon, экран 120 Гц), macOS, Node 26.2.0, Chromium из Playwright 1.64.0.
Код спайков: `spikes/`, сырые цифры: `spikes/results/*.json`. Код одноразовый, в продукт не переносится.

## Версии (зафиксированы)

`@electric-sql/pglite` 0.5.8 (PostgreSQL 18.3), `libpg-query` 18.1.5, `pgsql-deparser` 18.3.10, `@xyflow/react` 12.12.0, `motion` 14.0.0, `vite` 8.3.3, `@vitejs/plugin-react` 6.1.2, `react` 19.3.0, `@playwright/test` 1.64.0, pnpm 10.34.6.

## БД (PGlite)

- **Старт.** Node: старт + датасет bookstore 625 мс. Браузер, свой worker: `new PGlite()` 636 мс, датасет 47 мс.
- **Ассеты.** `pglite.wasm` 9.9 МБ (3.5 МБ gzip), `pglite.data` 6.1 МБ, `initdb.wasm` 0.4 МБ. Это главный вес приложения: в Ф13 нужны долгий HTTP-кэш и предзагрузка.
- **Снапшоты.** `dumpDataDir('gzip')` = весь каталог данных, поэтому даже bookstore весит 4.6 МБ. Dump 204-250 мс, загрузка из dump 140-151 мс. На 100k строк: 8.9 МБ, dump 452 мс, load 266 мс.
- **ctid в JOIN.** INNER 9 строк; LEFT 11, у двух книг без автора ctid автора = NULL; FULL 12 (1 автор без книг, 2 книги без автора). Изменения в других таблицах внутри транзакции ctid не трогают. Lineage по ctid подтверждён.
- **TEMP TABLE** внутри `BEGIN ... ROLLBACK` работает, ctid у её строк свои (`(0,1)`...), после отката таблицы нет.
- **SAVEPOINT.** Ошибка под `SAVEPOINT` + `ROLLBACK TO` не ломает транзакцию, следующий запрос выполняется.
- **statement_timeout НЕ работает.** `SET LOCAL statement_timeout = '500ms'` принимается, но `pg_sleep(3)` и `count(*) from generate_series(1, 5e7)` отрабатывают до конца. Единственная защита: сторож клиента. Проверено в браузере: таймаут 3 с сработал за 3003 мс, `terminate()`, новый worker из dump поднялся за 151 мс, данные целы (`count(*) from book` = 11).
- **xmin/xmax.** UPDATE переносит строку: `(0,1)` → `(0,12)`, новая версия получает `xmin` = текущий txid и `xmax` = 0. Ловушка для урока MVCC: до UPDATE у строк book `xmax` уже ненулевой (= xmin загрузки), потому что проверки FK при вставке order_item ставят блокировку `FOR KEY SHARE`. Ненулевой `xmax` не значит «строка удалена».
- **Расширения и роли.** `pg_trgm` работает (`similarity('Пушкин', 'Пушкинн')` = 0.67). `CREATE ROLE`, `GRANT SELECT`, `SET ROLE`: под ролью `select` работает, `insert` даёт `42501`.
- **Поля ошибок.** `42703`: `position` '8' (строка, 1-based символ). `23502`: `table`, `column`. `23503`, `23505`, `23514`: `constraint`, `table`, `detail`. Имена ограничений стандартные: `customer_email_key`, `orders_customer_id_fkey`, `customer_bonus_check`.

## Парсер и депарсер

- **libpg-query в браузере:** загрузка WASM 10-19 мс, разбор короткого запроса 0.06-0.1 мс. Вес `libpg-query.wasm` 1.7 МБ (345 КБ gzip).
- **Позиции в байтах UTF-8** подтверждены: в `select 'Привет' as x, b.title from book b` колонка `b.title` на байте 28 = символе 22.
- **Загрузка WASM под Vite требует обхода.** Emscripten в собранном бандле запрашивает `/libpg-query.wasm` от корня сайта, а Vite файл не выпускает. В dev без пребандла у `libpg-query.js` нет default-экспорта. Рабочий конфиг (`spikes/vite.config.ts`): плагин кладёт `libpg-query.wasm` в корень сборки (`emitFile`) и отдаёт его в dev через middleware; `optimizeDeps.exclude` только для `@electric-sql/pglite`, `libpg-query` пребандлится.
- **Круговой тест депарсера: 49/50.** Единственная потеря смысла: `FETCH FIRST n ROWS WITH TIES` превращается в `LIMIT n` (`limitOption` теряется). При сравнении деревьев кроме `location`, `stmt_location`, `stmt_len` надо отбрасывать `rexpr_list_start` и `rexpr_list_end` (новые в PG18 у `IN (...)`).

## Доска и оверлей

- 30 таблиц по 15 строк, `onlyRenderVisibleElements`, 200 строк с `layoutId` перемешиваются каждые 600 мс.
- fps без действий 120, при pan во время анимации 120. С замедлением CPU ×4: 120 и 119. Бюджет ≥55 fps выполнен с запасом.
- `ViewportPortal`: прямоугольник призрака совпадает с нодой после pan, zoom колесом и `setViewport({ zoom: 1.37 })`, расхождение 0 px. Условие: у ноды `box-sizing: border-box` (иначе рамка добавляет 2 px к ширине и расхождение растёт с зумом). В продукте это даёт Tailwind preflight.
- Анимация оверлея за 3 с не вызвала ни одной перерисовки `TableNode`. Pan вызывает несколько (3), потому что ноды входят в видимую область.
- `onlyRenderVisibleElements` выгружает ноды вне кадра: оверлей не должен искать DOM ноды, координаты берутся из модели доски (`nodeRect` в контрактах, раздел 10), а не из `getBoundingClientRect`.

## Решения и правки

1. `statement_timeout` в PGlite не работает → превью без таймаута, защита только сторожем. Поправлены спека (5.4, 5.13), контракты (раздел 1 и `Sandbox.preview`), трекер (P2.6).
2. Обход загрузки `libpg-query.wasm` под Vite → контракты, раздел 1. Применяется в Ф4 (парсер в браузере), Ф2 не затрагивает.
3. `WITH TIES` теряется депарсером → трассировщик не строит стадию limit с `LIMIT_OPTION_WITH_TIES` через депарсер (склейка текста по позициям или `final-only`). Контракты, раздел 1; план Ф5 получил факт.
4. Вес снапшота 4.6-9 МБ → кэш снапшотов по датасетам в памяти допустим: датасетов 4, в худшем случае ~30 МБ. Отдельных мер не нужно.
5. Отклонений по доске и оверлею нет.
