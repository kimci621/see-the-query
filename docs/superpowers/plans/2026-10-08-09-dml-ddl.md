# Ф9 DML и DDL: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Научить трассировщик и оверлей операторам изменения данных и структуры (INSERT, INSERT ... SELECT, UPDATE, DELETE, UPDATE ... FROM, DELETE ... USING, каскады, ON CONFLICT, MERGE, TRUNCATE, DDL), обновлять базовую доску после «Применить» одним коммитом состояния, расширить словарь ошибок до ~40 SQLSTATE и написать уроки глав 1-3 (кроме 1.1).

**Architecture:** DML трассируется **одним настоящим прогоном** оператора с расширенным `RETURNING old.ctid, new.ctid, old.*, new.* [, merge_action()]` (PostgreSQL 18). Пара «до/после» берётся прямо из `old`/`new`, без сопоставления по PK. Всё, что нужно увидеть до оператора (вердикты WHERE, исходные строки INSERT, конфликтующие строки ON CONFLICT, снимки каскадных таблиц), снимается пробами под SAVEPOINT до прогона. DDL трассируется снимком каталога (`introspect` + список ограничений из `pg_constraint`) до и после прогона, переименования берутся из AST. Эффект оператора остаётся в транзакции превью (SAVEPOINT освобождается), её откатывает `sandbox.preview`. Аниматоры `dml`, `ddl` и отскок от ограничения строят кадры только из данных стадии и `ctx.schema`.

**Tech Stack:** TypeScript strict, `@electric-sql/pglite@0.5.8` (PostgreSQL 18.3), `libpg-query@18.1.5`, `pgsql-deparser@18.3.10`, zustand 5, vitest 5, MDX. Новых зависимостей нет.

**Spec:** `docs/superpowers/specs/2026-10-08-visual-sql-design.md`: 3.9 (превью и «Применить»), 4 (каталог анимаций, разделы DML и DDL), 5.6 (трассировщик, DML и DDL), 5.7 (модель Trace), 5.14 (ошибки), 6.2 (датасеты), 6.3 (главы 1-3). Контракты: `docs/superpowers/plans/2026-10-08-00-contracts.md`.

## Предусловия: правки контрактов

Этот план опирается на правки контрактов, которые координатор вносит отдельным коммитом `docs(contracts): ...` до задачи 3. Код задач уже написан под них.

1. `features/tracer/types.ts`, стадия `error`: два необязательных поля `attempted?: Relation` (строки, которые оператор пытался записать) и `conflictKeys?: RowKey[]` (существующие строки, с которыми столкнулась запись или новое ограничение).
2. Стадия `dml`: необязательное поле `defaulted?: string[]` (колонки, которые заполнила база: DEFAULT, identity). Соглашение по `output`: все строки целевой таблицы до оператора (у изменённых уже новые значения), удалённые строки остаются в `output` (их ключи в `deleted`), вставленные идут в конце. `mergeBranches` ключуется ключами строк целевой таблицы (старый ctid для UPDATE/DELETE, новый для INSERT), значение `'skipped'` не используется.
3. `Sandbox.preview`: после `ROLLBACK` восстанавливает последовательности (`setval` к снимку, снятому до `BEGIN`).
4. `traceStatement`: TCL (`BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`) в превью не выполняется, трасса `final-only` с причиной. Эффект DML и DDL остаётся в транзакции превью до её отката.
5. `features/db/types.ts`: код `SANDBOX_OPEN_TRANSACTION = 'VS003'`. `Sandbox.apply`: если после текста транзакция осталась открытой (BEGIN без COMMIT/ROLLBACK) или прервана ошибкой, песочница делает `ROLLBACK`; в первом случае бросает `VS003`, в журнал текст не попадает.

## Global Constraints

- Только контракты. Планы Ф5-Ф8 пишутся параллельно, поэтому внутренние функции Ф5 (кроме `rowKeyOf`, `traceStatement`, типов) не используются. SAVEPOINT для Ф9 даёт своя функция `attempt` в `dml/shared.ts`.
- Все SQL-факты плана проверены на PGlite 0.5.8 (PostgreSQL 18.3) 2026-10-08 в scratchpad. Факты Ф0 (`docs/spikes.md`): UPDATE переносит строку (`(0,1)` → `(0,12)`), у строк `book` `xmax` ненулевой ещё до UPDATE из-за FOR KEY SHARE, поэтому «вставлена ли строка» определяем по `old.ctid is null`, а не по `xmax = 0`.
- PostgreSQL 18: `RETURNING old.*, new.*` работает для INSERT, UPDATE, DELETE, INSERT ... ON CONFLICT и MERGE; `merge_action()` в RETURNING MERGE; `old.ctid`, `new.ctid` отдаются строкой `'(0,4)'`. Узел `merge_action()` в AST: `{ MergeSupportFunc: { msftype: 25 } }` (через `FuncCall` депарсер ставит кавычки и Postgres отвечает 42883).
- У PG18 NOT NULL хранится в `pg_constraint` с `contype = 'n'` (у таблицы `customer` 5 таких ограничений из 11).
- Последовательности не откатываются: каждый INSERT в превью сжигал бы номер. Превью возвращает счётчики после отката, «Применить» (`apply`) не возвращает: дырка после настоящего `ROLLBACK` остаётся, это материал урока 2.5.
- Ошибки ограничений (Ф0): у `23502` есть `table` и `column`, нет `constraint`; у `23503`, `23505`, `23514` есть `constraint`, `table`, `detail`. Имена: `customer_email_key`, `orders_customer_id_fkey`, `customer_bonus_check`, `book_author_id_fkey`.
- Значения из PGlite: `numeric` строкой (`'890.00'`), `bigint` и `int` числом, `date`/`timestamptz` объектом `Date`, `jsonb` объектом, `text[]` массивом.
- Подписи стадий на русском: `«<КЛАУЗ>: <что произошло>, <было> → <стало>»`.
- Тексты плана и уроков без длинных тире. Комментарии в коде на русском.
- Каждая задача заканчивается обновлением `docs/PROGRESS.md` и коммитом `<type>(<area>): <описание>` с последней строкой ``. Пункт P9.1 закрывает координатор, этот план его не трогает.

- [ ] **Step 3: Реализовать `sequences.ts`**

```ts
// src/features/db/sequences.ts
import type { DbClient } from './types';

// Последовательности живут вне транзакций: nextval в превью не откатывается ROLLBACK'ом.
// Снимок до BEGIN и setval после ROLLBACK возвращают счётчики на место.
export type SequenceSnapshot = string;

const SNAPSHOT_SQL = `select coalesce(jsonb_agg(jsonb_build_object(
  'schema', schemaname, 'name', sequencename,
  'value', coalesce(last_value, start_value), 'called', last_value is not null)), '[]')
from pg_sequences`;

const RESTORE_SQL = `select count(setval(format('%I.%I', s->>'schema', s->>'name')::regclass,
  (s->>'value')::bigint, (s->>'called')::boolean))
from jsonb_array_elements($1::jsonb) s`;

export async function snapshotSequences(db: DbClient): Promise<SequenceSnapshot> {
  const r = await db.query(SNAPSHOT_SQL);
  return JSON.stringify(r.rows[0]?.[0] ?? []);
}

export async function restoreSequences(db: DbClient, snap: SequenceSnapshot): Promise<void> {
  await db.query(RESTORE_SQL, [snap]);
}
```

В методе `preview` (форма из плана Ф2, задача про песочницу) снять снимок перед `BEGIN` и восстановить сразу после `ROLLBACK`. Остальная логика (сторож, проверка `xactId`, пересборка после COMMIT) не меняется, добавляются две строки. Итоговая форма:

```ts
    preview: (fn, signal) =>
      exclusive(async () => {
        signal?.throwIfAborted();
        const client = live();
        const sequences = await snapshotSequences(client);
        await client.query('begin');
        const started = await xactId(client);
        const outcome = await fn(client).then(
          (value) => ({ ok: true as const, value }),
          (error: unknown) => ({ ok: false as const, error }),
        );
        if (!outcome.ok && isDeath(outcome.error)) throw outcome.error;
        const now = await xactId(client);
        await client.query('rollback');
        // nextval не откатывается: возвращаем счётчики, иначе каждый символ в редакторе сжигает номер
        await restoreSequences(client, sequences);
        // внутри превью выполнился COMMIT: база изменилась, возвращаем состояние журнала
        if (now !== null && now !== started) await changeTo(journal);
        if (!outcome.ok) throw outcome.error;
        return outcome.value;
      }),
```

Если клиент умер по таймауту, до `restoreSequences` дело не доходит: новый клиент поднимется из снапшота, где счётчики верные.

import { type DbClient, DbException } from './types';

// SAVEPOINT вне транзакции даёт 25P01, в прерванной 25P02, в открытой проходит.
// Так узнаём, что текст «Применить» оставил транзакцию, и откатываем её.
export async function closeDanglingTransaction(db: DbClient): Promise<'idle' | 'open' | 'aborted'> {
  let state: 'open' | 'aborted';
  try {
    await db.query('savepoint __vs_probe');
    state = 'open';
  } catch (e) {
    if (!(e instanceof DbException)) throw e;
    if (e.db.code === '25P01') return 'idle';
    if (e.db.code !== '25P02') throw e;
    state = 'aborted';
  }
  await db.query('rollback');
  return state;
}

// Трасса одного оператора на текущем состоянии базы (схема снимается заново)
export async function traceSql(db: DbClient, sql: string): Promise<Trace> {
  await initParser();
  const parsed = parseSql(sql);
  if (!parsed.ok) throw new Error(parsed.error.message);
  return traceStatement(parsed.statements[0], db, { schema: await introspect(db) });

export function stageOf<K extends Stage['kind']>(trace: Trace, kind: K): Extract<Stage, { kind: K }> {
  const stage = trace.stages.find((s) => s.kind === kind);
  if (!stage) throw new Error(`нет стадии ${kind}: ${trace.stages.map((s) => s.kind).join(', ')}`);
  return stage as Extract<Stage, { kind: K }>;
}

// src/features/tracer/dml/shared.ts
import { type DbClient, type DbError, DbException, type QueryResult } from '@/features/db/types';
import { deparse } from '@/features/sql/deparse';
import type { ParsedStatement } from '@/features/sql/types';
import type { Node } from '@pgsql/types';
import { rowKeyOf } from '../rowkey';
import type { Column, Relation, Row, RowKey, Stage, Trace } from '../types';

// Узлы AST libpg-query 18, с которыми работает Ф9 (форма проверена в scratchpad)
export interface RangeVarNode { schemaname?: string; relname: string; alias?: { aliasname: string } }
export interface DmlNode {
  relation: RangeVarNode;
  cols?: Array<{ ResTarget: { name: string } }>;
  selectStmt?: Node;
  onConflictClause?: { action: string; infer?: { indexElems?: Array<{ IndexElem: { name?: string } }>; conname?: string } };
  whereClause?: Node;
  fromClause?: Node[];
  usingClause?: Node[];
  returningClause?: { options?: unknown[]; exprs?: unknown[] };
}
export interface Target { tableId: string; schema: string; name: string; alias: string; sql: string; columns: Column[] }

export const qident = (name: string) => `"${name.replaceAll('"', '""')}"`;
export const keyOf = (alias: string, ctid: string): RowKey => rowKeyOf({ [alias]: ctid }, [alias]);
export const row = (alias: string, ctid: string, values: unknown[]): Row => ({ key: keyOf(alias, ctid), lineage: { [alias]: ctid }, values });
export const sameValue = (a: unknown, b: unknown) => JSON.stringify(a) === JSON.stringify(b);

let savepoints = 0;
// fn под SAVEPOINT. keep = true: изменения остаются в транзакции превью, следующий оператор их увидит
export async function attempt<T>(db: DbClient, fn: () => Promise<T>, keep: boolean): Promise<{ ok: true; value: T } | { ok: false; error: DbError }> {
  const sp = `__vs_dml_${++savepoints}`;
  await db.query(`savepoint ${sp}`);
  try {
    const value = await fn();
    await db.query(keep ? `release savepoint ${sp}` : `rollback to savepoint ${sp}`);
    return { ok: true, value };
  } catch (e) {
    // VS001 / VS002: worker уже мёртв, откатывать нечего
    if (!(e instanceof DbException) || e.db.code.startsWith('VS')) throw e;
    await db.query(`rollback to savepoint ${sp}`);
    return { ok: false, error: e.db };
  }
}

export async function resolveTarget(db: DbClient, rv: RangeVarNode): Promise<Target | null> {
  const name = rv.schemaname ? `${qident(rv.schemaname)}.${qident(rv.relname)}` : qident(rv.relname);
  const found = await db.query(
    'select n.nspname::text, c.relname::text from pg_class c join pg_namespace n on n.oid = c.relnamespace where c.oid = to_regclass($1)',
    [name],
  );
  if (found.rows.length === 0) return null;
  const [schema, relname] = found.rows[0] as [string, string];
  const sql = `${qident(schema)}.${qident(relname)}`;
  const cols = await db.query(
    'select attname::text, format_type(atttypid, atttypmod) from pg_attribute where attrelid = $1::regclass and attnum > 0 and not attisdropped order by attnum',
    [sql],
  );
  const alias = rv.alias?.aliasname ?? relname;
  return {
    tableId: `${schema}.${relname}`, schema, name: relname, alias, sql,
    columns: cols.rows.map(([n, t]) => ({ name: n as string, type: t as string, source: { alias, column: n as string } })),
  };
}

export async function snapshot(db: DbClient, t: Pick<Target, 'sql' | 'alias' | 'columns'>, maxRows: number): Promise<Relation> {
  const r = await db.query(`select ctid::text, * from ${t.sql} order by ctid limit ${maxRows}`);
  return { columns: t.columns, rows: r.rows.map(([ctid, ...values]) => row(t.alias, ctid as string, values)) };
}

const colRef = (...fields: string[]) => ({ ColumnRef: { fields: fields.map((f) => (f === '*' ? { A_Star: {} } : { String: { sval: f } })) } });
const resTarget = (val: unknown, name?: string) => ({ ResTarget: name ? { name, val } : { val } });

// Один настоящий прогон: RETURNING old.ctid, new.ctid, old.*, new.* [, merge_action()], затем RETURNING пользователя.
// ponytail: если пользователь переименовал old/new через RETURNING WITH (OLD AS o), прогон упадёт с ошибкой; редкий случай
export function instrument(ast: Node, nodeName: string): string {
  const copy = structuredClone(ast) as unknown as Record<string, DmlNode>;
  const body = copy[nodeName];
  const extra: unknown[] = [
    resTarget(colRef('old', 'ctid'), '__vs_old_ctid'),
    resTarget(colRef('new', 'ctid'), '__vs_new_ctid'),
    resTarget(colRef('old', '*')),
    resTarget(colRef('new', '*')),
  ];
  // merge_action() в AST = MergeSupportFunc (msftype 25 = text); через FuncCall депарсер берёт имя в кавычки
  if (nodeName === 'MergeStmt') extra.push(resTarget({ MergeSupportFunc: { msftype: 25 } }, '__vs_action'));
  body.returningClause = { ...body.returningClause, exprs: [...extra, ...(body.returningClause?.exprs ?? [])] };
  return deparse(copy as unknown as Node);
}

// Эталон для панели результата: только RETURNING пользователя, без наших колонок
export function userResult(r: QueryResult, prefix: number): QueryResult {
  const fields = r.fields.slice(prefix);
  return { fields, rows: fields.length ? r.rows.map((x) => x.slice(prefix)) : [], command: r.command, rowCount: r.rows.length };
}

export function makeTrace(
  stmt: ParsedStatement,
  started: number,
  parts: Pick<Trace, 'stages' | 'result' | 'error' | 'touched'> & Partial<Pick<Trace, 'mode' | 'fallbackReason'>>,
): Trace {
  return { sql: stmt.text, statementType: stmt.kind, mode: 'full', notices: [], timingMs: performance.now() - started, ...parts };
}

const CONSTRAINT_SQL = `select n.nspname || '.' || r.relname,
  array(select a.attname::text from unnest(c.conkey) with ordinality k(attnum, ord)
        join pg_attribute a on a.attrelid = c.conrelid and a.attnum = k.attnum order by k.ord),
  case when c.confrelid = 0 then null else fn.nspname || '.' || fr.relname end
from pg_constraint c
join pg_class r on r.oid = c.conrelid join pg_namespace n on n.oid = r.relnamespace
left join pg_class fr on fr.oid = c.confrelid left join pg_namespace fn on fn.oid = fr.relnamespace
where c.conname = $1 and r.relname = $2 and n.nspname = $3`;

export async function constraintInfo(db: DbClient, name: string, table: string, schema: string): Promise<{ tableId: string; columns: string[]; refTableId: string | null } | null> {
  const r = await db.query(CONSTRAINT_SQL, [name, table, schema]);
  const hit = r.rows[0] as [string, string[], string | null] | undefined;
  return hit ? { tableId: hit[0], columns: hit[1], refTableId: hit[2] } : null;
}

// Стадия ошибки: что подсветить. У 23502 нет constraint, только table + column (Ф0)
export async function errorStage(db: DbClient, error: DbError, target: Target | null, extra: { attempted?: Relation; conflictKeys?: RowKey[] } = {}): Promise<Stage> {
  const tableIds = new Set<string>(target ? [target.tableId] : []);
  const columns = new Set<string>();
  const schema = error.schema ?? target?.schema ?? 'public';
  if (error.table) tableIds.add(`${schema}.${error.table}`);
  if (error.table && error.column) columns.add(`${schema}.${error.table}.${error.column}`);
  if (error.constraint && error.table) {
    const info = await constraintInfo(db, error.constraint, error.table, schema);
    if (info) {
      for (const c of info.columns) columns.add(`${info.tableId}.${c}`);
      if (info.refTableId) tableIds.add(info.refTableId);
    }
  }
  return {
    id: 'error', kind: 'error', caption: `Ошибка ${error.code}: ${error.message}`,
    output: { columns: [], rows: [] }, error, focus: { tableIds: [...tableIds], columns: [...columns] }, ...extra,
  };
}

// Имена колонок, упомянутых в выражении (для подсветки предиката)
export function columnNames(node: unknown): string[] {
  const out = new Set<string>();
  const walk = (n: unknown): void => {
    if (Array.isArray(n)) return n.forEach(walk);
    if (!n || typeof n !== 'object') return;
    const ref = (n as { ColumnRef?: { fields: Array<{ String?: { sval: string } }> } }).ColumnRef;
    if (ref) {
      const last = ref.fields.at(-1)?.String?.sval;
      if (last) out.add(last);
      return;
    }
    Object.values(n).forEach(walk);
  };
  walk(node);
  return [...out];
}

// src/features/tracer/dml/source.ts
import type { DbClient, DbError } from '@/features/db/types';
import { deparse } from '@/features/sql/deparse';
import type { Node } from '@pgsql/types';
import type { Relation, RowKey } from '../types';
import { type DmlNode, type Target, attempt, constraintInfo, keyOf, qident } from './shared';

export function insertColumns(body: DmlNode, target: Target): string[] {
  return body.cols?.length ? body.cols.map((c) => c.ResTarget.name) : target.columns.map((c) => c.name);
}

// Исходные строки INSERT (VALUES или SELECT), вычисленные отдельно, до вставки
export async function sourceRelation(db: DbClient, body: DmlNode, target: Target): Promise<Relation | undefined> {
  if (!body.selectStmt) return undefined; // DEFAULT VALUES
  const run = await attempt(db, () => db.query(`select * from (${deparse(body.selectStmt as Node)}) as __vs_src`), false);
  // ponytail: VALUES (DEFAULT) отдельно не вычисляется, попытку тогда не показываем
  if (!run.ok) return undefined;
  const names = insertColumns(body, target).slice(0, run.value.fields.length);
  return {
    columns: names.map((name) => ({ name, type: target.columns.find((c) => c.name === name)?.type ?? 'unknown' })),
    rows: run.value.rows.map((values, i) => ({ key: `src:${i}`, lineage: {}, values })),
  };
}

// Существующие строки цели, совпавшие с исходными строками по колонкам keyCols
export async function collidingKeys(db: DbClient, body: DmlNode, target: Target, keyCols: string[]): Promise<RowKey[]> {
  const cols = insertColumns(body, target);
  if (!body.selectStmt || keyCols.length === 0 || !keyCols.every((c) => cols.includes(c))) return [];
  const list = keyCols.map(qident).join(', ');
  const sql = `select t.ctid::text from ${target.sql} as t
    where (${keyCols.map((c) => `t.${qident(c)}`).join(', ')}) in
      (select ${list} from (${deparse(body.selectStmt)}) as s(${cols.map(qident).join(', ')}))`;
  const run = await attempt(db, () => db.query(sql), false);
  return run.ok ? run.value.rows.map(([ctid]) => keyOf(target.alias, ctid as string)) : [];
}

// Что показать при ошибке INSERT: попытку и (для 23505) строку, об которую она споткнулась
export async function insertErrorExtras(db: DbClient, body: DmlNode, target: Target, error: DbError): Promise<{ attempted?: Relation; conflictKeys?: RowKey[] }> {
  const attempted = await sourceRelation(db, body, target);
  const out: { attempted?: Relation; conflictKeys?: RowKey[] } = attempted ? { attempted } : {};
  if (error.code !== '23505' || !error.constraint) return out;
  const info = await constraintInfo(db, error.constraint, target.name, target.schema);
  const keys = info ? await collidingKeys(db, body, target, info.columns) : [];
  return keys.length ? { ...out, conflictKeys: keys } : out;
}

// src/features/tracer/dml/trace-dml.ts
import type { DbClient } from '@/features/db/types';
import type { ParsedStatement } from '@/features/sql/types';
import type { TraceFn } from '../route';
import type { TraceOptions } from '../trace';
import type { Row, RowKey, Stage, Trace } from '../types';
import { type DmlNode, attempt, errorStage, instrument, keyOf, makeTrace, resolveTarget, row, sameValue, snapshot, userResult } from './shared';
import { insertColumns, insertErrorExtras } from './source';

type Op = 'insert' | 'update' | 'delete' | 'merge';
type DmlStage = Extract<Stage, { kind: 'dml' }>;
const OPS: Record<string, Op> = { InsertStmt: 'insert', UpdateStmt: 'update', DeleteStmt: 'delete', MergeStmt: 'merge' };
const BRANCH = { INSERT: 'not_matched_insert', UPDATE: 'matched_update', DELETE: 'matched_delete' } as const;

function dmlCaption(op: Op, s: { inserted: number; updated: number; deleted: number; before: number }): string {
  if (op === 'insert') {
    const upd = s.updated ? `, обновлено при конфликте ${s.updated}` : '';
    return `INSERT: вставлено строк ${s.inserted}${upd}, ${s.before} → ${s.before + s.inserted}`;
  }
  if (op === 'update') return `UPDATE: изменено строк ${s.updated} из ${s.before}`;
  if (op === 'delete') return `DELETE: удалено строк ${s.deleted}, ${s.before} → ${s.before - s.deleted}`;
  return `MERGE: вставлено ${s.inserted}, изменено ${s.updated}, удалено ${s.deleted}`;
}

// INSERT / UPDATE / DELETE / MERGE: один настоящий прогон с RETURNING old/new (PG18).
// Стадии и пары «до/после» строятся из его строк и из снимков, снятых до него.
export async function traceDml(stmt: ParsedStatement, db: DbClient, opts: TraceOptions, traceSelect: TraceFn): Promise<Trace> {
  const started = performance.now();
  const nodeName = Object.keys(stmt.ast)[0];
  const op = OPS[nodeName];
  const body = (stmt.ast as unknown as Record<string, DmlNode>)[nodeName];
  const maxRows = opts.maxRows ?? 2000;
  const target = await resolveTarget(db, body.relation);
  if (!target) {
    // таблицы нет: пусть Postgres сам объяснит (42P01)
    const run = await attempt(db, () => db.query(stmt.text), true);
    const touched = { tableIds: [], columns: [] };
    if (run.ok) return makeTrace(stmt, started, { mode: 'final-only', fallbackReason: 'Целевая таблица не найдена в каталоге', stages: [], result: run.value, error: null, touched });
    return makeTrace(stmt, started, { stages: [await errorStage(db, run.error, null)], result: null, error: run.error, touched });
  }

  const stages: Stage[] = [];
  const before = await snapshot(db, target, maxRows);
  if (op !== 'insert') {
    stages.push({ id: `scan:${target.alias}`, kind: 'scan', alias: target.alias, tableId: target.tableId, caption: `FROM: таблица ${target.name}, строк ${before.rows.length}`, output: before });
  }

  const touched = { tableIds: [target.tableId], columns: [] as string[] };
  const run = await attempt(db, () => db.query(instrument(stmt.ast, nodeName)), true);
  if (!run.ok) {
    const extra = op === 'insert' ? await insertErrorExtras(db, body, target, run.error) : {};
    stages.push(await errorStage(db, run.error, target, extra));
    return makeTrace(stmt, started, { stages, result: null, error: run.error, touched });
  }

  const n = target.columns.length;
  const prefix = 2 + 2 * n + (op === 'merge' ? 1 : 0);
  const byKey = new Map(before.rows.map((r) => [r.key, r]));
  const inserted: RowKey[] = [];
  const deleted: RowKey[] = [];
  const updated: DmlStage['updated'] = [];
  const mergeBranches: DmlStage['mergeBranches'] = {};
  const added: Row[] = [];
  for (const r of run.value.rows) {
    const oldCtid = r[0] as string | null;
    const newCtid = r[1] as string | null;
    const oldValues = r.slice(2, 2 + n);
    const newValues = r.slice(2 + n, 2 + 2 * n);
    let key: RowKey;
    if (oldCtid !== null && newCtid !== null) {
      // UPDATE переносит строку на новый ctid (Ф0): ключ по старому, чтобы совпасть со строкой на доске
      key = keyOf(target.alias, oldCtid);
      const changedColumns = target.columns.filter((_, i) => !sameValue(oldValues[i], newValues[i])).map((c) => c.name);
      updated.push({ key, before: oldValues, after: newValues, changedColumns });
      byKey.set(key, row(target.alias, oldCtid, newValues));
    } else if (newCtid !== null) {
      const fresh = row(target.alias, newCtid, newValues);
      key = fresh.key;
      inserted.push(key);
      added.push(fresh);
    } else {
      key = keyOf(target.alias, oldCtid as string);
      deleted.push(key);
      // удалённая строка остаётся в output: аниматору нужны её значения, ключ уже в deleted
      if (!byKey.has(key)) byKey.set(key, row(target.alias, oldCtid as string, oldValues));
    }
    if (op === 'merge') mergeBranches[key] = BRANCH[r[2 + 2 * n] as keyof typeof BRANCH];
  }

  const defaulted = op === 'insert' && body.cols?.length
    ? target.columns.map((c) => c.name).filter((c) => !insertColumns(body, target).includes(c))
    : [];
  const dml: DmlStage = {
    id: `dml:${target.alias}`, kind: 'dml', op, tableId: target.tableId,
    inserted, deleted, updated, conflicts: [], mergeBranches, cascades: [],
    caption: dmlCaption(op, { inserted: inserted.length, updated: updated.length, deleted: deleted.length, before: before.rows.length }),
    output: { columns: target.columns, rows: [...byKey.values(), ...added] },
    sourceRange: { from: stmt.from, to: stmt.to },
    ...(defaulted.length ? { defaulted } : {}),
  };
  stages.push(dml);
  touched.columns = [...new Set(updated.flatMap((u) => u.changedColumns))].map((c) => `${target.tableId}.${c}`);
  return makeTrace(stmt, started, { stages, result: userResult(run.value, prefix), error: null, touched });
}

### Task 17: L1.3 Первичный и внешний ключ

- Тезисы: PK - личный номер строки, UNIQUE + NOT NULL; FK - ссылка «кто чей», VALUES на доске: FK-ребро, наведение на `book.author_id` в тексте подсвечивает связанные строки (мост T/C, P8.5). ### Task 18: L1.4 DDL, DML, DCL, TCL

- Тезисы: карта команд: DDL меняет схему (create/alter/drop), DML - данные (insert/update/delete/merge), DCL - права (grant/revoke, вне песочницы), TCL - транзакции (begin/commit/rollback). Таблица-памятка в Cheatsheet. Блоки: `select title from book limit 1` (DQL рядом); `begin` в превью → трасса final-only с объяснением (задача 3) - «транзакциями управляет превью». ### Task 21: L2.2a Генерируемые колонки

### Task 22: L2.3 NOT NULL, UNIQUE, CHECK, DEFAULT

- Блоки: вставка без name → 23502 (отскок, подсветка колонки); дубль email → 23505; `check (bonus >= 0)` → 23514 с `conflictKeys`; DEFAULT: `insert into customer (name, email, created_at) values ('...', '...', now())` - bonus 0 с бейджем default. Сцены: отскоки от каждого ограничения (аниматор constraint-error).

### Task 23: L2.4 PK, FK, ON DELETE

- Блоки: `delete from orders where order_id = 1` - CASCADE уносит 2 позиции (волна каскада); FK без действия → 23503 (RESTRICT); `on delete set null` на тестовой таблице - строки остаются, колонка NULL. Три ветки одной сцены.

### Task 24: L2.5 Identity vs serial, последовательности

- Тезисы: `generated always as identity` vs `serial` (serial - исторический, из последовательности); дырки после ROLLBACK. Блоки: `insert into author (name) values ('X')` в превью трижды → после «Применить» следующий id не 7, а 9... нет: превью восстанавливает счётчики (задача 2), а «Применить» настоящего ROLLBACK юзера - дырка. Показать: превью не сжигает, а `begin; insert; rollback;` - сжигает. `select nextval(...)`/`currval` - кратко. Ловушка: дырки - это нормально.

### Task 25: L2.6 ALTER TABLE

- Блоки: `add column` (выезд колонки, NULL у строк), `drop column`, `rename column`, `alter column type` (переделка значений), `add constraint` с конфликтом (урок 22-сцена). Сцены аниматора DDL.

### Task 26: L2.7 DROP, TRUNCATE, CASCADE

- Блоки: `truncate review` (мгновенно, контраст с delete); `drop table <тестовая>`; `drop table ... cascade` - волна на зависимые (NOTICE в сообщениях). Ловушка: cascade удаляет то, о чём не подумал.

### Task 27: L2.8 COMMENT ON

- Блоки: `comment on table book is 'Каталог книг магазина'`; чтение: `select obj_description('book'::regclass)`. Сцена: подпись у таблицы (не пустой diff, notices). Краткий урок.

### Task 28: L3.1 INSERT (датасет bookstore)

### Task 29: L3.2 RETURNING

- Блоки: `insert ... returning author_id` (7); `update ... returning old.price, new.price` (PG18); `delete ... returning *`. Тезисы: RETURNING - «отпечаток» операции: панель результата + подсветка строк на доске. Сцена: строки «отпечатываются».

### Task 30: L3.3 UPDATE, UPDATE ... FROM

- Блоки: `update book set price = price * 0.9 where price > 800` (4 строки, flip ячеек); без WHERE (все 11 - ловушка, предупреждение); `update ... from author` (1 строка). Тезисы: WHERE сначала, потом изменения; новая версия строки (MVCC - тизер главы 11).

### Task 31: L3.4 DELETE, DELETE ... USING, vs TRUNCATE

- Блоки: `delete from review where rating < 4` (2, перечёркивание); `delete ... using book` (по категории); `truncate` рядом - сравнение трёх сцен. Тезис: WHERE не остановить на полпути; TRUNCATE - вся таблица.

### Task 32: L3.5 INSERT ... ON CONFLICT

- Блоки: DO NOTHING (отскок от anna@example.com); DO UPDATE с `excluded` (бонус 320); выбор ключа конфликта `on conflict (email)`. Тезисы: upsert = «вставь, а если занято - ...»; partial index conflict - тизер. Сцены столкновения.

### Task 33: L3.6 MERGE

- Блоки: тест из задачи 9 (1 updated + 1 inserted); ветки MATCHED/NOT MATCHED; `when matched ... delete`. Тезисы: MERGE = «синхронизация по ключу», сравнение с ON CONFLICT (по строке vs по источнику). Сцена веток.
