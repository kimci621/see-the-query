# Ф9 DML и DDL: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> Редакция 2026-10-21: план сверен с кодом Ф2-Ф8 и переписан. Снята задача про последовательности в превью (сделана в P2.16) и задача про открытую транзакцию в «Применить» (авто-COMMIT остаётся). Задачи перенумерованы, добавлены счётчик последовательности (задача 12) и компонент вложенных рамок (задача 16).

**Goal:** Научить трассировщик и оверлей операторам изменения данных и структуры (INSERT, INSERT ... SELECT, UPDATE, DELETE, UPDATE ... FROM, DELETE ... USING, каскады, ON CONFLICT, MERGE, TRUNCATE, DDL), расширить словарь ошибок до ~30 SQLSTATE и написать уроки глав 1-3 (кроме 1.1).

**Architecture:** DML трассируется **одним настоящим прогоном** оператора с расширенным `RETURNING old.ctid, new.ctid, old.*, new.* [, merge_action()]` (PostgreSQL 18). Пара «до/после» берётся прямо из `old`/`new`, ключ строки по старому ctid, таблицы без PK отдельного случая не требуют (спека 5.6, правка согласована 2026-10-21). Всё, что нужно увидеть до оператора (строки цели, вердикты WHERE, исходные строки INSERT, конфликтующие строки, снимки каскадных таблиц), снимается пробами Ф5 (`createProber`, под SAVEPOINT) до прогона. Вердикты WHERE у UPDATE и DELETE считают шаги Ф5 `scanStep`, `joinStep`, `filterStep` над синтетическим SelectStmt. DDL трассируется diff-ом снимков каталога: до = `opts.schema`, после = `introspect` внутри транзакции превью; переименования берутся из AST. Эффект оператора остаётся в транзакции превью, её откатывает `sandbox.preview`. Аниматоры `dml`, `ddl` и отскок от ограничения строят кадры только из данных стадии и `ctx.schema`.

**Tech Stack:** TypeScript strict, `@electric-sql/pglite@0.5.8` (PostgreSQL 18.3), `libpg-query@18.1.5`, `pgsql-deparser@18.3.10`, zustand 5, vitest 5, MDX. Новых зависимостей нет.

**Spec:** `docs/superpowers/specs/2026-10-08-visual-sql-design.md`: 3.9 (превью и «Применить»), 4 (каталог анимаций, разделы DML и DDL), 5.6 (трассировщик, DML и DDL), 5.7 (модель Trace), 5.14 (ошибки), 6.2 (датасеты), 6.3 (главы 1-3). Контракты: `docs/superpowers/plans/2026-10-08-00-contracts.md`.

### Правки контрактов (координатор, отдельный коммит `docs(contracts): ...` до задачи 2)

1. Стадия `error`: рядом с существующим `group?` два необязательных поля `attempted?: Relation` (строки, которые оператор пытался записать) и `conflictKeys?: RowKey[]` (существующие строки, с которыми столкнулась запись или новое ограничение). Остальные поля не трогать.
2. Стадия `dml`: необязательные `defaulted?: string[]` (колонки, которые заполнила база: DEFAULT, identity, генерируемые) и `sequences?: Array<{ column: string; before: number | null; after: number | null }>` (счётчики identity и serial до и после прогона, задача 12). Соглашение по `output`: все строки целевой таблицы до оператора (у изменённых уже новые значения), удалённые остаются в `output` (их ключи в `deleted`), вставленные идут в конце. `mergeBranches` ключуется строками целевой таблицы (старый ctid для UPDATE/DELETE, новый для INSERT); `'skipped'` остаётся в типе, но не используется.
3. Стадия `filter`: необязательный признак `target?: true`. Стоит у WHERE оператора UPDATE и DELETE: аниматор приглушает строки с false и UNKNOWN и оставляет их на месте.
4. `TableInfo` (Ф2): поле `constraints: Array<{ name: string; kind: 'p' | 'u' | 'f' | 'c'; columns: string[] }>`. NOT NULL туда не входит, его даёт `ColumnInfo.nullable`.
5. Оверлей: `GhostRow.cellMarks?: Record<number, 'changed' | 'default'>` (жёлтая ячейка переворота UPDATE и бейдж `default` у INSERT).
6. MDX-компоненты уроков: `<Nesting>` (задача 16).

## Global Constraints

- Внутренние функции Ф5 переиспользуются, своих дублей не пишем:
  - `createProber`, `Prober.run`, `Prober.rows`, `ProbeOverflow`, `TraceFallback`, `ident`, `sqlOf`, `typeNames` (`tracer/probe.ts`); SAVEPOINT даёт `prober.run` через `withSavepoint`, своих точек сохранения нет;
  - `findTable`, `walk`, `hasVolatile`, `touchedOf` (`tracer/whitelist.ts`);
  - `createSelectCtx`, `stageId`, `rangeOf` (`tracer/select/context.ts`), `scanStep`, `joinStep`, `filterStep`, `flattenFrom`;
  - `captions` (`tracer/captions.ts`), `rowsWord`/`plural` (`src/lib/plural.ts`), `rowKeyOf`;
  - в тестах `traceSql`, `stageOf`, `summary`, `column` (`tests/helpers/trace.ts`), `withDataset`, `inPreview` (`tests/helpers/db.ts`).
- Соглашения трассы как в `trace.ts`: id стадии `${stages.length}:<kind>`, `timingMs` округлён, трасса с ошибкой `mode: 'final-only'` с `fallbackReason: 'Запрос завершился ошибкой'`, подпись ошибки `captions.error(code, message)`. Общие поля трассы (`sql`, `touched`, `notices`, `timingMs`) ставит `finish` из `trace.ts`, трассировщики Ф9 их не собирают.
- Правило одного прогона. До прогона оператора трассировщик Ф9 может отказаться (вернуть `null` или строку-причину), и тогда `trace.ts` выполнит оператор сам. После прогона отказаться так нельзя: оператор выполнился бы второй раз. Любой отказ после прогона это своя трасса `final-only` с `result` из прогона.
- Таблица больше лимита проб (`ProbeOverflow`) → `final-only` с причиной, сжатого режима для DML нет.
- Все SQL-факты плана проверены на PGlite 0.5.8 (PostgreSQL 18.3). Факты Ф0 (`docs/spikes.md`): UPDATE переносит строку (`(0,1)` → `(0,12)`), у строк `book` `xmax` ненулевой ещё до UPDATE из-за FOR KEY SHARE, поэтому «вставлена ли строка» определяем по `old.ctid is null`, а не по `xmax = 0`.
- PostgreSQL 18: `RETURNING old.*, new.*` работает для INSERT, UPDATE, DELETE, INSERT ... ON CONFLICT и MERGE; `merge_action()` в RETURNING MERGE; `old.ctid`, `new.ctid` отдаются строкой `'(0,4)'`. Узел `merge_action()` в AST: `{ MergeSupportFunc: { msftype: 25 } }` (через `FuncCall` депарсер ставит кавычки и Postgres отвечает 42883).
- У PG18 NOT NULL хранится в `pg_constraint` с `contype = 'n'` (у таблицы `customer` их 6). `introspect` такие ограничения отсекает, NOT NULL берём из `ColumnInfo.nullable`.
- Последовательности: превью возвращает счётчики после отката (P2.16), «Применить» не возвращает: дырка после упавшего INSERT остаётся, это материал урока 2.5.
- Ошибки ограничений (Ф0): у `23502` есть `table` и `column`, нет `constraint`; у `23503`, `23505`, `23514` есть `constraint`, `table`, `detail`. Имена: `customer_email_key`, `orders_customer_id_fkey`, `customer_bonus_check`, `book_author_id_fkey`. FK `book.author_id` без действия, то есть `NO ACTION` (23503); `RESTRICT` дал бы `23001`. В bookstore `ON DELETE CASCADE` есть только у `order_item`, `SET NULL` нет ни одного.
- Временная таблица: у `pg_class` схема `pg_temp_N`, в приложении `pg_temp` (`introspect.ts:62`). Таблицу ищем через `findTable`, схему ошибки нормализуем так же.
- Вид оператора: `kindOf` (`sql/parser.ts:64`) отдаёт `TruncateStmt` как `'ddl'`, `IndexStmt` и `ViewStmt` как `'other'`. Маршрут Ф9 строим по имени узла AST, не по `stmt.kind`.
- `useLiveTrace` затирает `touched` трассировщика редакторским (`editor/useLiveTrace.ts:131`). Подсветку и раскрытие колонок даёт `editor/touched.ts`, его и расширяем (задача 4).
- Подписи стадий на русском: `«<КЛАУЗ>: <что произошло>, <было> → <стало>»`, числа через `rowsWord`, все тексты в `captions.ts`.
- Значения из PGlite: `numeric` строкой (`'890.00'`), `bigint` и `int` числом, `date`/`timestamptz` объектом `Date`, `jsonb` объектом, `text[]` массивом.
- Изменение трассировщика = unit-тест на стадию + golden-сверка: каждая задача 2-10 дописывает 1-3 запроса в `GOLDEN_F9` (`tests/tracer/golden.queries.ts`, подключается в задаче 2).
- Тексты плана и уроков без длинных тире. Комментарии в коде на русском.

```ts
// src/features/tracer/dml/shared.ts
import type { Node } from '@pgsql/types';
import type { SchemaSnapshot, TableInfo } from '@/features/db/introspect';
import { type DbError, DbException, type QueryResult } from '@/features/db/types';
import { ident, type Prober, sqlOf } from '../probe';
import { rowKeyOf } from '../rowkey';
import type { Column, Relation, Row, RowKey } from '../types';
import { findTable } from '../whitelist';

// Узлы AST libpg-query 18, с которыми работает Ф9 (форма проверена в scratchpad)
export interface RangeVarNode {
  schemaname?: string;
  relname: string;
  alias?: { aliasname: string };
}
export interface DmlNode {
  relation: RangeVarNode;
  cols?: Array<{ ResTarget: { name: string } }>;
  selectStmt?: Node;
  onConflictClause?: { action: string; infer?: { indexElems?: Array<{ IndexElem: { name?: string } }>; conname?: string } };
  whereClause?: Node;
  fromClause?: Node[];
  usingClause?: Node[];
  withClause?: unknown;
  returningClause?: { options?: unknown[]; exprs?: unknown[] };
}
export interface Target {
  table: TableInfo;
  alias: string;
  sql: string; // "schema"."name" для проб
  columns: Column[];
}

export const keyOf = (alias: string, ctid: string): RowKey => rowKeyOf({ [alias]: ctid }, [alias]);
export const row = (alias: string, ctid: string, values: unknown[]): Row => ({
  key: keyOf(alias, ctid),
  lineage: { [alias]: ctid },
  values,
});
export const sameValue = (a: unknown, b: unknown) => JSON.stringify(a) === JSON.stringify(b);

// Проба, ошибка которой часть трассы (ограничение): DbException → { ok: false }. SAVEPOINT даёт prober.run
export async function tryRun(
  prober: Prober,
  sql: string,
): Promise<{ ok: true; value: QueryResult } | { ok: false; error: DbError }> {
  try {
    return { ok: true, value: await prober.run(sql) };
  } catch (e) {
    // VS001 / VS002: worker уже мёртв, это не ошибка запроса
    if (!(e instanceof DbException) || e.db.code.startsWith('VS')) throw e;
    return { ok: false, error: e.db };
  }
}

// Целевая таблица из снапшота доски: временные как pg_temp, представления не трассируем
export function resolveTarget(schema: SchemaSnapshot, rv: RangeVarNode): Target | null {
  const table = findTable(schema, rv.schemaname, rv.relname);
  if (!table || (table.kind !== 'table' && table.kind !== 'temp')) return null;
  const alias = rv.alias?.aliasname ?? table.name;
  return {
    table,
    alias,
    sql: `${ident(table.schema)}.${ident(table.name)}`,
    columns: table.columns.map((c) => ({ name: c.name, type: c.type, source: { alias, column: c.name } })),
  };
}

// Все строки цели по ctid. Больше maxRows → ProbeOverflow, трасса уходит в final-only
export async function snapshot(prober: Prober, t: Target): Promise<Relation> {
  const a = ident(t.alias);
  // алиас обязателен: без него order by ctid сортирует текстовый ctid (introspect.ts)
  const r = await prober.rows(`SELECT ${a}.ctid::text, ${a}.* FROM ${t.sql} AS ${a} ORDER BY ${a}.ctid`);
  return { columns: t.columns, rows: r.rows.map(([ctid, ...values]) => row(t.alias, ctid as string, values)) };
}

const colRef = (...fields: string[]) => ({
  ColumnRef: { fields: fields.map((f) => (f === '*' ? { A_Star: {} } : { String: { sval: f } })) },
});
const resTarget = (val: unknown, name?: string) => ({ ResTarget: name ? { name, val } : { val } });

// Один настоящий прогон: RETURNING old.ctid, new.ctid, old.*, new.* [, merge_action()], затем RETURNING пользователя.
// ponytail: RETURNING WITH (OLD AS o) у пользователя ломает old.* в прогоне; редкий случай, тогда ошибка Postgres
export function instrument(ast: Node, nodeName: string): string {
  const copy = structuredClone(ast) as unknown as Record<string, DmlNode>;
  const body = copy[nodeName];
  const extra: unknown[] = [
    resTarget(colRef('old', 'ctid'), '__vs_old_ctid'),
    resTarget(colRef('new', 'ctid'), '__vs_new_ctid'),
    resTarget(colRef('old', '*')),
    resTarget(colRef('new', '*')),
  ];
  // merge_action() в AST = MergeSupportFunc (msftype 25 = text); через FuncCall депарсер берёт имя в кавычки
  if (nodeName === 'MergeStmt') extra.push(resTarget({ MergeSupportFunc: { msftype: 25 } }, '__vs_action'));
  body.returningClause = { ...body.returningClause, exprs: [...extra, ...(body.returningClause?.exprs ?? [])] };
  return sqlOf(copy as unknown as Node);
}

// Эталон для панели результата: только RETURNING пользователя, без наших колонок
export function userResult(r: QueryResult, prefix: number): QueryResult {
  const fields = r.fields.slice(prefix);
  return {
    fields,
    rows: fields.length ? r.rows.map((x) => x.slice(prefix)) : [],
    command: r.command,
    rowCount: r.rows.length,
  };
}

// Что подсветить при ошибке: цель, таблица ошибки, колонки ограничения, таблица по ту сторону FK.
// У 23502 нет constraint, только table + column (Ф0)
export function errorFocus(
  error: DbError,
  target: Target,
  schema: SchemaSnapshot,
): { tableIds: string[]; columns: string[] } {
  const tableIds = new Set([target.table.id]);
  const columns = new Set<string>();
  const errSchema = error.schema?.startsWith('pg_temp_') ? 'pg_temp' : error.schema;
  const table = error.table ? findTable(schema, errSchema, error.table) : null;
  if (table) {
    tableIds.add(table.id);
    if (error.column) columns.add(`${table.id}.${error.column}`);
    const con = table.constraints.find((c) => c.name === error.constraint);
    for (const c of con?.columns ?? []) columns.add(`${table.id}.${c}`);
    const fk = schema.fks.find((f) => f.name === error.constraint && f.from.tableId === table.id);
    if (fk) tableIds.add(fk.to.tableId);
  }
  return { tableIds: [...tableIds], columns: [...columns] };
}
```

```ts
// src/features/tracer/dml/source.ts
import type { Node } from '@pgsql/types';
import type { DbError } from '@/features/db/types';
import { ident, type Prober, sqlOf } from '../probe';
import type { Relation, RowKey } from '../types';
import { type DmlNode, keyOf, type Target, tryRun } from './shared';

export function insertColumns(body: DmlNode, target: Target): string[] {
  return body.cols?.length ? body.cols.map((c) => c.ResTarget.name) : target.columns.map((c) => c.name);
}

// Исходные строки INSERT (VALUES или SELECT), вычисленные отдельно, до вставки
export async function sourceRelation(prober: Prober, body: DmlNode, target: Target): Promise<Relation | undefined> {
  if (!body.selectStmt) return undefined; // DEFAULT VALUES
  const run = await tryRun(prober, `SELECT * FROM (${sqlOf(body.selectStmt)}) AS __vs_src`);
  // ponytail: VALUES (DEFAULT) отдельно не вычисляется, попытку тогда не показываем
  if (!run.ok) return undefined;
  const names = insertColumns(body, target).slice(0, run.value.fields.length);
  return {
    columns: names.map((name) => ({ name, type: target.columns.find((c) => c.name === name)?.type ?? 'unknown' })),
    rows: run.value.rows.map((values, i) => ({ key: `src:${i}`, lineage: {}, values })),
  };
}

// Существующие строки цели, совпавшие с исходными строками по колонкам keyCols
export async function collidingKeys(prober: Prober, body: DmlNode, target: Target, keyCols: string[]): Promise<RowKey[]> {
  const cols = insertColumns(body, target);
  if (!body.selectStmt || keyCols.length === 0 || !keyCols.every((c) => cols.includes(c))) return [];
  const t = ident(target.alias);
  const sql = `SELECT ${t}.ctid::text FROM ${target.sql} AS ${t}
    WHERE (${keyCols.map((c) => `${t}.${ident(c)}`).join(', ')}) IN
      (SELECT ${keyCols.map(ident).join(', ')} FROM (${sqlOf(body.selectStmt as Node)}) AS __vs_s(${cols.map(ident).join(', ')}))`;
  const run = await tryRun(prober, sql);
  return run.ok ? run.value.rows.map(([ctid]) => keyOf(target.alias, ctid as string)) : [];
}

// Что показать при ошибке INSERT: попытку и (для 23505) строку, об которую она споткнулась
export async function insertErrorExtras(
  prober: Prober,
  body: DmlNode,
  target: Target,
  error: DbError,
): Promise<{ attempted?: Relation; conflictKeys?: RowKey[] }> {
  const attempted = await sourceRelation(prober, body, target);
  const out = attempted ? { attempted } : {};
  if (error.code !== '23505' || !error.constraint) return out;
  const con = target.table.constraints.find((c) => c.name === error.constraint);
  const keys = con ? await collidingKeys(prober, body, target, con.columns) : [];
  return keys.length ? { ...out, conflictKeys: keys } : out;
}
```

```ts
// src/features/tracer/dml/trace-dml.ts
import type { DbClient } from '@/features/db/types';
import type { ParsedStatement } from '@/features/sql/types';
import { captions } from '../captions';
import type { Prober } from '../probe';
import type { Special, TraceFn } from '../route';
import type { Row, RowKey, Stage, TraceOptions } from '../types';
import { type DmlNode, errorFocus, instrument, keyOf, resolveTarget, row, sameValue, snapshot, tryRun, userResult } from './shared';
import { insertColumns, insertErrorExtras } from './source';

type Op = 'insert' | 'update' | 'delete' | 'merge';
type DmlStage = Extract<Stage, { kind: 'dml' }>;
const OPS: Record<string, Op> = { InsertStmt: 'insert', UpdateStmt: 'update', DeleteStmt: 'delete', MergeStmt: 'merge' };
const BRANCH = { INSERT: 'not_matched_insert', UPDATE: 'matched_update', DELETE: 'matched_delete' } as const;

// INSERT / UPDATE / DELETE / MERGE: один настоящий прогон с RETURNING old/new (PG18).
// Стадии и пары «до/после» строятся из его строк и из снимков, снятых до него.
// null до прогона: не наш случай, оператор выполнит trace.ts. После прогона null вернуть нельзя
export async function traceDml(
  stmt: ParsedStatement,
  _db: DbClient,
  prober: Prober,
  opts: TraceOptions,
  _traceSelect: TraceFn,
): Promise<Special | null> {
  const nodeName = Object.keys(stmt.ast)[0];
  const op = OPS[nodeName];
  const body = (stmt.ast as unknown as Record<string, DmlNode>)[nodeName];
  // WITH разберёт Ф10
  if (body.withClause) return null;
  const target = resolveTarget(opts.schema, body.relation);
  if (!target) return null;

  const stages: Stage[] = [];
  const before = await snapshot(prober, target);
  const run = await tryRun(prober, instrument(stmt.ast, nodeName));
  if (!run.ok) {
    const extra = op === 'insert' ? await insertErrorExtras(prober, body, target, run.error) : {};
    stages.push({
      id: `${stages.length}:error`,
      kind: 'error',
      error: run.error,
      focus: errorFocus(run.error, target, opts.schema),
      caption: captions.error(run.error.code, run.error.message),
      output: { columns: [], rows: [] },
      ...extra,
    });
    return { mode: 'final-only', fallbackReason: 'Запрос завершился ошибкой', stages, result: null, error: run.error };
  }

  const n = target.columns.length;
  const prefix = 2 + 2 * n + (op === 'merge' ? 1 : 0);
  const byKey = new Map(before.rows.map((r) => [r.key, r]));
  const inserted: RowKey[] = [];
  const deleted: RowKey[] = [];
  const updated: DmlStage['updated'] = [];
  const mergeBranches: DmlStage['mergeBranches'] = {};
  const added: Row[] = [];
  for (const r of run.value.rows) {
    const oldCtid = r[0] as string | null;
    const newCtid = r[1] as string | null;
    const oldValues = r.slice(2, 2 + n);
    const newValues = r.slice(2 + n, 2 + 2 * n);
    let key: RowKey;
    if (oldCtid !== null && newCtid !== null) {
      // UPDATE переносит строку на новый ctid (Ф0): ключ по старому, чтобы совпасть со строкой на доске
      key = keyOf(target.alias, oldCtid);
      const changedColumns = target.columns.filter((_, i) => !sameValue(oldValues[i], newValues[i])).map((c) => c.name);
      updated.push({ key, before: oldValues, after: newValues, changedColumns });
      byKey.set(key, row(target.alias, oldCtid, newValues));
    } else if (newCtid !== null) {
      const fresh = row(target.alias, newCtid, newValues);
      key = fresh.key;
      inserted.push(key);
      added.push(fresh);
    } else {
      key = keyOf(target.alias, oldCtid as string);
      deleted.push(key);
      // удалённая строка остаётся в output: аниматору нужны её значения, ключ уже в deleted
    }
    if (op === 'merge') mergeBranches[key] = BRANCH[r[2 + 2 * n] as keyof typeof BRANCH];
  }

  const given = insertColumns(body, target);
  const defaulted = op === 'insert' ? target.columns.map((c) => c.name).filter((c) => !given.includes(c)) : [];
  const dml: DmlStage = {
    id: `${stages.length}:dml`,
    kind: 'dml',
    op,
    tableId: target.table.id,
    inserted,
    deleted,
    updated,
    conflicts: [],
    mergeBranches,
    cascades: [],
    caption: captions.dmlInsert(inserted.length, before.rows.length),
    output: { columns: target.columns, rows: [...byKey.values(), ...added] },
    sourceRange: { from: stmt.from, to: stmt.to },
    ...(defaulted.length ? { defaulted } : {}),
  };
  stages.push(dml);
  return { mode: 'full', stages, result: userResult(run.value, prefix), error: null };
}
```

Пояснения к коду:
- `defaulted` без `cols` (`insert into t values (...)`) считает только колонки, которых нет в списке: `insertColumns` отдаёт все колонки таблицы, поэтому `defaulted` пустой. Генерируемые колонки в список не попадают никогда и всегда идут в `defaulted`.
- `sourceRange` весь оператор: позиции `ParsedStatement` абсолютные в тексте редактора, как у `rangeOf`.
- `touched` трасса берёт из `finish` (`touchedOf(stmt.ast, opts.schema)`), changedColumns туда не дописываем: `useLiveTrace` всё равно ставит редакторский `touched` (задача 4).

```ts
// src/features/tracer/route.ts
import { type DbClient, DbException } from '@/features/db/types';
import type { ParsedStatement } from '@/features/sql/types';
import { traceDml } from './dml/trace-dml';
import { type Prober, ProbeOverflow, TraceFallback } from './probe';
import type { Trace, TraceOptions } from './types';

export type Special = Pick<Trace, 'mode' | 'stages' | 'result' | 'error' | 'fallbackReason'>;
export type TraceFn = (stmt: ParsedStatement, db: DbClient, opts: TraceOptions) => Promise<Trace>;

const DML = new Set(['InsertStmt']);

// Операторы Ф9 по имени узла AST (stmt.kind у TRUNCATE и CREATE INDEX не тот).
// null: не наш оператор, дальше Ф5. Строка: причина final-only, оператор ещё не выполнялся
export async function traceSpecial(
  stmt: ParsedStatement,
  db: DbClient,
  prober: Prober,
  opts: TraceOptions,
  traceSelect: TraceFn,
): Promise<Special | string | null> {
  const node = Object.keys(stmt.ast)[0];
  try {
    if (DML.has(node)) return await traceDml(stmt, db, prober, opts, traceSelect);
  } catch (e) {
    // Сюда доходят только исключения до прогона: после него трассировщики Ф9 сами отдают final-only
    if (e instanceof ProbeOverflow) return 'Пока не анимируется: таблица больше лимита строк';
    if (e instanceof TraceFallback) return e.message;
    if (e instanceof DbException && !e.db.code.startsWith('VS')) return `Проба не удалась: ${e.db.message}`;
    throw e;
  }
  return null;
}
```
