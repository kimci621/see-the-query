# Контракты между фазами

Общий документ для всех планов фаз. Здесь зафиксированы имена файлов, типы, сигнатуры и соглашения, на которые опираются разные фазы. Каждый план фазы обязан им следовать. Если фазе нужно отклониться, она сначала правит этот документ (отдельный коммит `docs(contracts): ...`) и пишет в трекер новый пункт.

Спека: `docs/superpowers/specs/2026-10-08-visual-sql-design.md`.

Установленные факты о PGlite 0.5.8 (проверены по типам пакета и запуском в Node 2026-10-08):
- `select version()` → `PostgreSQL 18.3 (PGlite 0.5.8) on wasm32-unknown-emscripten`.
- Датасет bookstore загружается в Node за ~0.7 с (холодный старт PGlite включён).
- `ctid` в LEFT JOIN: у строки без пары ctid правой стороны = NULL (проверено).
- Ошибка `select nme from book` → `code 42703`, `position '8'`.
- `new PGlite(opts)`, `opts.loadDataDir?: Blob | File`, `opts.extensions`.
- `pg.query<T>(sql, params?, { rowMode: 'array' })` → `{ rows, fields: {name, dataTypeID}[], affectedRows?, command?, rowCount? }`.
- `pg.exec(sql)` → `Results[]` (несколько операторов).
- `pg.dumpDataDir('gzip' | 'none' | 'auto')` → `Promise<File | Blob>`.
- Ошибка: класс `DatabaseError` с полями `code, message, detail, hint, position (строка, 1-based символ), schema, table, column, constraint`.
- Контрибы: `@electric-sql/pglite/contrib/<name>` (есть `pg_trgm`, `pgcrypto`, `uuid_ossp`, `hstore`, `ltree`, `citext` и др.).
- `SET statement_timeout` принимается, но запросы **не прерывает** (проверено: `pg_sleep(3)` и `count(*) from generate_series(1, 5e7)` при таймауте 500 мс отработали до конца). Защита только через terminate worker'а.
- `dumpDataDir('gzip')` для bookstore: ~4.6 МБ, 250 мс; `new PGlite({ loadDataDir })` + первый запрос ~140 мс (Node). На 100k строк: 8.9 МБ, dump 460 мс, load 270 мс.
- Поля ошибки: у `23502` есть `table` и `column`, у `23503`/`23505`/`23514` есть `constraint`, `table`, `detail`; `position` есть только у ошибок разбора и имён (строка).
- `TEMP TABLE` внутри `BEGIN ... ROLLBACK` исчезает после отката; ошибка под `SAVEPOINT` + `ROLLBACK TO` не ломает транзакцию; роли и `SET ROLE` работают (`42501` без прав).
- `PGliteWorker` из `@electric-sql/pglite/worker` рассчитан на шаринг между вкладками с выбором лидера. **Мы его не используем.** Свой worker с простым RPC (раздел 4) даёт полный контроль: terminate, dump, load.

Установленные факты о libpg-query 18:
- `await loadModule()` один раз, потом `parseSync(sql)` → `ParseResult { version, stmts: RawStmt[] }`.
- `RawStmt { stmt: Node, stmt_location?: number, stmt_len?: number }`. `stmt_location` отсутствует, если равен 0; `stmt_len` отсутствует у последнего оператора без `;` (тогда длина до конца текста). Узлы выражений имеют поле `location` (байты). **Позиции в байтах UTF-8, а не в символах JS** (проверено: `select 'Привет' as x, b.title` → `b.title` на байте 28, символе 22). Перевод через `byteToChar` (раздел 5). Кириллица в строковых литералах ломает наивные позиции.
- Ошибка парсинга: `SqlError` с `sqlDetails.cursorPosition` (байтовая позиция, 0-based).
- У `A_Expr` вида `AEXPR_IN` в PG18 есть `rexpr_list_start` / `rexpr_list_end` (байтовые позиции скобок списка). При сравнении деревьев отбрасывать вместе с `location`, `stmt_location`, `stmt_len`.
- **Загрузка WASM под Vite** (проверено в Ф0, `spikes/vite.config.ts`): в сборке emscripten запрашивает `/libpg-query.wasm` от корня сайта, Vite файл не выпускает; в dev без пребандла нет default-экспорта. Решение: в `vite.config.ts` плагин `libpgQueryWasm()` (`generateBundle` → `emitFile({ fileName: 'libpg-query.wasm' })`, `configureServer` → middleware на `/libpg-query.wasm` с `Content-Type: application/wasm`); `optimizeDeps.exclude` только `['@electric-sql/pglite']`. Добавляет Ф4 вместе с `initParser`.

Установленные факты о pgsql-deparser 18.3.10:
- `deparseSync(node)` печатает многострочный SQL в верхнем регистре ключевых слов.
- Круговой тест parse → deparse → parse на 50 запросах программы: 49/50. **`FETCH FIRST n ROWS WITH TIES` теряет `WITH TIES`** (становится `LIMIT n`). Трассировщик не собирает стадию limit с `limitOption = LIMIT_OPTION_WITH_TIES` через депарсер.

### types.ts

```ts
export interface QueryField { name: string; dataTypeID: number }
export interface QueryResult {
  fields: QueryField[];
  rows: unknown[][];          // всегда rowMode: 'array'
  command?: string;           // 'SELECT', 'INSERT', ...
  rowCount?: number;
}
export interface DbError {
  code: string;               // SQLSTATE или наш код VS001/VS002
  message: string;
  detail?: string;
  hint?: string;
  position?: number;          // 1-based позиция символа в исходном SQL
  schema?: string;
  table?: string;
  column?: string;
  constraint?: string;
}
export class DbException extends Error {
  constructor(public readonly db: DbError) { super(db.message); this.name = 'DbException'; }
}
export const SANDBOX_TIMEOUT = 'VS001';   // запрос превысил время
export const SANDBOX_CRASHED = 'VS002';   // worker упал

export interface DbClient {
  query(sql: string, params?: unknown[]): Promise<QueryResult>;   // один оператор
  exec(sql: string): Promise<QueryResult[]>;                       // несколько операторов
  dump(): Promise<Blob>;
  version(): Promise<string>;                                      // select version()
  close(): Promise<void>;
}
```

### sandbox.ts

```ts
export interface Sandbox {
  readonly status: 'booting' | 'ready' | 'restarting' | 'failed';
  readonly datasetId: DatasetId | null;
  client(): DbClient;                                   // текущий живой клиент
  loadLesson(datasetId: DatasetId, journal: readonly string[]): Promise<void>;
  // BEGIN; fn(client); ROLLBACK — всегда, даже при ошибке. statement_timeout в PGlite не работает: зависание ловит сторож клиента (VS001).
  preview<T>(fn: (db: DbClient) => Promise<T>): Promise<T>;
  apply(sql: string): Promise<QueryResult[]>;          // exec с автокоммитом, в журнал при успехе
  undo(): Promise<void>;                                // снапшот датасета + журнал без последнего
  reset(): Promise<void>;                               // снапшот датасета, журнал пуст
  journal(): readonly string[];
  subscribe(listener: (e: SandboxEvent) => void): () => void;
}
export type SandboxEvent =
  | { type: 'status'; status: Sandbox['status'] }
  | { type: 'restarted'; reason: 'timeout' | 'crash' }
  | { type: 'changed' };                               // после apply/undo/reset/loadLesson: пора обновить доску
export function createSandbox(factory: (dataDir?: Blob) => Promise<DbClient>): Sandbox;
```

Снапшоты датасетов кэшируются в памяти `Map<DatasetId, Blob>` внутри sandbox.

Типы из спеки 5.7, уточнённые:

```ts
// types.ts
export type Lineage = Record<string, string | null>;    // алиас → ctid ('(0,3)') или null
export type RowKey = string;                             // см. rowkey.ts
export interface Column { name: string; type: string; source?: { alias: string; column: string } }
export interface Row { key: RowKey; lineage: Lineage; values: unknown[] }
export interface Relation { columns: Column[]; rows: Row[] }
export interface SourceRange { from: number; to: number }  // символьные позиции в полном тексте редактора

export interface StageBase { id: string; sourceRange?: SourceRange; caption: string; output: Relation; volatile?: boolean; compressed?: boolean }
export type Stage = StageBase & (
  | { kind: 'scan'; alias: string; tableId: string }
  | { kind: 'join'; joinType: 'inner' | 'left' | 'right' | 'full' | 'cross'; leftAliases: string[]; rightAlias: string;
      pairs: Array<[RowKey | null, RowKey | null]>; onColumns: string[]; usingColumns: string[] }
  | { kind: 'filter'; clause: 'where' | 'having'; verdicts: Record<RowKey, true | false | null>; predicateColumns: string[] }
  | { kind: 'group'; keys: string[]; groups: Array<{ key: RowKey; members: RowKey[] }>; aggregates: string[] }
  | { kind: 'window'; partitions: Array<{ members: RowKey[] }>; computed: string[]; frame?: string }
  | { kind: 'project'; kept: string[]; removed: string[]; computed: string[]; renamed: Record<string, string> }
  | { kind: 'distinct'; on: string[] | null; stacks: Array<{ winner: RowKey; members: RowKey[] }> }
  | { kind: 'sort'; order: RowKey[]; sortKeys: string[] }
  | { kind: 'limit'; kept: RowKey[]; cut: RowKey[]; limit: number | null; offset: number }
  | { kind: 'setop'; op: 'union' | 'union all' | 'intersect' | 'intersect all' | 'except' | 'except all'; branches: [Trace, Trace] }
  | { kind: 'materialize'; name: string; inner: Trace }
  | { kind: 'recursion'; name: string; iterations: Relation[] }
  | { kind: 'subquery'; mode: 'scalar' | 'in' | 'exists' | 'correlated' | 'lateral'; samples: Array<{ outer: RowKey; inner: Trace }> }
  | { kind: 'dml'; op: 'insert' | 'update' | 'delete' | 'merge' | 'truncate'; tableId: string;
      inserted: RowKey[]; deleted: RowKey[];
      updated: Array<{ key: RowKey; before: unknown[]; after: unknown[]; changedColumns: string[] }>;
      conflicts: Array<{ key: RowKey; action: 'nothing' | 'update' }>;
      mergeBranches: Record<RowKey, 'matched_update' | 'matched_delete' | 'not_matched_insert' | 'skipped'>;
      cascades: Array<{ tableId: string; deleted: RowKey[]; updated: RowKey[] }> }
  | { kind: 'ddl'; diff: SchemaDiff }
  | { kind: 'error'; error: DbError; focus: { tableIds: string[]; columns: string[] } }
);

export interface SchemaDiff {
  addedTables: string[]; droppedTables: string[];
  addedColumns: Array<{ tableId: string; column: string }>; droppedColumns: Array<{ tableId: string; column: string }>;
  renamedColumns: Array<{ tableId: string; from: string; to: string }>;
  alteredColumns: Array<{ tableId: string; column: string; before: string; after: string }>;
  addedConstraints: Array<{ tableId: string; name: string; kind: 'p' | 'f' | 'u' | 'c' | 'n'; columns: string[] }>;
  droppedConstraints: Array<{ tableId: string; name: string }>;
  addedIndexes: Array<{ tableId: string; name: string }>; droppedIndexes: Array<{ tableId: string; name: string }>;
  addedSchemas: string[]; droppedSchemas: string[];
  renamedTables: Array<{ from: string; to: string }>;
  before: SchemaSnapshot; after: SchemaSnapshot;
}

export interface Trace {
  sql: string;
  statementType: StatementKind;
  mode: 'full' | 'final-only';
  fallbackReason?: string;                       // почему final-only (для пометки в UI)
  touched: { tableIds: string[]; columns: string[] };   // 'public.book', 'public.book.title'
  stages: Stage[];
  result: QueryResult | null;                    // эталон от прямого выполнения
  error: DbError | null;                          // ошибка прямого выполнения
  notices: string[];
  timingMs: number;
}

// trace.ts
export interface TraceOptions { signal?: AbortSignal; maxRows?: number /* 2000 */; schema: SchemaSnapshot }
// Вызывающий обязан обернуть вызов в sandbox.preview (транзакция уже открыта).
// Каждая проба выполняется под SAVEPOINT (savepoint.ts), ошибка пробы не рушит транзакцию.

// rowkey.ts
export function rowKeyOf(lineage: Lineage, aliasOrder: string[]): RowKey;   // 'b=(0,3)|a=(0,1)', null → '∅'
export function groupKey(index: number): RowKey;                            // 'g:0'

// verify.ts
export function sameResult(stageOutput: Relation, reference: QueryResult, orderKeys: number[] | null): boolean;

// whitelist.ts
```

### SQL в MDX

Примеры пишутся обычными fenced-блоками с мета-строкой:

````mdx
```sql run expect=rows:9
select b.title, a.name from book b join author a using (author_id);
```
````

Мета-ключи: `run` (кнопка «На доску»), `expect=rows:N`, `expectError=SQLSTATE`, `trace=final-only`, `apply` (пример меняет данные, кнопка «Применить» вместо превью), `noexec` (не выполнять в тестах контента: псевдокод, синтаксис). Rehype-плагин `rehypeCodeMeta` (в `features/lessons/mdx/rehype-code-meta.ts`) переносит мету в проп `data-meta`. Компонент `SqlBlock` разбирает её функцией `parseSqlMeta(meta: string): SqlMeta`.

```ts
export interface SqlMeta { run: boolean; apply: boolean; noexec: boolean; expectRows?: number; expectError?: string; trace?: 'full' | 'final-only' }
```

Остальные MDX-компоненты: `<TlDr>`, `<Callout kind="analogy|trap|tip|note">`, `<DontDoThis href>`, `<T id="public.book">book</T>`, `<C id="public.book.author_id">author_id</C>`, `<Scene>` + `<Step caption>` (внутри каждого `Step` один sql-блок), `<Cheatsheet>`.

Тест контента читает `.mdx` как текст, достаёт sql-блоки регулярным выражением, выполняет их последовательно на датасете урока (блоки с `apply` коммитятся, остальные в `BEGIN ... ROLLBACK`) и проверяет ожидания.

## 10. Оверлей (`src/features/overlay`)

Сцена = последовательность дискретных кадров. Аниматоры чистые и тестируются без DOM, рендер (motion + `layoutId`) анимирует переход между соседними кадрами.

```ts
// types.ts
export type RowState = 'normal' | 'kept' | 'dropped' | 'unknown' | 'null-filled' | 'new' | 'changed' | 'deleted' | 'cut' | 'matched';
export interface GhostColumn { name: string; type?: string; state: 'normal' | 'highlight' | 'removed' | 'computed' | 'key' | 'added' }
export interface GhostRow { key: RowKey; values: unknown[]; state: RowState; group?: number; badge?: string; cellNotes?: Record<number, string> }
export interface GhostTable { id: string; title: string; x: number; y: number; columns: GhostColumn[]; rows: GhostRow[]; dashed?: boolean; opacity?: number }
export type Decoration =
  | { kind: 'pair-line'; id: string; from: { table: string; row: RowKey; col: string }; to: { table: string; row: RowKey; col: string } }
  | { kind: 'scanner'; table: string; rowIndex: number }
  | { kind: 'scissors'; table: string; afterRow: number }
  | { kind: 'counter'; id: string; x: number; y: number; text: string }
  | { kind: 'bracket'; table: string; fromRow: number; toRow: number; color: number; label?: string }
  | { kind: 'arrow'; id: string; from: { x: number; y: number }; to: { x: number; y: number }; tone: 'info' | 'danger' };
export interface Frame { tables: GhostTable[]; decorations: Decoration[]; camera?: { x: number; y: number; width: number; height: number } }
export interface Phase { id: string; stageIndex: number; caption: string; durationMs: number; frame: Frame }
export interface AnimatorContext {
  nodeRect(tableId: string): { x: number; y: number; width: number; height: number } | null;  // координаты доски
  workArea: { x: number; y: number };   // левый верхний угол рабочей зоны сцены
  schema: SchemaSnapshot;
}
export type Animator<S extends Stage = Stage> = (prev: Frame, stage: S, stageIndex: number, ctx: AnimatorContext) => Phase[];

// playback.ts
export interface Playback { phases: Phase[]; stageStarts: number[] }   // stageStarts[i] = индекс первой фазы стадии i
export function buildPlayback(trace: Trace, ctx: AnimatorContext): Playback;
export const ANIMATORS: { [K in Stage['kind']]?: Animator<Extract<Stage, { kind: K }>> };
```

Длительности фаз при скорости 1x: 400-900 мс. Скорость делит длительность. `prefers-reduced-motion` → `transition: { duration: 0 }` у motion, фазы сменяются по таймеру с той же длительностью.

`OverlayLayer` рендерится внутри `<ReactFlow>` через `ViewportPortal` из `@xyflow/react`, поэтому координаты кадра = координаты доски, а pan/zoom применяются автоматически.
