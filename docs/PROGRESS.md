# Трекер работ Visual SQL

Источник истины по плану: [спека](./superpowers/specs/2026-10-08-visual-sql-design.md). Этот файл отвечает на вопрос «что сделано и что дальше».

## Правила (обязательны для любого агента)

Статусы:
- ⬜ не сделано
- 🔄 в работе
- ⚠️ затруднения / уточнения / сбой
- ✅ готово

1. **Взял пункт в работу** → поменял ⬜ на 🔄 и дописал дату: `🔄 (2026-10-09)`.
2. **Закончил** → ✅ ставится только после проверки: критерий «Готово, когда» фазы выполнен, `pnpm check` зелёный (с фазы 1), для уроков выполнен DoD урока (ниже). Дата: `✅ (2026-10-09)`.
3. **Застрял, нужен ответ пользователя, что-то сломалось, пункт отменён или переосмыслен** → ⚠️ + строка `Заметка:` сразу под пунктом. В заметке: что случилось, что пробовал, что нужно для разблокировки. Пункты не удаляются никогда.
4. Один агент держит в 🔄 не больше одного пункта одновременно.
5. Обновление трекера коммитится вместе с работой по пункту, в том же коммите.
6. Статус фазы в сводке выводится из пунктов: все ✅ → фаза ✅; есть ⚠️ → фаза ⚠️; есть 🔄 или часть ✅ → фаза 🔄.
7. Порядок: фазы основной части идут по номерам. Раздел «После основных этапов» не начинается, пока основная часть не ✅. Исключение только по прямому указанию пользователя.
8. Новые обнаруженные работы добавляются пунктом в нужную фазу (со следующим свободным номером), а не делаются молча.

**DoD урока** (для пунктов `L…`): MDX написан своими словами по `docs/content-style.md`; прочитаны референс-урок курса и страницы PG docs; у каждого `<Sql>` есть ожидание (`expect` или `expectError`); `pnpm test:content` зелёный; трасса `full` (или `trace="final-only"` с причиной в комментарии); сцена каждого примера просмотрена глазами на доске.
