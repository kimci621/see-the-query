# Как писать уроки see-the-query

Гайд для всех, кто пишет уроки: людей и агентов. Источник правил: спека, раздел 6.1. Если правило гайда спорит со спекой, права спека, а гайд надо поправить.

## Главное

- Один урок = одна идея. Читается за 5-12 минут: 700-1500 слов и 5-12 SQL-примеров.
- Каждый тезис показываем на доске. Тезис, который нельзя запустить, скорее всего не нужен.
- Тексты только свои. Курс «Диджитализируй!» читаем как образец тона и глубины, но не переносим оттуда ни фраз, ни аналогий, ни примеров. Продукт будет публичным.
- Факты сверяем с официальной документацией PostgreSQL (`https://www.postgresql.org/docs/current/...`). Если пишешь «так делает Postgres», найди это в доке и положи ссылку во frontmatter.

## Тон

- Обращение на «ты». Разговорно, как объясняешь коллеге за кофе.
- Короткие абзацы: 1-4 предложения. Короткие предложения.
- Без канцелярита: не «осуществляет выборку», а «достаёт строки». Не «является», а «это».
- Без длинных тире. Нужна пауза: точка, запятая или двоеточие.
- Без «просто», «очевидно», «легко». Новичку это не просто.
- Термин вводим один раз, жирным, с объяснением человеческими словами. Дальше называем его одинаково.
- Ключевые слова SQL в тексте пишем в верхнем регистре и в обратных кавычках (`WHERE`, `LEFT JOIN`). Исключение: цитата подписи плеера, она в «ёлочках», как на экране. В коде пишем в нижнем регистре: так их набирает пользователь.

## Структура урока

Порядок разделов фиксированный. Заголовки разделов второго уровня (`##`) пишем своими словами, кроме служебных: «Что есть в данных», «Чего нет в выдаче и почему», «Ловушки», «Проверь себя».

1. `<TlDr>`: одна-две строки, суть урока. Пишется в одну строку исходника.
2. **Что есть в данных.** Какие «особые» строки датасета участвуют в уроке и на что смотреть (`docs/datasets.md`). Например: «у «Простого Python» нет автора, у Бориса Пастернака нет книг».
3. **Основная часть.** Цикл повторяется: тезис → пример (`run`) → что видно на доске → число-якорь.
4. **Чего нет в выдаче и почему.** Список с ❌: строка, причина.
5. **Ловушки.** `<Callout kind="trap">`. Как делать в продакшене: `<Callout kind="tip">`.
6. **Don't Do This.** `<DontDoThis href="...">`, только если тема есть в PG wiki «Don't Do This».
7. **Проверь себя.** Два-три вопроса, ответ можно проверить запуском на доске.
8. `<Cheatsheet>`: шпаргалка урока.

Ссылки на документацию в конец урока руками не пишем: `LessonView` сам выводит список из `docs` во frontmatter.

## Frontmatter

```yaml
---
id: inner-join                 # уникальный slug, совпадает с именем файла после номера
title: INNER JOIN, ON и USING  # заголовок урока, он же h1
chapter: joins                 # id главы из content/chapters.ts
number: "6.2"                  # всегда в кавычках, иначе YAML превратит 6.10 в 6.1
order: 2                       # порядок внутри главы, совпадает с NN в имени файла
dataset: bookstore             # bookstore | empty | events | big_bookstore
board:
  tables: [public.author, public.book, public.book_category]   # таблицы на доске; без board видны все
  layout:                      # необязательно, без него раскладка dagre
    author: { x: 330, y: 0 }
    book: { x: 0, y: 280 }
initialQuery: |                # запрос в редакторе при первом открытии урока
  select * from book;
docs:                          # официальная документация, минимум одна ссылка
  - url: https://www.postgresql.org/docs/current/queries-table-expressions.html#QUERIES-JOIN
    title: Соединение таблиц (JOIN)   # подпись под уроком: по-русски, коротко, по заголовку страницы
course: ["11.38"]              # номера референс-уроков курса (только для авторов)
tags: [join, inner join]       # для поиска ⌘K
mvp: true
---
```

Имена в `board.tables` и `layout` можно писать без схемы: `book` значит `public.book`. В `<T id>` и `<C id>` схема обязательна.

Путь файла: `content/lessons/<NN>-<chapter-id>/<NN>-<id>.mdx`, где первое `NN` это номер главы, второе это `order` (оба с ведущим нулём). Пример: `content/lessons/06-joins/02-inner-join.mdx`. Нарушение пути ловит `pnpm test:content`.

## SQL-примеры

Пример пишется обычным fenced-блоком с языком `sql` и метой после языка:

````mdx
```sql run expect=rows:9
select b.title, a.name
from book b
join author a on a.author_id = b.author_id;
```
````

Мета:
- `run`: кнопка «▶ На доску». Ставь почти всегда.
- `expect=rows:N`: сколько строк вернёт последний оператор блока. Проверяет `pnpm test:content`.
- `expectError=SQLSTATE`: блок обязан упасть с этим кодом (`42703`, `42803`...). Для примеров ошибок.
- `trace=final-only`: визуализатор честно показывает только итог. Над блоком обязателен комментарий с причиной: `{/* final-only: подзапрос во FROM появится в Ф10 */}`.
- `apply`: пример меняет данные. Вместо «На доску» будет кнопка «Применить», в тестах блок коммитится. В уроках про чтение данных не используется.
- `noexec`: не выполнять (псевдокод, синтаксис в шпаргалке). Не сочетается с `run`, `apply` и ожиданиями (`expect`, `expectError`).

Правила:
- У каждого блока есть `expect`, `expectError` или `noexec`. Опечатка в мете роняет тест, и это хорошо.
- В `run`- и `apply`-блоке один оператор. Ключевые слова в нижнем регистре, `;` в конце.
- `begin`, `commit` и `rollback` в блоке без `apply` не пишем: превью их не выполняет.
- Блоки выполняются сверху вниз на одной базе. Превью-блоки не оставляют следов, `apply`-блоки оставляют.
- Сортируй результат (`order by`), если в тексте важен порядок строк. Без `order by` порядок не обещан, и такой пример годится только для ловушки про порядок.
- Внутри `<Scene>`, `<Callout>` и других компонентов блок пишется без отступа, с пустой строкой до и после.

## Компоненты

- `<TlDr>Суть урока одной строкой.</TlDr>`
- `<Callout kind="analogy">`: аналогия из жизни. Одна главная аналогия на урок, своя, бытовая, без натяжек. Аналогия объясняет механику, а не украшает текст.
- `<Callout kind="trap">`: ловушка, на которой спотыкаются. Внутри обязательно пример, который её показывает.
- `<Callout kind="tip">`: как делают в продакшене.
- `<Callout kind="note">`: важное отступление, без которого можно жить.
- `<DontDoThis href="https://wiki.postgresql.org/wiki/Don't_Do_This#...">`: пересказ своими словами, почему так не надо, и что делать вместо этого.
- `<T id="public.book">book</T>`: таблица в тексте. Наведение подсвечивает её на доске, клик приводит к ней камеру.
- `<C id="public.book.author_id">book.author_id</C>`: колонка в тексте. Наведение подсвечивает колонку и колонку, на которую она ссылается по внешнему ключу.
- `<Scene>` из нескольких `<Step caption="...">`: срежиссированная последовательность запросов. В каждом шаге ровно один sql-блок. Кнопки «Назад» и «Дальше» отправляют запрос шага на доску.
- `<Cheatsheet>`: шпаргалка. Внутри списки и блоки `noexec`.

Других компонентов в MDX нет. Новый компонент = правка контрактов и гайда.

## Приёмы

- **Числа-якоря.** «Вернулось 9 строк. Запомни это число». Следующий пример сравнивает с ним: «а теперь 11: две книги без автора вернулись».
- **Чего нет в выдаче и почему.** После примера, где строки пропали, перечисли их: «❌ Простой Python: у книги нет автора, пары не нашлось».
- **Что видно на доске.** После каждого `run`-примера одна-две фразы о том, что произойдёт на доске: «строки без пары краснеют и уходят».
- **Ошибка как урок.** Типичная ошибка новичка показывается блоком `expectError`. Рядом текст: что написал Postgres и как это читать.
- **Проверь себя.** Вопрос, ответ на который получается запуском: «Сколько строк вернёт этот запрос, если поменять `>` на `>=`? Проверь на доске».

## Чеклист перед коммитом (DoD урока)

- [ ] Прочитаны референс-урок курса и страницы PG docs из `docs`.
- [ ] Текст свой, по структуре выше, без длинных тире.
- [ ] У каждого sql-блока ожидание или `noexec`, у `final-only` есть причина в комментарии.
- [ ] `pnpm test:content -t "урок <id>"` зелёный.
- [ ] Каждый пример нажат «На доску» и просмотрен глазами: сцена совпадает с текстом.
- [ ] `pnpm check` зелёный.

## Что есть в данных

В <T id="public.book">book</T> 11 книг. У «Острова погибших кораблей» нет цены: в <C id="public.book.price">price</C> стоит NULL.

## Дорогие книги

```sql run expect=rows:3
select title, price from book where price > 1000;
```

Вернулось 3 строки. Запомни это число. На доске по строкам бежит сканер: зелёные остаются, красные уходят вниз.

<Callout kind="analogy">
Турникет в метро: каждая строка прикладывает карту, и турникет пускает только тех, у кого условие дало «да».
</Callout>

## Чего нет в выдаче и почему

- ❌ Тихий Дон: 890 не больше 1000.
- ❌ Остров погибших кораблей: цены нет, сравнение дало «не знаю», а «не знаю» не пропускается.

<Callout kind="trap">
Опечатка в имени колонки ломает весь запрос, а не одну строку:

```sql run expectError=42703
select titel from book;
```
</Callout>
