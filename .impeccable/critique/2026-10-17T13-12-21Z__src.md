## Design specificity verdict

**Authored for this product.** The table node is the signature: PK key and FK link glyphs, mono type row with NN/U/✓ flags, dashed NULL chip, row-count badge, fold to "+4 колонки", column tint for the columns the query reads. One accent `--touched` carries "трогает запрос" through the tint, the table ring, the keyboard focus ring and the `--sql-keyword` colour. The pill "Превью: база не меняется", the camera flying to the DML target, and the error card ("Колонки titel нет в book. Может, title? [Заменить на title]", "Postgres не нашёл таблицу books. Есть: author, book, …", the 428C9 and 23503 explanations in plain Russian) could not be lifted into another product. The token layer is real and re-tuned for dark (row states, SQL palette, 8 group colours, shiki on the same tokens).

**Interchangeable.** Everything around the board is stock shadcn neutral with Geist, a black primary button, default React Flow controls and the "React Flow" attribution, a plain-text wordmark, stock Sonner toast and Dialog. At thumbnail size it still reads as "shadcn app with a canvas".

**Missed opportunity.** The board is the stage but is the least legible region in the first lesson and after ⌘0. The row-state tokens that would give it character (`--new`, `--changed`, `--deleted`) exist and are unused on the base board: committed row 7 "Аноним" looks like every other row. And the board does not follow the query as you type it (P1-1), which is the product's core promise.

## Priority issues

**[P1-1] The board does not follow the query you type: the camera and the `--touched` ring stay on the previous table.**
- Evidence: select-basics, type `select name from author` (caret at end of text, the normal typing state): result shows 6 names, `name` is tinted on `author`, but `author` stays at y = -156 with only 2 rows visible and `book` keeps `data-focused=true` and the blue ring (`r2-select-author.png`, `run2.log`). Same with a trailing `;`. Moving the caret 4 characters left into `author` immediately moves the camera to `author` at zoom 1 and the ring follows (`run3.mjs`: `author@817,124 f=true`). So focus by cursor only fires when the caret is strictly inside the FROM clause; `clauseAt` evidently treats the end-of-statement position as outside FROM (`src/features/editor/EditorPane.tsx` effect on `activeClause`).
- Why it matters: "write SQL, see Postgres execute it" breaks at the first new table; worse, the accent that means "трогает запрос" points at a table the query does not touch. When the overlay arrives (Ф6) it will play on a table that may be off-frame.
- Fix: treat the caret at the end of the last FROM/INTO/USING identifier (and end of statement) as inside that clause; additionally refocus on trace completion when the traced table set differs from `focused` (same path as `focusDmlTarget`, for SELECT too). Add one e2e: type `select name from author` on select-basics, expect `author` `data-focused=true` and fully in frame.
