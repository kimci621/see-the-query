# see-the-query

Визуальный тьютор по PostgreSQL. Слева темы, по центру теория, справа miro-подобная доска с таблицами, которой управляет SQL. Пишешь запрос, и в реальном времени видишь, как Postgres его выполняет: таблицы съезжаются при JOIN, строки отваливаются на WHERE, колонки исчезают на SELECT. Настоящий PostgreSQL работает в браузере через PGlite, бэкенда нет.

## Документы (читать в этом порядке)

1. `docs/PROGRESS.md`: трекер всех работ со статусами. С него начинается любая сессия.
2. `docs/superpowers/specs/2026-10-08-visual-sql-design.md`: дизайн-спека, источник истины по продукту и архитектуре.
3. `docs/superpowers/plans/`: детальные планы фаз (пишутся перед каждой фазой).
4. `docs/spikes.md` (с Ф0): выводы спайков, зафиксированные версии.
5. `docs/content-style.md` (с Ф8): гайд по тексту уроков.
6. `docs/datasets.md` (с Ф2): датасеты и их особые строки.

## Как начать сессию

1. Открой `docs/PROGRESS.md`.
2. Есть пункт в 🔄 или ⚠️ → продолжай его (для ⚠️ сначала прочитай `Заметка:`; если нужен ответ пользователя, спроси).
3. Иначе бери первый ⬜ по порядку фаз.
4. Нет согласованного плана текущей фазы → сначала план (скилл writing-plans) в `docs/superpowers/plans/`, согласование с пользователем, потом код.

## Обязательные правила

### Трекер

- Статусы: ⬜ не сделано, 🔄 в работе, ⚠️ затруднения / уточнения / сбой, ✅ готово.
- Перед началом пункта: ⬜ → 🔄 с датой. После проверки: 🔄 → ✅ с датой. Проблема, вопрос, сбой, отмена: ⚠️ + строка `Заметка:` под пунктом.
- ✅ только после проверки: критерий «Готово, когда» выполнен, `pnpm check` зелёный, для уроков выполнен DoD урока, для задач DoD задачи.
- Пункты не удаляются. Новая работа = новый пункт в нужной фазе.
- Трекер коммитится в том же коммите, что и работа по пункту.
- Раздел «После основных этапов» (Ф12, Ф13, бэклог) не начинается, пока Ф0-Ф11 не ✅, если пользователь не сказал иначе.
- Полные правила в шапке `docs/PROGRESS.md`.

### Спека

- Спека важнее кода. Хочешь сделать иначе, чем в спеке → сначала предложи правку спеки пользователю, после согласования правь спеку, потом код.
- Каждый урок программы и каждая операция каталога анимаций (спека, раздел 4) должны совпадать со спекой.

### Продуктовые инварианты (нельзя нарушать)

1. **Честность анимации.** Финальная стадия трассы сверяется с прямым выполнением запроса. Не совпало или узел не в whitelist → режим `final-only`. Неверную анимацию не показываем никогда.
2. **Базовая доска не анимируется.** Все движения идут на оверлее. Базовая доска перерисовывается только после «Применить», одним обновлением состояния.
3. **Настоящий Postgres.** Результаты, ошибки и тексты ошибок берутся только от PGlite. Своё вычисление SQL не пишем.
4. **Превью не меняет базу.** Всё, что выполняется во время набора, идёт в `BEGIN ... ROLLBACK`.
5. **Логический порядок шагов**: FROM → JOIN → WHERE → GROUP BY → HAVING → окна → SELECT → DISTINCT → ORDER BY → LIMIT.

### Границы модулей

- `features/tracer` не импортирует React и UI. На вход SQL и клиент БД, на выход `Trace`. Тестируется в Node.
- `features/overlay` не ходит в БД, только проигрывает `Trace`.
- `features/board` не знает про запросы, только про `BoardModel`.
- Связь между ними только через сторы zustand (`useSceneStore`, `useBoardStore`).
- `components/ui` генерирует shadcn CLI. Правим только при реальной нужде.

### Контент

- Тексты уроков пишем своими словами. Курс «Диджитализируй!» (`~/Projects/digitaliziruy!/synopsis/topics/11._SQL_в_PostgreSQL/`, `.../12._PostgreSQL_на_практике/`) только читаем как референс стиля и глубины. Копировать оттуда тексты запрещено: продукт станет публичным.
- Факты сверяем с официальной документацией PostgreSQL (ссылки в спеке, раздел 6.5).
- Стиль: `docs/content-style.md`. На «ты», коротко, аналогии, числа-якоря, ловушки, шпаргалка в конце.
- У каждого `<Sql>` в уроке есть ожидание (`expect` или `expectError`). `pnpm test:content` обязан быть зелёным.
- Один урок за один заход. Не пиши главу целиком за раз.

### Код

- TypeScript strict, без `any` без причины.
- Комментарии в коде на русском, идентификаторы на английском.
- Тексты интерфейса на русском.
- Оверлей анимирует только `transform` и `opacity`.
- Новые зависимости вне стека спеки (раздел 5.1) только после согласования с пользователем.
- Изменение трассировщика = unit-тест на стадию + golden-сверка. Новый вид стадии без теста не мержится.
- Минимальный код под задачу, без спекулятивных абстракций.

### Коммиты

- Conventional Commits, описание на русском: `feat(tracer): стадия filter с вердиктами`.
- Один пункт трекера = один или несколько коммитов, обновление трекера в последнем из них.
- Коммит только с зелёным `pnpm check` (с Ф1).

## Стек

Vite, React 19, TypeScript, pnpm, Tailwind v4, shadcn/ui, PGlite (Web Worker), libpg-query + pgsql-deparser, React Flow (`@xyflow/react`), dagre, motion, CodeMirror 6, MDX + shiki, zustand, react-router, Vitest, Playwright, Biome. Точные версии фиксируются в Ф0 (`docs/spikes.md`).

## Команды

- `npm i -g pnpm@10`: один раз, если pnpm не установлен (в Node 25+ нет corepack).
- `pnpm install`: зависимости.
- `pnpm dev`: dev-сервер Vite (http://localhost:5173).
- `pnpm build`: typecheck + production-сборка в `dist/`.
- `pnpm check`: typecheck + Biome + unit-тесты (проекты vitest `node` и `dom`). Обязателен перед каждым коммитом.
- `pnpm test` / `pnpm test:watch`: только unit-тесты.
- `pnpm test:content`: тесты контента уроков (проект `content`).
- `pnpm e2e`: Playwright, сам поднимает dev-сервер на порту 5199. Первый раз: `pnpm exec playwright install chromium`.
- `pnpm format`: автоформат Biome.
- `pnpm dlx shadcn@latest add <component>`: добавить компонент shadcn в `src/components/ui`.
